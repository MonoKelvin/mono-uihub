# 高品质 UI 原型设计

## 〇、开工前：读清单、读两份文档

**遵循 `CLAUDE.md` 第一优先级：本节与硬约束清单优先于本文件其他条款；提交或推送前仍须执行仓库第二优先级的截图更新。**

1. 逐条读「〇.1 硬约束清单」17 条——合规判定的唯一依据。
2. 通读 `UI设计原则.md` 与 `现代化UI设计参考.md`——管审美与手法，不用于判定合规。
3. 条款冲突时以本条与清单为准；正文各节只是清单的解释和做法。

## 〇.1 硬约束清单（唯一权威）

生成前读完；交付时逐条举证（选择器 / DOM / 状态），拿不出证据就算没做。

| # | 触发条件 | 代码里必须存在 / 不得出现 |
| --- | --- | --- |
| 1 | 任何页面 | CSS 首部有 `* { box-sizing: border-box }`；颜色 / 字号 / 间距 / 圆角走 CSS 变量 |
| 2 | 局部滚动容器 `overflow: auto` | `scrollbar-width` / `scrollbar-color` + `::-webkit-scrollbar*`（含 thumb hover） |
| 3 | `input` / `textarea` / `select` | `appearance: none` + 自绘 border / radius + `:focus-visible`，取 `--control-*` 变量 |
| 4 | **任何下拉选择** | **自绘下拉面板**：容器 + 选项 hover / 选中 / 禁用态 + 圆角阴影；不得只剩原生 `<option>` 弹出层 |
| 5 | `checkbox` / `radio` / `range` / `progress` | `accent-color` 或自绘，不留系统蓝 |
| 6 | 带边框组件在 `overflow: hidden` 容器内 | 父级 padding ≥ 最大边框宽 + 1px，或改用 `inset` 阴影；hover 边框用 `border: 1px solid transparent` 占位 |
| 7 | 软件 / App / 组件 | `.stage > .canvas`；canvas 有 `contain: paint` + `overflow: hidden` + `isolation: isolate`；浮层 `absolute`；画布内无 `fixed`、无 `vw/vh` |
| 8 | 对话框 | 内容多时横向（16:9 / 4:3），画布内居中、四边 ≥ 24px；遮罩与模糊只作用于画布内 `.scrim` |
| 9 | 任何界面文案 | 无「演示 / 原型 / 模拟 / 示例 / Mock / 占位 / Lorem」；无教学标注、序号箭头、说明气泡 |
| 10 | 每个可见控件 | 有真实事件响应，无死按钮；列表 / 表单 / 异步操作备齐空 / 加载 / 失败 / 成功 / 禁用态；**有参考图时按识别出的产品逻辑补全未展示的模块 / 页面，并做成真实视图而非一堆弹窗**（见 0 节） |
| 11 | 有参考图（`imageToUI`） | `metadata.json` 有合规 `imageToUI`；**网页**宽度撑满，首屏优先随窗口宽高自适应，让内容完整展示、不遮挡、不越界；若完整适配会造成拥挤或内部遮挡，才按内容自然增高并滚动，不锁 `aspect-ratio`；**软件 / App / 组件**按 W:H 等比、内部统一 `cqw`（不混 `cqh`、不给 `clamp()` 设 px 上限）、一屏不滚；背景只还原样式并铺满容器；不用 `transform: scale()` 整体缩放；网页视口适配按第 17 条（`clamp()` 只用于网页，不与上述画布规则冲突） |
| 12 | 字体 | 非默认系统字体（长正文 / 密集数据除外），CDN 引入 + 回退栈；默认字号 ≥ 12px（例外见 4.4） |
| 13 | 图标 | 全站一套（Tabler 或内联 SVG sprite），无 emoji 当功能图标，线宽统一 |
| 14 | 第三方库 | 只走 CDN；无 React / Vue / Tailwind / Next，无本地构建 |
| 15 | `assets/` | 默认平铺；某分类 ≥ 5 张才建子目录，否则加 `icon-*` 等前缀；文件名英文 kebab-case |
| 16 | 动画 | `start()` 幂等；可逆状态复用同一 Timeline 的 `reverse()` / `play()`；连续目标用 `quickTo()`；有 `prefers-reduced-motion` 分支 |
| 17 | 交付 | `ui/<page-name>/`（英文 kebab-case ≤ 4 词）内有 `metadata.json`；**以 1366×768 为标准参考值**（可按内容密度小范围浮动）验证布局不挤不撞：文字无重叠遮挡（有意设计的重叠 / 错位除外）、无无效换行溢出、容器不过小导致内部紧贴、组件之间不紧贴不重叠；**按标准响应式伸缩**：布局随视口按比例变、正文字号 / 图标基本固定、只有大标题 / 背景 / 段落用 `clamp()` 缓缩放；**禁止全站线性等比放大**（`html{font-size:calc(100vw/N)}` / `transform:scale()`）；窄视口按需重排、不横滚（网页 / 软件建议，App / 组件不强求） |

写 CSS 时按第 2–5 条一次性把控件样式建完，别等收尾补。

## 〇.2 UI 去 AI 味：必须使用 `nutlope/hallmark` （从图片还原UI的情况可以不考虑）

生成、改版或视觉精修 UI 时，必须检查当前环境是否已安装 `nutlope/hallmark` 提供的技能。

- **已安装**：设计前按当前可用技能列表中的实际名称调用，结合产品定位推导视觉方向；实现后再按其要求审查并修正模板化的构图、排版、配色、组件和文案，然后执行第九节最终自检。不得只提及技能名而不实际调用或应用。
- **未安装**：明确告知用户并推荐执行以下命令，由用户决定是否安装，不得擅自安装。安装后确认技能已在当前环境可用，再按实际技能名调用；用户选择不安装时，继续执行仓库原有设计与自检要求，并在交付说明中如实注明未使用 Hallmark，不得声称已完成该技能检查。

```bash
npx skills add nutlope/hallmark -g
```

Hallmark 是审美补充，不替代「〇.1 硬约束清单」17 条与两份文档的必读、回归检查。其建议与仓库最高优先级规则、硬约束或用户当次明确要求冲突时，遵循后者；去 AI 味不得牺牲必要功能、可访问性或原生 HTML / CSS / JS 技术栈。

## 一、目标：以设计师作品为审美标杆，不套 AI 模板

交付要像成熟设计师的真实作品：信息经过取舍、主次明确、构图有辨识度、细节属于同一套语言。简约高级是完成度要求，不是把所有产品做成浅灰底、小字、圆角卡片；大胆的品牌色、海报排版和高密度工作台也必须有秩序。

- 审美与可用性并重，不为截图好看隐藏必要信息或缩小操作文字。
- 风格由产品决定，但不能用「功能完整」为冗余内容、入口堆叠和装饰填空辩护。
- 主动定方向，不等用户给颜色、字体、布局、动效参数；选择要落到具体视觉关系。
- 拒绝默认的 SaaS 首屏、统计卡片墙、统一 Bento 和逐区块营销模板；这些结构只在真实任务需要时使用。
- 画面普通时先改内容取舍、构图和素材，不继续添加渐变、阴影、徽标和动画。

### 独立推导，借鉴设计关系，不复制旧页

- 完整阅读两份文档后，先从 [图文参考索引](references/INDEX.md) 按当前容器、任务与设计手法找相关案例，再用当前内容独立推导。借鉴的是关系与取舍，不是固定色板、字体或整页模板；用户当次提供的具体要求与参考优先，不要求逐一打开所有已有项目。
- 检索时用具体问题，例如「网页 + 商品展陈」「软件 + 深色编辑器」「App + 价格层级」「组件 + 拟物开关」，不要只搜「高级、简约」。先读匹配的 1–3 篇说明，再实际查看其中相关 WebP；长图按需要放大局部，不只看缩略图。没有匹配项时再研究外部参考，不硬套库里的页面。
- 每篇说明把字体、排版、布局、色彩职责、组件形态与设计理念落实到可见安排。方向说明写清「借哪种关系、为什么适合、哪些不沿用」；可以查阅原型源码核实字体与数值，但不复制代码作为新页起点。
- 允许按需阅读本文件要求的文档、相关设计与工具说明，用于研究或核对；只读与当前任务有关的内容，不遍历整个原型库。图文案例是两份必读文档的补充，不替代必读与回归。
- `现代化UI设计参考.md` 第五节保留可直接执行的文字示例，`references/` 提供对应的图片与精炼拆解。索引负责找到案例，说明负责讲清关系，图片负责核对画面；不能只列项目名、链接或形容词。
- 研究图片与动态参考时，区分产品界面、展示包装与讲解标注；静态画面、关键帧和实际运行是不同证据。不要从截图编造未见的交互与精确动效参数，不把视频的镜头运动、循环复位或多屏拼贴当成默认产品行为。
- 不复制参考原型的 HTML / CSS / JS 当起点，不整套搬用品牌色、字体、业务模块和布局；借鉴的是设计理由与关系，当前页面仍现场推导。
- 不机械复用上一轮的配色、骨架、组件组合或动效；差异不能只靠换色、换文案、换图。修改已有页面则保留其有效视觉语言，不为了求新强行换风格。
- 〇节的硬约束与两份文档必读、交付回归义务不变。

## 二、先判断产品，再定风格

看定位、用户、场景、内容、品牌气质，再定视觉方向。下表是思路，不是模板。

| 产品气质 | 可探索的表达 |
| --- | --- |
| 国际化 / 英文品牌 | 大尺度排版、字距与留白、摄影、符号 |
| 潮流 / 创意 / 年轻化 | 大胆构图、强字体个性、几何图形、视觉化数字 |
| 专业工具 / 桌面软件 | 清晰的信息组织、舒适密度、细腻的状态反馈、克制用色 |
| 科技 / AI / 数据产品 | 数据可视化、结构图形、动态反馈、有辨识度的科技视觉 |
| 文化 / 艺术 / 内容品牌 | 编辑式排版、衬线或特色字体、材质感、有情绪的色彩 |
| 高端消费 / 生活方式 | 精致字体、产品影像、材质光影、克制而鲜明的品牌表达 |

可以混搭，也可以原创，不套风格名词。

### 交付容器：四类

| 类型 | 判断依据 | 外框与滚动 | 画布边界 |
| --- | --- | --- | --- |
| A 软件 | 后台、工具、仪表盘 | 完整窗口；长列表局部滚动 | 窗口内锁死 |
| B 网页 | 品牌、落地、内容站、作品集 | 自然文档流；整页滚动 | 视口即画布 |
| C App | 移动优先、点名 App / 手机 / 小程序 | 手机比例外框；框内滚动 | 手机框内锁死 |
| D 组件 | 播放器、灯箱、上传框等单一控件 | 按内容自然尺寸；内部局部滚动 | 组件框内锁死 |

用户点明按用户要求，没点明按功能推断。容器只决定展示方式，不限制风格。

**还原参考图时另按 0 节**：网页随内容自然增长、可滚动；软件 / App / 组件一屏装下、不出现滚动。

### 四类容器各自怎么做

**A 软件**
- 窗口、背景、内容要成完整展示关系，别为悬浮效果加多余装饰。
- 主要信息和常用操作自然共存；复杂内容靠分区和局部滚动承载。
- 先分配空间和布局，再定滚动区；不靠裁切、隐藏滚动条、整体缩放掩盖布局问题。
- 窄屏重排、分组、调整信息呈现，核心功能不能消失。
- 展示窗口的宽高按内容密度、目标视口与展示条件决定；四周留出合适空间，不用固定视口百分比限制所有软件。

**B 网页**
- 按内容选长页叙事、模块化浏览、沉浸首屏等结构。
- 要有视觉节奏和层次，别每个区块都同一套布局。
- 需要叙事才加滚动驱动动画，不为凑规则硬加。

**C App**
- 导航与控件符合移动端习惯；单列、横向浏览或成组双列按任务与触控空间选择，不把单列卡片流当唯一骨架。
- 原生控件做必要定制，但不牺牲可访问性和操作体验。
- 触控区、底部导航、内容滚动按真实移动端尺寸；还原任务仍执行 0 节的一屏与比例规则。
- 手机画布比例按用户指定的设备或参考图决定；没有指定时选适合内容的常见移动屏幕比例，不绑定某一品牌机型。

**D 组件**
- 按用途自然成形，不套完整软件外壳。
- 把空闲、悬停、聚焦、加载、完成、出错等状态设计全，变化要连贯可懂。

### 容器边界：界面必须锁在画布里（软件 / App / 组件）

硬约束。网页的边界是浏览器视口，软件 / App / 组件有自己的边界。对话框、抽屉、遮罩、模糊一旦跑到画布外，界面就从「一个软件」退化成「一张网页截图」——这是这类原型最常见的破绽。

```
body > .stage          舞台：居中 + 背景，不承载产品内容
       └ .canvas      画布：产品的界面边界
          ├ 产品内容（标题栏 / 主区 / 侧栏…）
          └ .layer     浮层组：对话框、抽屉、下拉、Toast
              ├ .scrim  遮罩：变暗 + 模糊
              └ .dialog 对话框本体
```

```css
.canvas {
  position: relative;    /* 浮层定位基准 */
  contain: paint;        /* 裁剪 + 让 fixed 锚定到画布，不可省 */
  overflow: hidden;
  isolation: isolate;    /* 层叠与背景采样隔离在画布内 */
  container-type: size;  /* 可选：内部要用 cqw/cqh 时才加，且必须给显式宽高 */
  width: min(1440px, 100%);
  height: min(900px, calc(100svh - 2 * var(--stage-pad)));
}

.layer  { position: absolute; inset: 0; }        /* 参照画布，绝不用 fixed */
.scrim  { position: absolute; inset: 0;          /* 尺寸即画布，模糊范围严格等于画布 */
          background: rgb(8 10 14 / .45); backdrop-filter: blur(10px); }
.dialog { position: relative; width: min(720px, 78cqw); max-height: 82cqh;
          display: flex; flex-direction: column; }
.dialog-body { flex: 1; min-height: 0; overflow: auto; }  /* 只让内容区滚动 */
```

**`contain: paint` 不能省。** 实测只有 `overflow: hidden` 时，画布内的 `fixed` 仍相对浏览器视口定位并逃逸；加上 `contain: paint`（或 `transform` / `filter` / `will-change` / `contain: layout`）才会锚定到画布并被裁剪。`container-type: size` 单独不生效，必须与 `contain: paint` 并存。

**禁止**
- 画布内用 `position: fixed` 定位浮层——参照系是视口，天生越界。
- 用 `vw` / `vh` / `dvh` 给画布内元素定尺寸。
- 把遮罩、模糊、阴影施加在 `body`、`.stage` 或画布之外。
- 用 `transform: scale()` 整体缩放画布塞进屏幕——文字、模糊、阴影会一起糊。
- 让舞台出现产品语义内容（说明文字、按钮、装饰都不行）。

### 对话框尺寸（软件强制）

**先用对地方**：对话框只装短暂、原子的操作（确认、快速选择、轻量表单）。有实质内容的模块做成真实视图，别用对话框堆功能（见 0 节）；用了才按下面的比例规范。

**默认横向：宽 > 高。** 下表只在「确需弹层」时适用；编辑器、看板、设置这类有实质内容的模块先做成独立视图，别按表格塞进对话框。

| 内容量 | 比例 | 建议尺寸（相对画布） |
| --- | --- | --- |
| 多（表格、图表、长表单、编辑器） | 宽 > 高，16:9 或 4:3 | 宽 60%–80%，高 ≤ 75% |
| 中（设置面板、多字段表单） | 宽 > 高 | 宽 480–640px，高 320–420px |
| 少（确认、单字段、提示） | 可接近方形 | 宽 320–420px，高 220–320px |
| 纵向列表（长列表、树、选择器） | 高 > 宽（唯一例外） | 宽 320–400px，高 60%–80% |
| 工作区（日程、看板、全屏编辑） | 接近画布全尺寸 | 画布内留 16–24px 边距 |

判定顺序：先问内容是否需要并排。表格、图表、代码、时间轴这类横向更易读的用横向；单一列表、树、分步表单可以纵向。

```css
.dialog--wide   { width: min(72cqw, 860px); aspect-ratio: 16 / 9; max-height: 78cqh; }  /* 内容多 */
.dialog--panel  { width: min(56cqw, 680px); aspect-ratio: 4 / 3;  max-height: 78cqh; }  /* 内容多·紧凑 */
.dialog--compact{ width: min(32cqw, 380px); aspect-ratio: 5 / 4; }                        /* 内容少 */
.dialog--tall   { width: min(30cqw, 360px); height: min(72cqh, 620px); }                   /* 单一纵向列表 */
```

内容超高时 `max-height` 生效、比例被打破是有意的：宁可比例略变，也不让内容溢出画布。

- 画布内居中，四周留白 ≥ 24px，不贴边、不跨出。
- 只让 `.dialog-body` 滚动，头尾固定。
- 遮罩 `rgb(0 0 0 / .35)` ~ `rgb(0 0 0 / .5)`，模糊 8–16px。
- 同一软件内同类对话框用同一尺寸，别一个 16:9 一个窄高条。

## 三、设计流程：先定任务，再定方向，最后建系统

动手前先读 `skills/ui-metadata/SKILL.md`，按规范写 `metadata.json`。

### 0. 图片还原：以图定调，补全整个产品（图片作为还原输入时执行）

**先区分用途**：任务要求以图片还原界面时，执行本节以及对应硬约束；仅研究标杆、借鉴风格关系后独立设计，不自动触发本节的还原比例策略与 `imageToUI` 归档。用户同时给图与文字要求时，按用户明确的用途判断，不把「参考某种风格」改成逐像素复刻。

**还原的是整个产品，不是参考图那一屏。** 参考图只给出产品定位、功能域和视觉语言的样本；要据此推理出未展示的必要模块、页面与功能，交付一个完整、能走通的产品。完整范围由该产品的任务与入口线索决定，不扩展成行业功能全集。只复刻图里那屏等于没交付。

**先识别，再推理**

- **识别**：产品是什么、服务谁、有哪些功能域、导航与信息层级，以及视觉语言——配色、字体、字阶、间距、圆角、边框、图标、图形语气、文案语气、组件形态与状态表现。
- **推理**：按品类常识和图中已有的导航 / 入口线索，补齐同类产品必然需要的视图——列表与详情、筛选搜索、创建与编辑、设置、账户、数据页、空 / 加载 / 失败态。图里是仪表盘首页就补明细与配置视图，是商品页就补分类、搜索、订单。
- **边界**：只补与识别出的产品逻辑一致的模块，别凭空加无关功能凑数（见第七节），也别为了补全把首屏塞满。**用户要求单组件时，只补该组件自身必要的交互与状态，不按完整应用扩展消息、账户、设置等业务视图。**
- **同源**：补出来的页面沿用同一套视觉语言、组件规范和文案语气，读起来是同一个产品，不是几张风格不同的拼贴。

**做成真实界面，不靠弹层凑功能**

- 补全的模块落在真实的页面 / 视图 / 工作区里：导航切换、分区、侧栏、列表→详情、内联编辑、面板切换。原型应该有可浏览的多个界面，而不是一屏加一堆弹窗。
- 弹层只用于短暂、原子、不需要独立空间的操作（确认、快速选择、轻量表单）。凡是能做成主界面一部分的，就做成主界面。
- 别为了显得「功能全」堆参考图里没有的对话框；对话框密度高是还原偷懒的典型信号。

**来源声明（`imageToUI`）**：用图当输入（看图做 UI、以图还原、一比一复刻）时必须写 `imageToUI`，让画廊能回溯原图。

- 输入是图片 URL：原样写入，如 `"imageToUI": "https://dribbble.com/..."`。
- 输入是 base64 或本地路径：**先问用户二选一**——给源链接，或允许把图复制到 `ui/<slug>/assets/` 存档（推荐，可离线可追溯），再把 `imageToUI` 写成 `"./assets/source-<slug>.png"`。
- ⚠️ 禁止把 base64 或本地绝对路径写进该字段，浏览器打不开。
- 以 `http://` / `https://` / `//` 开头视为外链；`./assets/...` 视为目录内资源；留空则不显示图标。

**素材取用**：默认不抠原图。用 `resource-getter` 或文生图找相似的，与原图并排比对，主体、构图、色调、气质接近就用；差太多就换图或改提示词。用户明确要求「必须和原图一样」时才从原图抠（主体用 `matte.py`，整块照片按区域裁切）。

```bash
python tools/image-forge/matte.py "ui/<slug>/assets/source-<slug>.png" "ui/<slug>/assets/<name>.png"
```

背景复杂加 `--model isnet-general-use`（首次下载 ~170MB）。只写了外链时，先把图另存到 `assets/`。

**适配：按容器定尺寸，别把比例焊死**

先保结构与样式（层级、间距关系、对齐、配色、字体气质），尺寸按容器类型适配，不机械照搬参考图像素。

| 容器 | 尺寸策略 |
| --- | --- |
| 网页 | 宽度撑满视口，高度随内容；内容完整呈现；**不锁 `aspect-ratio`**；视口适配按第八节 |
| 软件 / App / 组件 | 按参考图 W:H 成比例，整体等比缩放到合适尺寸，画布内留外边距；内容锁在一屏，**不出现滚动** |

**网页**
- 宽度 `100%`（要版心就加 `max-width` + 居中），高度自然增长，不锁 `aspect-ratio`。
- **通过 UI 图片还原网页时，首屏尽量自适应当前窗口的宽度和高度，优先让文字、主图与控件完整展示，不遮挡、不超出各自区域。** 主图优先 `object-fit: contain`，布局同时考虑可用宽高；不要照搬参考图的越界裁切，也不要只按宽度适配后忽略短窗口。
- **例外只在完整适配会造成拥挤或内部遮挡时成立**：先重排、收紧留白或调整主图尺寸；仍不合适就让首屏随内容自然增高、保留纵向滚动，不强塞一屏，不靠裁切、隐藏必要内容或缩小正文与控件规避问题。
- 用标准响应式手段：布局用 `%` / grid / flex / `minmax()`，正文字号固定档，只有大标题 / 背景 / 段落用 `clamp()` 缓缩放。**不要用 `cqw` 把比例锁死，也不要让全站尺寸随视口线性等比放大。**
- 首屏和每个区块都要内容完整：文字不截断、图片不压扁、块与块不重叠、无意外缝隙或多余空档。
- 参考图的纵向节奏（区块高度关系、留白比例）可保留，但以内容自然高度为准。
- **视口适配按第八节**：1366×768 是参考值不是硬基准，断点按内容定；还原网页额外验证至少一个短窗口，检查首屏是否完整或合理转为自然滚动。

**软件 / App / 组件**
- 画布 `aspect-ratio` ≈ 参考图 W:H，用 `min()` 定宽高，外边距交给舞台留白。
- 内部尺寸统一 `cqw`（不混 `cqh`、不给 `clamp()` 设 px 上限），字号、间距、圆角、图标随画布同系数变化。
- 内容必须装进一屏：装不下就先整体缩小画布，再压留白或减装饰，**别用滚动条解决**。
- 等比缩小后个别字号 / 图标显得过细过小、与整体失衡，可在不改构图的前提下**同类成组适度放大**（同级给同一新值，幅度宁小勿大）；位置、对齐、留白节奏、主次层级不能变。禁止借这条重排版式或放大标题找平衡。
- 多图比例不一致以主图（信息最全或作首屏那张）为准，一页内不混多种宽高比。
- 缩小后正文仍要可读、触控区仍要好点，这条优先于「和原图一模一样」。

**背景只还原样式，不还原尺寸**
- 纯色、渐变、纹理、噪点一律用 CSS 画，铺满所在容器：网页铺满视口，软件 / App / 组件铺满画布。
- 不按参考图里背景块的像素尺寸设宽高，也别为背景单独切一张固定尺寸的图去对位置。
- 网页背景会被内容自然覆盖的，可以直接省略；其余容器的背景铺满即可，不必还原原图里的边界。

```css
/* 网页：撑满 + 响应式，不锁比例 */
.page { width: 100%; min-height: 100svh; }
.hero { display: grid; grid-template-columns: minmax(0, 1fr) minmax(0, 1.2fr);
        gap: clamp(24px, 4vw, 64px); }
@media (max-width: 900px) { .hero { grid-template-columns: 1fr; } }

/* 软件 / App / 组件：成比例 + cqw，一屏不滚 */
.canvas { aspect-ratio: 1600 / 1200; container-type: inline-size;
          width: min(96vw, calc(94svh * 1600 / 1200)); }
.title  { font-size: 5cqw; }
.card   { padding: 2cqw; border-radius: 1.2cqw; }
```

画布的 `vw` / `svh` 只给画布本身定尺寸，画布内元素仍禁视口单位。还原软件 / App / 组件时还要叠加「容器边界」的 `contain: paint`、`overflow: hidden`。

### 1. 明确任务

定产品定位、用户场景、核心任务、信息优先级、首屏重点。先备真实文案和合理数据，再设计呈现，不用空洞占位。

### 2. 定视觉方向

用简短的设计说明讲清本页气质：用户先看什么、先做什么；参考作品在哪些关系上成立；本页借鉴哪些取舍、不沿用哪些做法；字体、色彩、图形、构图如何形成同一种性格；低频内容放在哪里；动效是否有必要。不能只写「简约、高级、科技感」，也不能把标杆的配色或版式变成必须照抄的参数。

先明确本页不需要的东西，再组织主体。功能完整靠真实视图和清晰流程实现，不靠首屏堆满模块；参考里没有的统计卡、徽标、说明段和宣传区，不为显得丰富自行补上。视觉方向见 `现代化UI设计参考.md` 第二节，容器与组件关系见第三节，组合错误及纠正见第四节，自包含案例与精修顺序见第五节；研究、实施与验证边界见第六节。

### 3. 建设计系统

建 CSS 变量和可复用样式：颜色、字体、字号、间距、圆角、边框、阴影、动效。要有统一逻辑，但不强制固定数值。**别把设计系统做成限制创意的参数表**，每个选择都服务整体效果。

**这一步就要把适配做对**（第八节）：按 1366×768 这个参考值定尺寸、间距、栅格（内容少的页面可自己取更小的合理值），保证文字不重叠、换行不溢出、容器不小到让内容贴边、组件之间不紧贴；布局按流式响应组织、正文字号固定档、少数大元素用 `clamp()`，别做全站等比放大。别等页面写完再补——那时只能靠改断点补救，布局已经挤坏了。

## 四、视觉要点

### 4.1 层级靠字号和留白，不靠卡片和边框

- 让人一眼知道先看哪里，再自然看到其余信息。
- 用字号、字重、字体性格、色彩、位置、留白、对齐建层级，不靠堆卡片和边框。
- 构图可探索网格、非对称、错位、分栏、叠排、沉浸式、编辑式。
- 允许大胆对比、特殊断行、视觉张力，但整体要协调易读。
- 页面要有疏密、轻重、节奏，别所有区域平均用力。
- 不默认居中、对称、等宽卡片、相同区块排列。
- 设计要帮用户完成任务，不是只求截图好看。

### 4.2 功能不为视觉让路

**简约不是删核心能力，也不是把全部能力同时展示。** 必要功能按当前产品的真实任务给全，低频功能进入真实次级视图或上下文操作；不要把整个品类的功能全集当成这页的需求，更不能为「完整」添加无关模块、重复入口和解释段。怎么做见第七节。

### 4.3 写真实文案，不写说明和标注

- 界面不是说明书。能短就别长，但别为省字丢信息。
- **不得出现任何「演示 / 原型 / 模拟」相关文字或图形**：不写「演示模式」「示例数据」「Mock 数据」「测试账号」「这是原型」；不画气泡标注、箭头提示、序号标记、教学高亮框；不用「示意图」「占位图」「Lorem ipsum」「待补充」。每个字、每个图标都必须是产品真实会有的。
- 当成正式上线产品来设计：文案像真实业务数据，图表数值关系可信，空状态写产品自己的引导语，错误提示写真实场景。实现不了的（服务端接口）在交付说明里讲。
- 英文 / 国际化页面可用精简词语、短标签、大字号、视觉化符号。
- 潮流创意页面可多用图标、符号、图形、视觉化数字；专业工具优先清晰。
- 中文要自然准确，不为装饰硬塞英文或无意义缩写。
- 文案要具体有信息量，避免营销空话、重复标题、自述式引导。
- 状态、趋势、流程、分类、比例按理解成本选图标、图表、结构图或文字。

### 4.4 主动选字体，别用默认

**别把系统默认字体当最终方案。** 除长正文、密集信息、阅读优先场景，都要主动挑。

- 要高级感 / 设计感 / 品牌感时，主动找展示字体或组合，别用默认字体交差。
- 标题、字标、关键数字、正文、辅助信息可用不同性格，但要协调，别堆太多。
- 英文：几何无衬线、人文无衬线、Grotesk、衬线、窄 / 宽体、Display、手写、实验体，按气质选，别默认 Inter。
- 中文：现代黑体、宋体 / 衬线、圆体、书写体、特色展示体；展示体只用于标题短文本，长正文优先可读性。
- 数字：基线、字面高度、宽度、对齐要统一，别用宽窄不一的艺术体。
- 字重、字宽、字距、大小写、斜体、断行都能出设计感，别只靠换字体名。
- 默认最小 12px（例外仅限小 logo / 图案内嵌文字，不扩展到正文、操作和关键状态）。正文与操作文案按内容自然换行；展示标题可按语义与构图有意断行，但须验证目标视口与字体回退下的可读性、不碰撞与信息完整。

字体来源与加载见第六节。

### 4.5 配色先定职责，不套固定色板

先看产品、素材与品牌气质，再决定背景、内容面、文字、重点和状态的色彩关系。中性、低饱和、鲜明品牌色、深色或双色都可以成立；不规定通用色值或面积比例，也不把某种颜色直接判成「AI 味」。

- 颜色必须有职责：识别对象、建立氛围、引导操作、区分状态或表达数据，不能每个模块随意另配一种强调色。
- 不把雾绿、雾蓝、淡紫、黑底蓝紫光晕等熟悉组合当不经判断的默认；产品与参考有依据时，不因它们常见就排除。
- 同类内容和组件的配色逻辑保持同源；品牌主色与必要语义色可以共存，辅助区域降低视觉竞争。
- 渐变、透明、材质、光影要服务构图或状态，不作为默认的高级感包装。
- 对比保证正文、重要状态和控件可辨；不能用过淡文字、低饱和或压小字号掩盖信息拥挤。

### 4.6 图标一套，图形要有目的

- 图标、符号、几何、插画、摄影、数据可视化都能当主视觉，不只靠文字和卡片。
- 图形风格按气质选，线条、比例、质感要协调。
- 功能图标重在易识别；品牌图形可以更有性格。
- 不混风格不同的图标库，不用 emoji 当功能图标。
- 图形要有表达目的：识别、解释关系、传递状态、塑造品牌、制造张力。
- 影像要有构图、色彩、内容逻辑，别随便拼图填版面。

### 4.7 细节做全，不只首屏

- 字体渲染、字距、对齐、边界、图标比例、层级、交互状态、内容细节都要管。
- 边框、分割线、阴影、圆角、纹理、透明按需用，不为装饰而装饰。
- 组件之间既保持一致，也允许关键区域有合理差异。
- 滚动区、弹层、菜单、空状态、错误状态和首屏一样要做完。
- 别为「像设计稿」牺牲真实使用时的可读性、可操作性、响应速度。

### 4.8 边框不能被裁掉（清单第 1、6 条）

**带边框组件放进会裁剪的父容器时，父容器 padding 必须 ≥ 组件所有状态的最大边框宽度**，否则边框被切一截，读起来就是「渲染坏了」。

`overflow: hidden` 裁的是 padding box：内边距能吸收子元素外溢，但外扩 `box-shadow` 和 `outline` 画在边框盒之外，内边距救不回来。

按优先级解：

1. 全局 `* { box-sizing: border-box }`，从根上消除溢出。
2. 父容器 `padding ≥ 边框宽 + 1px`。实测边框 4px 时 `padding ≤ 6px` 仍被裁，`≥ 7px` 完整——恰等于边框宽也会被裁。
3. 用 inset 阴影替代：`.card { border: 0; box-shadow: inset 0 0 0 1px var(--line); }`。

**禁止**：外扩 `box-shadow` / `outline` 当常驻边框；负 margin 合并相邻边框。

hover 才出边框（最高频翻车点）：用透明边框占位、只切颜色。

```css
.item { border: 1px solid transparent; transition: border-color .18s; }
.item:hover { border-color: var(--line); }
```

### 4.9 原生控件必须自绘（清单第 2–5 条）

原生控件由系统渲染，和自绘 UI 两套语言，最容易被跳过、也最破坏整体感。按「出现什么 → 必须写什么」办：

| 页面出现 | 样式表里必须存在 |
| --- | --- |
| 局部滚动容器 | `scrollbar-width` / `scrollbar-color` + `::-webkit-scrollbar*`（含 thumb hover），8–10px，只作用于该容器 |
| `input` / `textarea` / `select` | `appearance: none` + 自绘 border / radius / `focus-visible`，全取 `--control-*` |
| **任何下拉** | **自绘面板**：容器 + 选项 hover / 选中 / 禁用态 + 圆角阴影，与输入框共用 `--control-*`。原生 `option` 弹出层不受 CSS 控制，不能留 |
| `checkbox` / `radio` / `range` / `progress` | `accent-color: var(--brand)` 或自绘，不留系统蓝 |
| 日期 / 时间 / 颜色等复合输入 | 自绘面板或限定输入格式，不用原生弹出层 |

建好设计系统、写全局 CSS 时一次写完，别等收尾补。内边距、字号、圆角、聚焦态都进变量（`--control-bg` / `--control-border` / `--control-radius` / `--control-focus`），和卡片按钮同一套视觉。

## 五、动效

动效是设计的一部分，不只是给按钮加 hover。按气质和需求判断它该扮演什么角色。

### 5.1 先判断要不要动

- 用户点名要高级、流畅、炫酷、沉浸、电影感时，把动效当重点，用 GSAP 等专业库做复杂效果，别用 CSS transition 敷衍。
- 品牌站、创意展示、产品发布、作品集、互动叙事可以设计有节奏的入场、滚动叙事、视差、文字动画、形变、遮罩揭示、分层运动、连贯转场。
- 专业工具和高频界面，动效用来讲清状态、建立空间关系、给反馈；可以精致，但不能妨碍效率。
- 没明确要求时按气质适度设计，别为炫技加无意义动效。
- 别所有元素都淡入上移，也别每个组件各自表演。

### 5.2 缓动要自然，别线性

- **避免机械线性**：移动、缩放、转场用自然加减速或弹簧；Linear 只给匀速旋转、进度、持续滚动。
- **缓动要有质感**：按距离、质量、场景选 ease-out、ease-in-out、power、expo、back、spring；夸张弹性克制用，别廉价反复弹跳。
- **适当加阻尼**：大面板、浮层、拖拽、跟随、磁吸、空间转场可以有惯性、阻尼、回弹。
- **动作要有因果**：进入、离开、展开、收起、切换、拖动要符合空间直觉。
- **编排要有节奏**：可错峰、重叠、衔接、分层，但要有主次，别所有元素同时乱动。
- **别做无意义循环**：永久漂浮、背景乱动、抢注意力的动画不要。
- **性能优先**：优先 transform、opacity；复杂滤镜、模糊、大面积实时效果慎用。

### 5.3 复杂动画用 GSAP，先查 gsap-skills

**先判定：系统已装 `gsap-skills` 就优先调用它拿最新 API 与写法；没装就主动问用户，推荐执行 `npx skills add https://github.com/greensock/gsap-skills`，由用户决定装不装，装完再用。** 别凭记忆手写过时用法。

复杂动画（入场叙事、滚动驱动、时间轴编排、交互拖拽、多元素协同）用 GSAP：

- 用 Timeline 编排一组动画（标签、重叠、嵌套、回调），别堆互不相关的 delay。
- 滚动驱动用 ScrollTrigger；平滑滚动、逐字、路径、翻转按需引插件。
- 简单状态反馈用 CSS transition / keyframes，不为用库而引库。
- CDN 引入（如 `gsap@3`），模块化管理，便于播放 / 暂停 / 反向 / 重置 / 清理。

### 5.4 连续操作要接得住、反得回

**新操作到来时从当前视觉状态自然衔接**，不闪烁、不跳回起点、不让动画状态和真实 UI 脱节。

- 可逆状态（展开/收起、开/关）：复用同一 Timeline，`reverse()` / `play()`，不重建。
- 连续变化目标（拖拽、光标跟随）：用 `gsap.quickTo()` 跟随最新输入，别每次新建补间。
- 多序列衔接：Timeline / 嵌套 / 回调 / 状态机统一管，别让独立动画抢同一属性。
- 按语义区分「继续 / 反向 / 转向新目标 / 并行其他属性」，别一律追加或一律终止；只覆盖真正冲突的属性（`overwrite: "auto"`，不随意 `kill()` 或全局 `overwrite: true`）。

### 5.5 尊重减少动效，别阻塞

- 支持 `prefers-reduced-motion: reduce`；减少动效时信息和功能仍要完整。
- 不用动画藏关键内容，或延迟用户必须立刻知道的信息。
- 避免高频闪烁、快速大幅缩放、引起不适的视差。
- 滚动动画不能干扰正常滚动、键盘和触控操作。
- 页面离开或组件销毁时，清理监听器、ScrollTrigger、动画实例。
- 首屏重要内容不能等动画库加载完才显示。

参考：[GSAP 文档](https://gsap.com/docs/v3/) · [Timeline](https://gsap.com/docs/v3/GSAP/Timeline/) · [Apple HIG Motion](https://developer.apple.com/design/human-interface-guidelines/motion) · [Material Motion](https://m1.material.io/motion/duration-easing.html)

## 六、素材、图标、字体

**统一用 `tools/resource-getter/get.py` 取素材**，别手拼站点 URL，别散落来源不明的外链。来源矩阵、许可、排错见 `tools/resource-getter/README.md`。

### 选型：矢量 > 抠图 > 摄影 > 手绘 > AI

1. 透明矢量插画：unDraw / Storyset / DiceBear / Doodle Ipsum
2. 抠图 PNG：Pixabay `--transparent` / pngimg
3. 摄影：Pixabay / Picsum / Unsplash / Pexels
4. 手绘 SVG（几何、装饰、图表）
5. AI 生图（最次，见下）

**默认热链，慢则落盘。** `get` 的 auto 模式实测 TTFB：> 0.9s 或读取 > 2.5s 就下载到 `ui/<page>/assets/`。再快也别把二十张大图堆首屏。

```bash
python tools/resource-getter/get.py search undraw "developer" --limit 5
python tools/resource-getter/get.py get undraw "developer" --page <page>
python tools/resource-getter/get.py get pixabay "fox" --type illustration --transparent --page <page>
python tools/resource-getter/get.py get pngimg "fox" --page <page>
python tools/resource-getter/get.py get storyset "developer" --style rafiki --page <page>
python tools/resource-getter/get.py url dicebear --style shapes --seed mono --page <page>
python tools/resource-getter/get.py probe <url>
```

`--page` 自动建 `ui/<page>/assets/` 并打印 `<img src="./assets/...">`；`--mode hotlink` 只出 URL，`--mode download` 强制落盘，`--force` 覆盖同名。（目录规则见第八节。）

### 透明底：别带方框

- **unDraw** 有直链 `cdn.undraw.co/illustration/<slug>.svg`，但带满幅 `#f8f8f8` 底，工具会自动移除（保守判定，覆盖不到 97% viewBox 就不动）；`--no-strip-bg` 可保留。
- **Storyset** 返回透明 SVG，需署名 `Illustration by Storyset`。
- **Doodle Ipsum** 用 `?bg=transparent`；裸 URL 每次刷新换图，`get` 会跟随 307 并缓存 `?i=` 静态地址。
- **DiceBear** 的 `backgroundColor=transparent` 必带，否则默认给纯色底。
- **Pixabay** `--transparent` 先按标签过滤，没命中就对前 8 条只取 64 字节做 PNG IHDR alpha 检查。
- **pngimg** 原生抠图，但许可 **CC BY-NC 4.0**，只能原型用。
- 换主色：unDraw 用 `--recolor '#c8a24a'`（替换 `#6c63ff`）；其他 SVG 加 `--from-color '#6c63ff' --recolor '#c8a24a'`。

### 许可红线

- **可商用**：unDraw、Pixabay、Doodle / Blush、Unsplash、Pexels、Picsum。
- **需署名**：Storyset / Freepik。
- **禁商用**：pngimg、Pixiv 作品（仅私人参考）、Pravatar（仅原型）。
- unDraw 不得转售或用于训练模型；Pixabay / Unsplash / Pexels 不得原样转售。

**拿不到稳定直链，别再用**：`illustrations.popsy.co`（超时）、`popsy.co`（530）、`svgrepo.com/show/*.svg`（429）、`cdn.jsdelivr.net/gh/realvjy/illustrations`（404）、`botanimals`（404）、`api.iconify.design/undraw:*`（404）。

### 图标：一套 Tabler，两态

只用 **Tabler Icons**，不混库，不用 emoji 当功能图标。图标名在 `tabler.io/icons` 查。

线宽由加载的样式表决定，**全站只选一种**：

| 样式表 | 线宽 | 适用 |
| --- | --- | --- |
| `tabler-icons.min.css` | 2 | 大号展示图标 |
| `tabler-icons-300.min.css` | 1.5 | **推荐**，多数 UI 通用 |
| `tabler-icons-200.min.css` | 1 | 小图标、高密度工具栏 |

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@tabler/icons-webfont@3.49.0/dist/tabler-icons-300.min.css">
<i class="ti ti-flask"></i>
```

需要两种线宽时用内联 SVG 各自控 `stroke-width`，别切两套 webfont。

**激活态必须用实心。** 线性图标在选中时常常看不出变化——收藏、书签、星标、tab 选中、开关打开、已读这类必须有可见差异，一律换实心。零构建页面直接内联 SVG：激活 `fill="currentColor"`，非激活 `fill="none" stroke="currentColor" stroke-width="1.5"`，同一图标留两态切 class。webfont 的实心是另一套字体（`tabler-icons-filled.min.css`），共用 `ti ti-<name>` 但字形不同，同页混排易冲突。

有开 / 关语义的图标（heart / star / bookmark / bell / check / eye / lock）都备两态，实心只出现在激活态。

### 字体：CDN 多源，别吊死一家

字体不走 resource-getter，直接 CDN。多试几个源，优先快的，找不到就换。常用：Google Fonts、Fontsource、ZeoSeven、jsDelivr / unpkg 字体包。

`@import` 放 CSS 最前，版本写死别用 `latest`：

```css
@import url('https://cdn.jsdelivr.net/npm/@fontsource/liu-jian-mao-cao@5.3.0/index.css');
```

按需引，别一次加载一堆字重和字符集；设好回退栈，字体没加载时布局不能塌。Fontsource 找中文展示体好用：`fontsource.org/?classifications=handwriting&languages=zh_Hans`。

**加载慢**：先换字体、换来源。字体一律在线 CDN 引入并设置系统兜底栈，不下载托管到 `assets/`。

### AI 生图：最次选项

只在素材既无在线替代、又超出手绘 SVG 能力时用（复杂拟物图标、风格化立绘、精细透明图形）。10 个以内基本形状能拼出七八成像的，一律手绘。

```bash
python tools/image-forge/generate.py --style lineicon \
  "a sci-fi HUD line icon, single cyan stroke, hexagonal frame" \
  ui/<page-name>/assets/icon-hud.png
```

- 需本地 `.env`（`IMAGE_API_BASE_URL` / `IMAGE_MODEL` / `IMAGE_API_KEY`），且页面目录下没有 `assets/`。
- `--style` 必填：`lineicon` / `skeuomorphic` / `illustration` / `render3d` / `iso25d` / `anime` / `chibi` / `photoreal` / `product` / `cinematic` / `stylized` / `guofeng`；`--list-styles` 查全表。
- 提示词只写主体、材质、光。**不写** `ultra detailed` / `8k` / `masterpiece`——它们是噪点和碎片感的来源，干净词由 `purify.json` 自动叠加。
- 单页 ≤ 5 张，更多要先列清单问用户。
- 生成一次就用，不回读分析、不反复重生成。`--dry-run` 先看拼好的提示词。
- 图片还原例外：为匹配原图可比对一次、不过再改一次提示词重生成。

## 七、功能做全，呈现做简

**功能范围按用户要求、当前产品定位与核心任务判断**，品类常识用于补齐必要流程，不用于扩展成行业功能全集。做编辑器就要能完成真实编辑；做后台就要覆盖必要工作流。不能为画面简洁省掉核心能力，也不能为显得完整添加无关统计、推荐、天气、宣传、助手或重复入口。

**先分配展示优先级**：当前任务所需内容直接呈现；相关但低频的能力放进可发现的真实次级视图 / 菜单 / 上下文操作；不属产品范围的内容不做。完整度检查整个流程，简洁度检查当前这一屏，不能混成「所有功能都放首页」。

**必须做到**
- 先梳理真实需要的功能，再设计布局；每项功能都要有入口和真实响应。
  - 软件：创建、导入导出、编辑、查找、视图、设置等，不适用不强加。
  - 网页：导航、浏览、搜索筛选、表单校验，以及空 / 加载 / 失败状态。
  - App：核心流程完整，含导航、返回、手势、列表详情、表单、通知。
  - 组件：空闲、悬停、聚焦、加载、成功、失败、禁用，以及必要键盘操作。
- 核心流程能从头走通：优先用本地数据在前端完成，不依赖后端。
- 状态齐备：空 / 加载 / 失败 / 成功 / 禁用，每个列表、表单、异步操作都要考虑。
- 每个可见控件都要有响应：点击、悬停、切换、展开、弹层、Toast、复制、筛选、增删。

**功能多而界面简**
- **分组**：工具栏按任务分 tab，一屏只露一组；低频进二级菜单。
- **渐进披露**：设置项给默认值，细节藏进二级视图 / 侧栏 / 更多菜单，用到再展开。
- **上下文出现**：选区浮条、右键菜单、行内操作，只在相关时出现。
- **一器多用**：一个下拉承载多值，一个按钮带菜单，一个面板切多视图。
- **键盘**：常用操作给快捷键（⌘S / ⌘F / ⌘B），界面就能少放按钮。
- **别用弹层替代页面**：有实质内容的模块（详情、编辑、列表、设置）做成真实视图，弹层只留给原子操作。把功能全塞进对话框，界面会退化成「一屏 + 一堆弹窗」（见 0 节）。

**不许做**
- 加无关功能凑数（记账 App 里的天气、编辑器里的股票行情）。
- 除连接 / 认证类按下方规则模拟外，不伪造业务成功（如「支付成功」「已上传至服务器」）。
- 把业务数据写进 localStorage / sessionStorage / IndexedDB——刷新就回演示状态。只有 UI 偏好（主题、动效开关）可缓存。
- 暴露「这是模拟的」：本地数据、假延迟可以，但文案不能出现「演示」「示例」「Mock」，也不能画教学标注（见 4.3）。

**连接 / 认证类交互：成功与失败交替模拟**

新建 UI 和以图还原都适用。连接服务器、登录、注册、同步、API key / 授权、设备搜索与配对，以及任何类似的异步连接动作，**默认不走「需要连接服务」或直接失败**，要模拟出完整结果：

- 用内存计数按触发次序交替：**第 1 次成功 → 第 2 次失败 → 第 3 次成功……**（奇数成功、偶数失败），让成功态和失败态两种 UI 反馈都能看到。
- 成功轮次：账号 / key 只做格式校验（邮箱、手机号、非空等），不校验真实性；通过就一定连接成功，接着走成功态逻辑（已连接视图、设备列表、同步完成的数据等）。
- 失败轮次：给真实的错误态（超时 / 无法连接 / 重试提示），保留重试入口，重试按计数继续交替；不能出现「这是模拟的」字样。
- 过程加加载、进度、信号波动等反馈，别一步跳到结果。
- 无输入的动作（搜索手环、扫描设备、重新同步）同理：首次搜到结果，刷新 / 重新搜索就失败，往复交替。
- 计数只放内存，不写 localStorage。

前端能模拟就模拟：本地数据、假延迟、真实状态流转；不许因为麻烦删功能，也不许留死按钮。用户明确说「不用模拟」「按指定成功 / 失败流程」「不用管连接交互」时按用户要求，其余默认按上面交替实现。

**和视觉冲突时**：先调信息架构和呈现方式（分组、收进菜单、改上下文操作），而不是删功能。只有用户要求删减或功能确实不属产品范围时才移除，并说明原因。

**分寸**：优先简洁原生 JS 或 Alpine.js，避免无谓抽象和过度设计；交互质感按第五节。

## 八、技术约定（清单没覆盖的部分）

### 适配：布局不挤不撞，按响应式伸缩而非整页等比

**这是生成时就要定的规则，不是交付前才补。** 自检只验证。

**1366×768 是标准参考值，不是硬基准。** 按页面内容密度自己定一个合理的检查尺寸，允许小范围浮动；内容很少的页面不必硬撑到 1366，视情况取一个更合适的值。关键是这个尺寸下布局要健全：

- **文字不重叠、不互相遮挡**。例外：为增加层次而**有意设计的重叠 / 错位**不算问题，别把它当溢出删掉。
- **不出现无效换行导致的溢出**：文字被挤到换行后撑破容器、被裁掉、或压到相邻元素。
- **组件容器不能过小导致内部元素紧贴**：文字贴边、图标挤成一团、内容与边界之间几乎没有内边距。
- **组件之间不能紧贴或重叠**：间距塌陷、卡片边缘相碰、区块叠在一起。
- 反过来也别为了避开紧贴撑出多余缝隙。判据：逐块扫一遍，每块都能完整读出、彼此有呼吸空间。

**视口变化按 UI 响应式规范来，不是整页等比放大。** 把整个页面当图片一起放大，放到很大时会整体膨胀，不是常见的适配做法：

| 对象 | 放大时怎么办 |
| --- | --- |
| **布局**（容器宽度、栅格列宽、留白、区块间距） | 随视口**按比例伸缩**：`%` / flex / grid / `minmax()` / `max-width` 版心 |
| **正文字号、图标、小图形、圆角、边框** | **一般保持固定档位**（固定值 + 少量媒体查询换档），不跟着等比例放大 |
| **大标题、首屏背景、大段落行宽** | 才用 `clamp()` 或 `vw` 混合给一个**更缓的缩放曲线**，并设上下限，别无限放大 |
| **断点位置** | 按内容何时开始挤来定，不是写死某个像素值 |

**窄视口**：小于检查尺寸时按需要重排——分栏改单列、侧栏收抽屉、导航折叠、留白收紧。**非强制**，主要针对网页和软件；App / 组件一般不做响应式，保持固定比例画布等比缩小即可。

```css
:root { --gap: clamp(16px, 2vw, 32px); --maxw: 1280px; }
.layout { width: min(100% - 2 * var(--gap), var(--maxw)); margin-inline: auto;
          display: grid; grid-template-columns: repeat(auto-fit, minmax(260px, 1fr));
          gap: var(--gap); }
body      { font-size: 16px; }                    /* 正文固定档，不随视口等比涨 */
.hero     { font-size: clamp(40px, 6vw, 88px); } /* 只有大标题用更缓的缩放 */
@media (max-width: 760px) { .layout { grid-template-columns: 1fr; } } /* 断点按内容定 */
```

**禁止**：`html { font-size: calc(100vw / N) }` 或 `transform: scale()` 让全站尺寸线性等比放大——那是整体膨胀，不是响应式。

**边界**：
- 软件 / App / 组件的画布按 0 节保留 W:H 与 `cqw` 等比（画布本身是固定容器，与网页流式布局不是一回事）；画布内仍禁视口单位。
- 缩放后仍要可读可点；正文 ≥ 12px、触控区可点（见 4.4）。
- 字号、间距、字阶的相对层级在任何尺寸下都不能乱。

### 其他约定

- HTML / CSS / JS，内容多时拆 `index.html` + `styles.css` + `app.js`。
- 第三方库只用 GSAP / Lenis / Alpine.js，能不引就不引。
- 语义化标签；可见焦点态；必要的 `aria-*`；对比度达标。
- 文件名语义化、英文 kebab-case，不用 `1.png` / `img2.jpg`；`metadata.json` 写法按 `skills/ui-metadata/SKILL.md`。

## 九、检查：反例与自检

### 必须避免（审美层反例）

可机检的判定以「〇.1 硬约束清单」为准。

- 不理解产品就套 SaaS 模板、默认字体、默认配色。
- 为简约删掉用户需要的功能、信息、入口。
- 所有内容卡片化、卡片套卡片，用边框阴影代替层级。
- 文字大小相近、缺重点，或只靠颜色制造层级。
- 为「高级」过度留白，导致空洞、信息不足、操作不便。
- 为「丰富」堆渐变、发光、玻璃、随机几何碎片、装饰图标。
- 字体不合气质；艺术字体用在长正文或破坏数字对齐。
- 只做静态首屏，滚动区、弹层、菜单、空状态、错误状态没做。
- 参考尺寸下文字重叠遮挡、无效换行溢出、容器过小让内容贴边、组件之间紧贴或重叠（有意设计的重叠 / 错位除外）。
- 把整页当图片等比放大：`html { font-size: calc(100vw / N) }` 或 `transform: scale()` 让所有尺寸一起涨（不是响应式）。
- 只复刻参考图那一屏，没推理补全其余模块 / 页面；或用一堆弹出对话框代替真实界面。
- 动画全线性、统一淡入，或大量互相冲突的独立动画。
- 重复操作导致跳帧、闪烁、跳回起点、状态错乱。
- 为视觉牺牲可读性、可访问性、性能、真实操作体验。
- 空洞营销词、重复文案、没有响应的装饰控件。

### 交付前自检

**两类证据分开**：硬约束 17 条必须逐条指向选择器 / 样式 / DOM / 状态，拿不出代码证据就补完；审美、可读性与流程按实际画面、内容关系和运行状态检查，不能仅凭代码声明通过。下面的问题用于分别核对这两类证据。

1. 产品定位：视觉语言贴合产品气质，不是套模板？
2. 整体审美：构图、排版、字体、配色、图形、影像形成统一且有辨识度的整体？
3. 字体：主动选了合适字体？标题有设计感？正文易读？数字协调对齐？
4. 功能：该有的都有？有参考图时，是否按识别出的产品逻辑补全了未展示的模块 / 页面、且与主界面同源？补全的功能是否落在真实视图而非一堆弹窗？没有死按钮？
5. 信息层级：重点突出？内容好找好懂？
6. 动效：运动自然？复杂动画有 Timeline？连续操作能衔接、反向、更新目标？
7. 细节：图标、边界、层级、对齐、状态、素材精致统一？
8. 适配（**验证，不在这里才做**）：生成时已按第八节做对？参考尺寸下文字无重叠遮挡（有意设计除外）、无无效换行溢出、容器不过小紧贴、组件之间不紧贴不重叠；布局流式响应、正文字号固定档、大标题用 `clamp()`，没有全站等比放大；窄视口重排不横滚？
9. 无障碍与性能：减少动效时仍完整？没有明显掉帧或阻塞？
10. **硬约束举证**：对「〇.1 清单」17 条逐条给代码证据——画布边界、对话框比例、边框完整性、原生控件含下拉面板、正式感文案、还原适配（网页不锁比例、容器一屏不滚、背景只还原样式）、适配基准（第 17 条：参考尺寸不挤不撞 + 标准响应式、无全站等比）、推理补全（第 10 条：多视图 + 不堆弹窗）全在这一步核，口径以清单为准。
11. **两份文档回归**：重读 `UI设计原则.md` 与 `现代化UI设计参考.md`，按后者第七节核对修正。先看标题与章节解释定位，拿不准再细读。
12. **Hallmark 应用**：已安装时是否实际调用并完成去 AI 味审查与修正？未安装时是否向用户推荐 `npx skills add nutlope/hallmark -g`，并如实说明未使用该技能？

最后整体审视：去掉无意义装饰和重复表达，保留必要功能与信息。画面仍显普通就重推构图、字体、视觉语言，别继续堆卡片、渐变、阴影。
