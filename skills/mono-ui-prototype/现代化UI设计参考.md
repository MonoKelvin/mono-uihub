# 现代化 UI 设计参考

> 本节说明：这是一套可直接照着做的 UI 设计风格规范，回答「这类界面通常怎么做、为什么这么做更好看、动手时按什么思路选」。生成原型前通读全文，完成后再读一遍做回归检查（见第七节）。若与 `SKILL.md` 的硬性规则冲突，一律以 `SKILL.md` 为准。

---

## 一、概述：这套风格的定位与用法

> 本节说明：交代文档管什么、怎么读、哪些是弹性尺度。先立住定位，后面各节才不会被执行成一张死板的参数表。

### 1.1 文档定位

> 本节说明：说明本文件与 `SKILL.md` 的分工，避免把风格参考误当成流程规范。

本文件是**风格参考**：规定视觉语言长什么样、用哪些手法、避开哪些做法。`SKILL.md` 是**生成规范**：规定流程、容器边界、对话框比例、硬禁清单、技术约定与交付自检。风格判断看本文件，能不能做、必须怎么做看 `SKILL.md`。

它不描述任何一个具体页面，也不提供可照抄的布局代码。所有条目都写成「设计某类界面时应该怎么做」的范式，落地时仍要按产品定位现场推导，不要把它当成新模板。

### 1.2 表述约定

> 本节说明：统一文中用词的含义，避免把分类词误读成限制、把区间值误读成硬参数。

- 文中「网页 / 移动应用 / 桌面软件 / 组件」是**适用对象**的分类，不是限制：同一套视觉语言可以用在不同容器上，差异只在排布与信息密度。
- 字号倍率、留白比例、圆角范围、间距倍数都是**经验区间**，用于起步校准；按实际内容、屏幕尺寸和品牌气质调整，不要当硬性数值。
- 「优先 / 通常 / 建议」表示倾向，允许有理由地偏离；「禁止 / 必须」表示硬约束。

### 1.3 适用边界

> 本节说明：说明什么时候该按这套风格做、什么时候可以主动偏离，避免风格被套到不合适的产品上。

- 需要主动偏离：产品本身要求强个性表达（游戏、儿童、潮流实验、艺术项目），或品牌已有明确的视觉资产与规范。此时保留「单一重心、克饰用色、层级清楚」这些底层手法，配色与字体由品牌决定。
- 风格服务于内容。信息密度高、操作链长的产品，先保证可用与可扫读，再谈留白和字阶，不要为了好看删功能。

## 二、风格总览：这套风格到底是什么

> 本节说明：先给一句可判断的定性，再拆开「为什么看起来高级」的底层手法。后面所有维度都是这几条手法的展开。

### 2.1 一句话定性

> 本节说明：用一句话概括这套风格，作为后面所有判断的锚点。

**以中性色为底、以内容主体（大标题、产品图或关键数据）为唯一视觉重心，用字号和留白建立层级，把装饰压到近乎看不见，只在状态和焦点上用一次强调色。**

它不靠「加东西」变好看：没有满屏渐变、没有每张卡片都描边加阴影、没有一堆彩色图标。它靠的是取舍——确定一个主角，然后让其余所有元素主动退后。四类容器在布局形态上差别很大（桌面软件是密集工作台、网页是编辑式长页、移动应用是单列卡片流、组件是孤立小构图），但收敛到这一层完全一致。

### 2.2 为什么它看起来高级：五条底层手法

> 本节说明：把「高级」拆成可验证、可复用的具体动作，避免空泛形容。

1. **单一视觉重心**。网页与落地页几乎每屏只有一个大对象：一张大尺寸产品图，或一组超大标题；其余文字压得很小、颜色压得很淡。工作台里一屏通常只有一张深色或彩色主卡，其余全是同类白卡。重心唯一，视线不需要竞争。
2. **层级靠字号差，不靠容器差**。主标题与辅助文字的字号差常达 4–8 倍；小标签用全部大写（中文用字号与浅色）、放宽字距，而不是塞进带边框的 chip。信息层次用排版解决，卡片和边框只承担分组。
3. **留白是主动分配的结果**。首屏大面积空区域不是没画完，是刻意把内容挤到一侧或一角；空白区与内容区比例常接近 1:1 甚至更高。留白把主体「托」出来，也让密集区有呼吸对照。
4. **中性色承担 90% 以上面积**。近白 / 浅灰（或近黑）是绝对主色，彩色只以小面积出现：状态点、进度条、按钮、图标、单个数据高亮。强调色越克制，出现时越有效。
5. **细节质感在「极轻」而不是「极炫」**。1px 发丝线、低透明度大扩散阴影、16–28px 圆角、统一线宽的线性图标、精确对齐的数字栏。这些细节近看才察觉，但缺了就会显得粗糙——这是「无 AI 味」的关键来源之一。

### 2.3 四类容器的形态差异与收敛

> 本节说明：先承认差异，再说明差异只发生在「排布与信息密度」层，视觉语言层是同一套。

- **桌面软件**：信息密度最高。左侧细导航 + 顶部工具条 + 多列卡片或 Bento 网格，一屏内并列多个数据模块，靠卡片内边距和统一圆角维持秩序。
- **网页**：信息密度最低。编辑式长页，一屏一个主题，大标题 + 单一主视觉，垂直方向按章节推进。
- **移动应用**：严格单列，卡片化、大圆角、大留白，视觉重心常是一张图或一个超大数字；底部标签栏固定。
- **组件**：本身就是一个完整的小构图，孤立呈现，重点在状态齐全与细节精确。

差异集中在「怎么排」，不影响「怎么选色、怎么定字阶、怎么用装饰」。第五节会把这些差异落成分场景范式，再收敛回一套统一风格。

## 三、UI 设计要点：逐维度的特征与设计思路

> 本节说明：这是文档主体。每节先给该维度的解释（管什么、为什么影响观感），再列特征，最后给可直接指导原型生成的思路。思路统一按「用什么手法 → 达到什么效果 → 注意什么边界」来写。

### 3.1 排版

> 本节说明：管版式骨架、分栏、栏宽、图文关系和视觉重心。排版决定第一眼的秩序感，是这套风格里权重最高的一项。

**特征**

- 网页主流是「左文右图」或「上文下图」两区构图：文字区收得很窄（约占版心 1/3 至 2/5），产品图占其余并允许轻微越出网格；页面四周留白很宽，内容不贴边。
- 网页另一类是全幅摄影 / 场景图作底，标题压在图上，图上再叠一条悬浮功能条；文字与图之间靠暗角或局部深色保证可读。
- 栏目不用等宽卡片阵列铺满，而是编辑式错落：大图配小图、编号（01 / 02）、细引线、侧排竖排小字。
- 桌面软件以规整网格为主：等宽列、Bento 大小格混排、侧栏宽度固定，密度高但每格内部留白充足。
- 移动应用严格单列，卡片纵向堆叠，几乎没有横向分栏。
- 四类都不靠「卡片套卡片」制造层次，主要靠分区和字号。

**设计思路**

- 先定一个视觉重心，再排其他内容：网页用「大标题 + 单一主视觉」，软件用「一张主卡 + 若干同级卡」，App 用「一张主图 / 一个大数字」。做法是给主角分配明显更大的面积和更强的对比，其余元素统一降一档；效果是视线有唯一落点；边界是一屏只能有一个主角，出现第二个等重主角就要合并或收进次级区域。
- 分栏用「窄文字区 + 宽视觉区」而不是等分：正文栏控制在约 45–75 字符宽，视觉区占剩余空间。效果是文字易读、主体舒展；边界是窄屏时改为上下堆叠，不要横向压缩文字栏。
- 网格用来对齐，不用来填满：允许某几格留空、允许元素跨列。效果是有节奏而不是阵列感；边界是留空必须是有意的，不能因为内容不够而空。
- 长页按「一屏一个主题」分章，章节之间用大幅留白或一条发丝线切换，不要每章都换一套布局。效果是叙事连贯；边界是别为了变化而把每章做成不同风格。

### 3.2 字体

> 本节说明：管字体家族、字号阶梯、字重、行高、字距与中英混排。字体是这套风格最直接的「品质信号」。

**特征**

- 高端 / 家居 / 时尚 / 地产类常用高对比衬线体（Didone 一类）做大标题：细笔画与粗笔画反差明显、字面偏窄；科技 / 产品 / 出行类用几何无衬线粗体做超大标题。
- 桌面软件与组件几乎全用中性无衬线，字重分 2–3 档，数字用等宽或表格数字对齐，保证读数不跳动。
- 极小号全大写标签 + 放宽字距是高频手法：用作分区名、字段标签、元信息（材质、年份、规格），颜色偏浅灰。
- 大数字承担视觉角色：温度、金额、时长、百分比、序号被放大到接近标题量级，成为主体而不只是数据。
- 字号阶梯跨度大（主标题与最小标签相差 6 倍以上），中间层级少，不堆连续字号。

**设计思路**

- 按品类气质选一套主字体，再配一套辅助字体，最多两套：高端 / 编辑感用衬线大标题配中性无衬线正文；工具 / 数据类用一套无衬线拉开字重即可。效果是气质明确且不杂乱；边界是长正文、密集数据不艺术化，衬线展示体只用于短标题。
- 建立 4–5 级字阶（展示标题 / 区块标题 / 正文 / 标签 / 数字），级间倍率拉开而不是等差递进。做法是先定正文，再向上乘 2–3 倍定标题、向下压到约 0.75 定标签；效果是层级一眼可辨；边界是同一页面不要出现 8 种以上字号。
- 强调靠字重和字号，不靠颜色和下划线：一段里最多一处强调。效果是干净；边界是必须靠颜色区分的状态（涨跌、成功失败）除外，且要配图标或文字，不能只靠颜色。
- 全大写 + 字距放宽只给「短标签」，不给句子：用在 2–3 个词的分区名、字段标签上。效果是精致的编辑感；边界是中文不做全大写，改用字号 + 字重 + 浅色区分。
- 中英混排：中文与拉丁基线对齐，中文字号可比同层拉丁小半档以平衡字面高度；数字与单位之间不留大空隙，金额、温度、百分比用同一字体族。效果是混排不参差；边界是不要用展示字体排数字，笔画会不齐。
- 数字用等宽 / 表格数字（`font-variant-numeric: tabular-nums`）并右对齐成列。效果是滚动刷新时不跳；边界是装饰性巨号序号若会压到相邻元素，宁可缩小或删掉。

### 3.3 间距

> 本节说明：管基础间距单位、模块节奏、内外边距和疏密对比。留白质量直接决定「贵不贵」。

**特征**

- 同类卡片内边距一致、卡片之间间隙一致，看起来像一套刻度推出来的。
- 网页模块之间的间距远大于模块内部间距，形成清晰的「疏—密—疏」节奏；首屏四周留白尤其宽。
- 软件与组件的卡片内边距相对宽松（约 20–32px 一档），即使信息密集也不显得挤。
- 留白不是平均分配：主体周围更空，辅助信息收得更紧。

**设计思路**

- 定一个基础单位（如 4 或 8），所有间距取它的倍数，形成 4–6 级刻度，不写零散数值。做法是内边距取 2–4 倍、卡片间隙取 2–3 倍、模块间距取 8–16 倍；效果是全页节奏统一；边界是不要为了「看起来精致」把所有间距都缩小一档，那会直接丢失高级感。
- 模块间距必须明显大于组件内间距（建议 3 倍以上）。效果是分组不用线也能看出来；边界是分组不清时优先加间距，而不是先加边框。
- 主动给主体「留空」：主视觉或大标题周围至少留出一个明显的空白带。效果是重心被托住；边界是留白区里不要塞装饰图形或说明文字补空。
- 疏密做对比而不是全页统一：密集数据区旁边配一块空区。效果是既专业又不压抑；边界是密集区内部的行距、内边距仍要保持一致。

### 3.4 对齐

> 本节说明：管对齐基准、边缘规则与非对称布局里的对齐逻辑。对齐错误是「粗糙感」最常见的来源。

**特征**

- 网页左侧文字块严格左对齐到同一条基线：标题、描述、标签、价格、按钮的左缘完全对齐；右侧产品图虽跨出网格，其边界仍与某个网格列相关。
- 软件数据卡里的数字右对齐成列，标签左对齐；表格与图表共享同一条时间轴 / 基线。
- 居中只用于少数场景：短标题、空状态、播放器、孤立控件、指标大数字；正文从不居中。
- 非对称构图里，看似随意的元素仍共享隐性基线（编号、竖排文字、页码贴边但对齐到同一条水平线）。

**设计思路**

- 全页先定两条基准线（左右版心边界），所有文字块左缘对齐到其中一条，不逐块微调。效果是秩序感直接成立；边界是圆角卡片的视觉内缩要计入，图标与文字按光学对齐微调不算破坏基线。
- 数字列一律右对齐并小数点 / 单位对齐，图例与标签一律左对齐。效果是可扫读；边界是不要为了居中好看把数值列居中。
- 非对称布局必须指定一个不变的锚点（左基线、底缘或中线），其余元素绕它错落。做法是错落只改位置与尺寸，不改对齐基准；效果是活泼但不散；边界是一屏只用一个锚点。
- 居中用于「短、少、单独」的内容：空状态、播放器、单个控件。效果是仪式感；边界是超过两行的文字不居中。

### 3.5 配色

> 本节说明：管主色 / 辅色 / 中性色体系、色彩数量、背景倾向、对比度与渐变尺度。

**特征**

- 近白 / 浅灰承担绝大多数面积；深色界面以近黑为底、卡面比背景亮一档。**强调色只占很小比例**，且一屏基本只有一个。
- 网页背景多为暖白 / 米白 / 浅灰而非纯白，产品摄影提供主要色彩；文字用近黑，按钮常用纯黑实心或深色胶囊。
- 桌面软件存在浅色与深色两套：浅色为浅灰底 + 纯白卡；深色为近黑底 + 略亮一档的卡面，靠明度阶梯而不是描边分层。
- 涨跌 / 成败才引入第二、第三个语义色，且只落在数值与状态点上。
- 渐变只出现在主视觉、插画、光晕或单个按钮上，不做整页背景渐变；深色界面里的紫色 / 蓝色光晕面积也控制得很小。
- 辅助文字用中深灰而非纯黑，标签用更浅的灰，形成三级文字明度。

**设计思路**

- 先定「中性基底 + 一个强调色」的最小配色，再判断是否需要第二色。做法是背景取近白或近黑、内容面比背景亮 / 暗一档、强调色只给交互与状态；效果是专业且不花；边界是强调色在首屏的覆盖面积控制在很小比例，出现第二色必须有语义理由。
- 深色模式用「近黑 + 明度阶梯」而不是纯黑 + 描边：背景、卡面、浮层各差一档明度，必要时加 1px 极弱描边。效果是有纵深；边界是纯黑底配高饱和彩色是廉价科幻感的典型来源。
- 文字建立三级明度（主文 / 次文 / 标签），不要用同一灰度配不同字号。效果是层级清楚且不刺眼；边界是浅灰文字在彩色底上会发脏，浅底上的浅灰要保证可读。
- 彩色尽量交给内容（产品图、插画、图表）而不是容器。做法是容器统一中性，让图片成为唯一彩色源；效果是主体突出；边界是不要给每张卡片配不同底色。
- 渐变只在有明确目的时用（模拟光照、区分主卡、引导视线），并限制在一个元素内。效果是有质感；边界是渐变、发光、玻璃态不要同时出现在一屏。
- **选型倾向**：低饱和青绿 / 雾蓝 / 淡紫是特定品牌调性下的选择，不是通用默认。`SKILL.md` 4.5 已明确要求把这类配色放到最后考虑——实际选型以那条为准，先从中性基底与产品本身的颜色出发。

### 3.6 装饰

> 本节说明：管圆角、描边、阴影、毛玻璃、纹理、分割线的使用尺度与克制原则。这部分决定「精致」还是「用力过猛」。

**特征**

- 圆角成体系：大卡片 / 面板约 16–28px，按钮用胶囊或小圆角，小标签与输入框约 6–12px；同一页同类元素圆角一致。
- 描边极轻：1px、低对比，多用于分组与深色卡面的层次；Bento 网格靠 1px 弱描边 + 明度差分层，几乎不用阴影。
- 阴影低透明度、大扩散、只给浮层 / 悬浮卡 / 弹层；默认卡片靠底色差与背景分离，不靠投影。
- 毛玻璃只出现在顶栏、浮层、通知卡等少量位置，且不承载小号图标文字（避免字形消失）。
- 分割线是发丝线，横向为主；深色模式用比背景略亮的线。噪点 / 纹理极少，仅个别品牌页用于营造材质。
- 一屏通常只用 1–2 种装饰手法，不会描边 + 阴影 + 渐变 + 玻璃同时上。

**设计思路**

- 建立一套圆角刻度并在同类组件上复用，不要逐个元素单独调。效果是组件像一家人；边界是不要把卡片、按钮、输入框都做成同一个圆角值，层级会消失。
- 分组优先用间距，其次发丝线，最后才是卡片边框。效果是画面轻；边界是高密度数据区可以保留线，但线色要足够弱。
- 阴影只表达「浮起来」：弹层、抽屉、悬浮操作、hover 抬起。做法是低透明度 + 大模糊半径 + 短扩散；效果是纵深而不脏；边界是常驻卡片不加外扩阴影，深色底上尤其无效。
- 毛玻璃限定于浮层，且模糊层交给伪元素承接，内容层保持透明，避免影响字形渲染。效果是通透；边界是模糊范围必须严格等于浮层 / 画布范围，不能溢出到产品界面之外。
- 深色卡片的层次用「明度差 + 1px 内描边」建立，不要靠发光。效果是安静的科技感；边界是发光只给状态点或单个焦点，不给整片区域。

### 3.7 首屏

> 本节说明：管首屏构图范式、主视觉处理、信息密度与 CTA。首屏是「重心唯一」原则最集中的体现。

**特征**

- 网页有三种成熟范式：① 左文右图（超大标题 + 短描述 + 一个 CTA + 大产品图）；② 全幅摄影打底、标题叠在图上、底部悬浮一条功能栏；③ 深色底 + 3D / 产品主视觉 + 少量数据卡。
- 网页导航极轻：小 logo、少量极小号链接、右侧一个实心按钮；不抢主视觉。CTA 通常只有一个主按钮，次级动作是文字链或播放图标。
- 大标题常带一个「轻」的对照成分：描边 / 浅色的年份或序号、斜体单词、浅色副标题，形成双层而不增加第二个主角。
- 桌面软件没有营销首屏，首屏即工作台：一张主卡（渐变或深色）+ 一组数据卡 + 侧栏 / 顶栏。
- 移动应用首屏即功能：一张主图 / 一个大数字 + 卡片流 + 底部标签栏；不做大段营销文案。

**设计思路**

- 首屏先写一句「这屏的主角是什么」，只保留支撑它的元素。做法是主视觉占最大面积、标题与它形成字阶对比、CTA 只有一个；效果是三秒内读懂页面；边界是首屏出现两个等重 CTA 或两个大标题时，必须降级其中一个。
- 网页左文右图范式：文字区收窄、顶部留白充分、主 CTA 放在标题与描述下方、图上不加说明文字。效果是编辑式的高级感；边界是文字压在图上时必须做局部暗化或模糊，保证对比度。
- 全幅图范式：标题放在图的留白区（天空、暗部），底部悬浮功能条跨在图上形成层次。效果是沉浸 + 功能兼得；边界是悬浮条不能挡住主体，且要落在画布内。
- 软件 / App 首屏不做欢迎语和营销口号，直接给可用的内容与操作。效果是像真实产品；边界是必要的引导要做成可关闭的轻量提示，不是覆盖全屏的说明层。
- 导航在首屏要「退后」：字号小、无底色、无重边框，只用一个按钮做对比。效果是主视觉不被切割；边界是可发现性不能牺牲，链接仍需清晰可点。

### 3.8 导航

> 本节说明：管导航形态、层级组织、选中态、图标与文字的搭配。导航是「秩序」最直接的地方。

**特征**

- 网页顶部细横条：logo 左（或居中）、少量小号链接居中 / 右、一个实心按钮在最右；滚动时可变为半透明毛玻璃。
- 桌面软件左侧竖栏为主：分组标题用极小浅灰字，条目为图标 + 文字，选中态是实心圆角块或左侧色条；也有顶部 ribbon / 多标签形态（工具类软件）。
- 侧边导航的共性是「分组清晰 + 选中唯一 + hover 微反馈」，不靠彩色图标堆叠区分。
- 移动应用底部 3–5 项标签栏，图标 + 小字，选中项换实心图标或强调色；顶部只放返回 / 标题 / 单个操作。
- 选中态都用「填充 + 强调色」或「实心图标」，不用单纯加粗文字。

**设计思路**

- 按容器选形态：网页顶栏、软件侧栏、App 底栏、组件内嵌。做法是每类只选一种主导航，不混搭；效果是符合使用习惯；边界是软件里如果同时需要侧栏和顶栏，顶栏只放全局操作（搜索、账户），不放第二套导航。
- 层级用「分组小标题 + 缩进 / 留白」表达，不用多层边框。效果是层级可读且轻；边界是分组不超过两级，更深的层级收进抽屉或展开项。
- 选中态做成明确的填充块（圆角胶囊）+ 强调色或实心图标，一次只有一个。效果是位置感明确；边界是别用「仅文字变色」当唯一选中反馈，弱对比下看不出来。
- 图标统一一套线性图标、统一线宽，与文字等高对齐。效果是整齐；边界是别在导航里混实心与线性图标，除非实心只用于选中态。
- hover 只给微底色或轻微位移，不给阴影放大。效果是安静的反馈；边界是别让 hover 触发布局变化。

### 3.9 引导、空状态、加载与反馈

> 本节说明：管新手引导、空状态、加载态、提示与反馈。这部分是「像真实产品」的关键。

**特征**

- 加载用骨架屏或细进度条，不用整屏 spinner：刷新 / 提交后先出现灰色占位块或进度指示，再换成真实内容。
- 状态切换是「就地完成」的：同一个按钮 / 输入框从 idle → loading → success → 复位，靠形状与颜色渐变，不新开弹层。成功态用整块填充色 + 对勾，失败态用红色小面积 + 叉号。
- 反馈短促且闭环：进度条走完 → 满色成功 → 自动回到初始态，整个过程可重复。
- 空状态常用虚线拖放框 + 一句简短说明 + 一个次要动作，不做插画堆砌。
- 通知 / Toast 是小圆角卡片 + 一个状态图标 + 一行文字，绿勾 / 红叉区分结果。

**设计思路**

- 加载态用骨架屏承接内容区，用进度条 / 转圈只承接局部动作。做法是占位块形状与真实内容一致；效果是布局不跳、等待可预期；边界是不要整页遮罩 + 全屏 spinner。
- 状态机就地切换：一个容器承载 idle / loading / success / error / 复位，靠形状、颜色、图标三者同步变化。做法是形状从胶囊渐变到圆形再回到胶囊、颜色从中性到语义色、图标从箭头到转圈到对勾；效果是连续、不闪烁；边界是状态切换不要替换成另一个 DOM 元素，也不要插入说明文字解释「正在加载」。
- 反馈要有闭环：成功 / 失败展示一小段时间后自动复位，允许再次操作。效果是可重复演示；边界是复位动画同样要平滑，不要瞬间跳回。
- 空状态给「现状 + 一个下一步」，控件用虚线框或极简图形，文案写真实业务语境。效果是不空洞也不说教；边界是不画教学标注、箭头气泡、序号说明。
- 提示用轻量 Toast / 内联文字，不用模态打断。效果是不阻断操作；边界是需要用户决策时才升级为对话框。
- 新手引导按「轻量、可关闭、只标一处」处理，避免整屏遮罩教学层。

### 3.10 文字和段落

> 本节说明：管正文可读性、段落长度、标题与正文的层级差、强调方式。文字质量是「无 AI 味」的核心。

**特征**

- 描述性段落很短，通常 2–3 行、每行 40–60 字符；大标题下设一行浅色副标题，不写长段介绍。
- 标题与正文的字号 / 字重落差很大，正文行高宽松（约 1.5–1.7）。
- 信息常拆成「小标签 + 值」的成对结构（规格、数量、日期、统计），标签小而浅、值大而深。
- 强调手段是字重、字号、斜体单词或单个强调色，不用下划线、不用全句大写、不用感叹号。
- 界面文案都是产品真实会有的内容（品名、价格、参数、状态），没有说明性、教学性文字。

**设计思路**

- 每个段落只承担一个意思，长度控制在 2–3 行；超出就拆成「一句主述 + 一组标签值」。效果是扫读快；边界是别为了短而丢掉必要信息。
- 标题 / 副标题 / 正文三层之间，用字号和明度同时拉开差距。效果是层级不靠颜色也能读；边界是别用三种不同颜色去区分三层。
- 把成组信息统一写成「浅色小标签 + 深色值」，标签全大写或短中文、值用大字号或表格数字。效果是密集信息也不乱；边界是同一组标签的宽度与对齐要一致。
- 界面里只写真实业务内容，不写「演示」「示例」「Mock」「占位」，也不画教学标注。效果是把原型当正式产品；边界是实现不了的能力在交付说明里讲，不写进界面。
- 中英混排：中文正文行高略高于纯英文，标点用全角，数字与单位保持同一字体族；品牌名与专有名词保留原文不强行翻译。

### 3.11 点缀和图形

> 本节说明：管图标风格、插画 / 图形语言、徽标标签、动效点缀的频率与位置。点缀的作用是「点」，不是「铺」。

**特征**

- 图标统一线性、细笔画、圆头端点，尺寸小；功能图标不做彩色填充，只有状态图标用语义色。
- 网页主视觉是真实产品摄影或高质感 3D 渲染（家具、耳机、滑板车、瓶身），几乎不用卡通插画。
- 天气 / 播放器一类小组件用扁平几何插画（云、太阳、渐变天空、有机形裁切），色彩柔和、块面干净。
- 深色界面里用细线框、节点连线、抽象光晕做背景图形，透明度很低，不干扰数据。
- 徽标与标签是小胶囊或圆点状态，配极短文字；编号（01 / 02）、细引线、小型「+」热点是网页常见的编辑式点缀。
- 每屏点缀数量很少，位置固定在边缘、角落或主体周围，不会散落在中段。

**设计思路**

- 全页只用一套图标、统一线宽与尺寸，实心形态只留给选中 / 激活态。效果是一致且有状态差异；边界是别混多个图标库，别用 emoji 当功能图标。
- 主视觉优先真实产品图或高质量渲染，图形化插画只用于「没有真实产品图或摄影可用」的场景。效果是质感可信；边界是插画的扁平几何风格要与中性基底协调，不要跳成另一种画风。
- 装饰性图形压低透明度、放在边缘或主体背后的空区，不与文字重叠。效果是有细节但不抢；边界是任何悬空在内容中段的图形都删掉。
- 编号、引线、热点这类编辑式点缀，用于解释主体或承担导航，且一屏只用一组。效果是有编辑感；边界是不要变成教学标注或说明气泡。
- 徽标 / 状态点用强调色，但面积极小。效果是提示到位；边界是别给每个列表项都配彩色标签。

### 3.12 交互与动效

> 本节说明：管转场方式、缓动节奏、悬停 / 点击反馈与状态过渡。本节只描述节奏与形态，不规定精确时长与缓动参数。

**特征**

- 滚动分章揭示是网页主动线：每屏一个主题，标题与产品图交替出现，元素带轻微上移 / 淡入，章节之间整块切换而非逐个小元素乱飞。
- 横向轮播 / 画廊切换：产品逐个淡入淡出，主体位置基本不动，只有产品与编号在换；整屏留白极大，切换节奏偏慢。
- 状态切换大量使用「形状渐变（morph）」：胶囊 ↔ 圆形 ↔ 展开面板、开关旋钮滑动并带一个脱离的小粒子、分享按钮展开成列表面板再收回。
- 环境级联动：日夜切换不只是开关变色，整个背景（星空 ↔ 蓝天、月亮 ↔ 太阳、云层遮挡、光晕）同步交叉渐变，所有变化围绕同一个因果。
- 就地反馈：拖到文件夹 → 目标高亮 / 反色 → 数量 +1 → 恢复；密码显隐 → 眼睛图标开合 + 底色反转；收藏 → 心形弹出。
- 底部抽屉 / 表单升起承担「详情 → 操作」的转场，背景保持不动或轻微变暗。
- 缓动明显非匀速，带轻微过冲 / 回弹；没有机械线性运动，也没有长时间循环的装饰动画。
- 共同节奏：短、单焦点、可逆、闭环。一次只动一个主角，操作打断后从当前状态接续或反向，不跳回起点。

**设计思路**

- 转场按「一个主角 + 一组跟随元素」编排：主角做位移 / 缩放 / 淡入，跟随元素只做轻微错峰。效果是连贯有主次；边界是别让每个元素各自独立淡入上移。
- 可逆状态复用同一条时间轴，用反向播放从当前进度返回；连续变化的目标用可更新目标的动画而不是每次新建。做法是展开 / 收起、打开 / 关闭共用一条 timeline；效果是连续操作不闪烁、不跳帧；边界是只覆盖真正冲突的属性，不要清空整个目标的所有动画。
- 状态过渡优先「就地 morph」：形状、颜色、图标三者同步变化，不新增浮层。效果是不打断、不闪烁；边界是形状变化过程中文字不要跳变或换行。
- 主题级切换（日夜、章节、视图）做环境联动：背景色、图形、光照、图标一起渐变，保持同一个因果链。效果是沉浸且合理；边界是所有变化限定在产品画布内，模糊与变暗不能溢出界面边界。
- 反馈类动画短促且闭环：触发 → 过程 → 结果 → 复位，允许重复。效果是可演示；边界是不要无限循环，也不要在界面上出现「演示 / 示例」字样解释动画。
- 缓动用自然的加速减速，可带轻微过冲；线性只留给进度和匀速旋转。效果是有质感；边界是过冲幅度要小，不做夸张弹跳。
- 内容区加载用骨架占位，提交类用进度 + 结果态；两者不要同时出现在一个操作里。

### 3.13 其他：响应式、组件一致性、暗色模式

> 本节说明：管前面维度没覆盖但影响落地质量的三件事。

**特征**

- 组件一致性极强：同页同类卡片的圆角、内边距、描边、字阶、图标尺寸完全一致；Bento 网格里格子尺寸有变化，但内部规范统一。
- 深色与浅色是两套完整体系，不是简单反色：深色用近黑 + 明度阶梯 + 极弱描边，浅色用浅灰底 + 纯白卡 + 低透明阴影。
- 网页长页里同一套组件在不同章节复用，只换内容与排布；移动应用里同一套卡片在多个页面复用。

**设计思路**

- 先定义组件规范（圆角、间距、字阶、描边、状态），再铺页面；同类组件共用同一套变量。效果是整体统一；边界是允许主卡有合理的视觉差异，但差异只给一个组件。
- 深浅色各自定义一套完整的背景 / 内容面 / 文字 / 描边 / 强调色变量，切换时整体换变量而不是逐元素反色。效果是两套都完整；边界是别在浅色里直接复用深色的高饱和强调色。
- 1366×768 是标准参考值、不是硬基准，可按内容密度小范围浮动。在这个尺寸下布局必须健全：文字不重叠遮挡（有意设计的重叠 / 错位除外）、不出现无效换行导致的溢出、组件容器不小到让内部元素紧贴、组件之间不紧贴不重叠。这是「适配」最核心的含义，生成时就要做对。
- 视口变化按标准响应式：布局（容器 / 栅格 / 留白）随视口按比例伸缩；正文字号、图标、小图形保持固定档位，不跟着等比放大；只有大标题、首屏背景、大段落用 `clamp()` 给更缓的缩放曲线并设上下限。断点按内容何时开始挤来定。窄视口才重排为单列、把侧栏收进抽屉，别用横向滚动硬塞。
- 别把整页当图片等比放大（全站尺寸线性随视口涨或 `transform: scale()`）——放到很大会整体膨胀，不是常见的适配做法。App / 组件一般不做响应式，保持固定比例画布等比缩小。
- 键盘焦点态与减少动态效果的方案按 `SKILL.md` 第八节与第五节执行。

## 四、优秀设计手法示例

> 本节说明：一组「手法级」示例，每个拆解某个局部组件或某个设计决策具体怎么做、为什么成立、可复用要点是什么。借的是手法，不是页面；不提供整页复刻步骤。

### 示例 1 · 编辑式产品标题的「双层对照」

> 本节说明：展示如何用同一行标题制造层次，而不增加第二个主角。

- **具体做法**：产品页标题把主词排成超大号无衬线粗体，紧跟一个同号但极浅 / 描边的年份或序号（如 `/20`）；第二行用一个短破折号起头接产品名。整页只有这一处超大字，其余全是小号标签与细线。
- **为什么成立**：层次来自同一行内的字重与明度差，而不是多写一行说明；视线只落一次，副成分退成纹理。
- **可复用要点**：一个大标题里最多一个「轻」的对照成分；对照成分用明度或描边，不用第二个强调色。
- **边界**：描边巨字只适合低反差的粗体；高对比衬线的细笔画会被描边拆成平行线，改用低透明度填色。

### 示例 2 · 左文右图里的「细线信息组」

> 本节说明：展示密集规格信息如何在不卡片化的前提下保持整齐。

- **具体做法**：左侧文字块从上到下统一左缘：一段 2–3 行描述 → 一条 1px 发丝线 → 一行四个极小全大写字段标签（材质 / 产地 / 年份 / 系列）对应下方值 → 又一条细线 → 三个文字链 → 大号价格 → 数量控件与一个纯黑实心按钮。右侧产品图跨到中线，不带任何说明文字。
- **为什么成立**：分组靠线与间距，不靠边框；全页唯一重色块是那个黑色按钮，CTA 因此不需要额外装饰就足够醒目。
- **可复用要点**：字段标签统一「浅灰 + 全大写 + 宽字距」，值统一深色；细线两侧留出一致的上下间距。
- **边界**：字段不超过 4 个；中文标签不做全大写，改用字号与浅色。

### 示例 3 · 悬浮功能条跨越图文边界

> 本节说明：展示如何用一个功能组件同时制造层次和承载真实操作。

- **具体做法**：高端地产页用整幅黄昏别墅照作底，衬线大标题压在左侧天空留白处；一条白色大圆角搜索栏横跨在图片下缘，一半压在图上、一半压在下方深色统计条上；统计条内用竖向细线分列，图标 + 大数字 + 小标签。
- **为什么成立**：白条既是层次分界又是真实功能（多条件搜索），装饰与用途合一；深色统计条把整页「压住」，不至于头重脚轻。
- **可复用要点**：悬浮条要有明确功能；跨边界时上下两层都要有足够对比；统计项用竖细线而非卡片分隔。
- **边界**：悬浮条不能挡住主体；标题压图处必须有足够暗度或局部遮罩保证可读。

### 示例 4 · 一张主卡定重心的工作台

> 本节说明：展示高密度工作台如何避免「满屏都是重点」。

- **具体做法**：音频仪表盘顶部一张深色渐变主卡：大号无衬线标题三行，其中一行用浅蓝斜体弱化，一个白色胶囊 CTA，产品实拍（耳机）压在右侧并轻微出血。主卡下方是一圈纯白数据卡，圆角统一，每张只放一种数据（柱状、进度条、面积图、列表）。强调色只出现在小徽标与进度条。
- **为什么成立**：深色只出现一次，视线先落主卡再扫数据卡；白卡之间靠统一圆角与间距成组，不需要描边。
- **可复用要点**：主卡占横向 1/2 以上、其余卡等宽；斜体弱化副句而不是缩小成另一行说明；主卡内的产品图不加背板。
- **边界**：主卡与数据卡的明度差要足够；一屏只能有一张深色主卡。

### 示例 5 · 靠「大数字 + 小标签」消化数据密度

> 本节说明：展示金融 / 数据界面如何不用边框格子也能清晰。

- **具体做法**：余额用超大号表格数字，下一行才是小标签与涨跌徽标；图表区只在选中点显示一个悬浮明细卡；下方三列等宽卡各放一组「小标签 + 大数字 + 细进度条」。整页只有一个紫色强调色，涨跌另用红 / 绿语义色。
- **为什么成立**：数值本身成为视觉层级，标签退到次要位置；边框省掉后，密集信息靠留白和对齐消化。
- **可复用要点**：数字用表格数字并右对齐成列；涨跌色只在数值与状态点出现；悬浮明细卡只在交互时出现。
- **边界**：语义色不能扩散到容器底色；进度条与数值要用同一强调色系。

### 示例 6 · Bento 网格用「1px 弱描边」分层

> 本节说明：展示深色界面不使用阴影也能有层次。

- **具体做法**：暗色 3×4 网格，每格统一大圆角、1px 极低对比内描边、比背景亮一档的面；格子里是细线框、节点连线、极简线稿图标；中央一格放一个超大数字与一行短说明作焦点；紫色 / 蓝色光晕只出现在网格边角，面积很小。
- **为什么成立**：层次来自明度阶梯与线，不来自投影；统一描边让大小不一的格子读起来仍是一套组件。
- **可复用要点**：所有格子共用圆角、描边色、内边距；图形线宽与描边一致；焦点格只靠字号差区分。
- **边界**：光晕不能盖住任何文字；格子内容为空时宁可合并格子，也不要加悬空装饰。

### 示例 7 · 有机形裁切 + 大数字的小组件

> 本节说明：展示小组件如何在无卡片边框的情况下形成完整构图。

- **具体做法**：用非矩形的有机形（圆润水滴 / 拱形）裁切扁平几何插画（渐变天空、太阳、云、城市剪影）作上半部主视觉；下方是超大号轻字重数字，旁边小号辅助值；底部三列线性图标 + 数值指标；最底部一组极小分页点。
- **为什么成立**：不规则图形打破了卡片矩形感，但信息区仍严格左对齐；数字是第二重心，指标图标化后不抢戏。
- **可复用要点**：一个组件里「一个图形主视觉 + 一个大数字 + 一组等宽指标」；图标线宽统一；分页点极小。
- **边界**：裁切形不要压到文字区；渐变只在插画内，不做整卡背景。

### 示例 8 · 悬浮产品 + 极简 CTA 的商品详情

> 本节说明：展示移动端详情如何用摄影与留白替代装饰。

- **具体做法**：纯白背景，中央放去背产品瓶（无背板、无边框），带轻微柔和投影；上方一行小号品牌字，中部居中粗体品名 + 一行浅色副标题，两侧是极小的规格切换数字；底部一行价格、一个圆形「+」按钮、一个评分。另一屏用全幅人像 + 白色大字压图。
- **为什么成立**：产品是唯一彩色源，CTA 虽小但位置固定、形状唯一（整页唯一的圆），因此仍然醒目。
- **可复用要点**：去背产品图不加容器；圆形按钮只给主操作；规格切换用小号数字而非标签组。
- **边界**：字距与行距要足，纯白底上浅灰文字仍需保证可读。

### 示例 9 · 开关的「环境级联动」

> 本节说明：展示状态变化如何从控件级升级为场景级，但仍保持单一因果。

- **具体做法**：拨动开关时，旋钮滑动并带一个脱离的小粒子 / 回弹；同时整个背景从深夜星空（月亮、星点、暗蓝）交叉渐变到白天（太阳带光晕、云层前后遮挡、亮蓝），云在白天移到太阳前方形成遮挡关系。另一做法是旋钮上的图标从时钟渐变到对勾。
- **为什么成立**：所有变化都由「切换」这一个动作引起，元素虽多但因果单一；背景渐变让状态可感知，不需要文字说明。
- **可复用要点**：主控件形变 + 环境色 / 图形同步渐变；图标随状态 morph；加一个极小的次级粒子增强手感。
- **边界**：变化必须限制在组件 / 画布边界内；不要给每个元素各设不同时长，保持同一节奏。

### 示例 10 · 单元素闭环状态机

> 本节说明：展示不用弹层、不换 DOM 就能表达完整状态。

- **具体做法**：按钮从白色胶囊 → 收缩为圆形 → 显示转圈（加载）→ 变绿并放大铺满（成功）→ 收回圆形 → 复位；文件上传从虚线拖放框 → 文件名 + 细进度条 → 满色对勾 → 回到虚线框；订阅框输入 → 出现 OK → 文字就地替换为「THANKS! CHECK YOUR EMAIL.」。
- **为什么成立**：全程同一个元素做形状 / 颜色 / 图标的连续变化，用户视线不跳；闭环允许重复操作。
- **可复用要点**：一个容器承载 idle / loading / success / error / 复位；形状与颜色同步过渡；结果态短暂停留后自动复位。
- **边界**：文字替换要在同一位置、同一对齐，不能引起换行或布局跳动；不要插入解释性文案。

### 示例 11 · 极端留白的横向产品画廊

> 本节说明：展示「少」如何本身成为高级感。

- **具体做法**：整屏近白，一次只出现一到两个产品（鞋、家具），产品小、位置偏中；说明文字极小、贴在产品旁；侧边有竖排旋转的小标签作栏目名；切换时产品淡出淡入、编号变化，背景与版心完全不动。
- **为什么成立**：留白占比极高，产品是唯一焦点；不动的框架给连续切换提供了稳定感。
- **可复用要点**：框架固定、只换主体；一次只展示一到两个对象；文字小到退成注释。
- **边界**：产品图必须有足够质感与去背质量；留白区不要补装饰图形。

### 示例 12 · 底部抽屉承接「详情 → 操作」

> 本节说明：展示移动端如何在不离开当前页的情况下推进流程。

- **具体做法**：详情页保持全屏主视觉，点击主 CTA 后白色圆角抽屉从底部升起，覆盖下半屏，内含紧凑表单与一个实心主按钮；背景主视觉保留可见；关闭时抽屉落下回到原状态。
- **为什么成立**：空间关系清楚（从当前页「长」出来的操作层），上下文不丢失；可逆。
- **可复用要点**：抽屉用大圆角上两角、背景保持可见；主按钮只有一个；打开 / 关闭复用同一条时间轴可反向。
- **边界**：抽屉必须落在 App 画布内，遮罩与模糊不能溢出；窄屏下抽屉高度不超过画布大部分区域。

## 五、分场景设计范式

> 本节说明：把前面的维度落到具体页面类型上，写成「设计某类界面时应该怎么做」的范式。每节先说明不同容器的差异，再给通用做法，最后统一收敛。

### 5.1 首屏 / 落地页

> 本节说明：这是决定第一印象的场景，重点在重心唯一与信息克制。

- **通用范式**：一个超大标题 + 一个主视觉（产品图 / 全幅摄影 / 3D 渲染）+ 一行短副文 + 最多一个主 CTA；导航轻到几乎看不见；四周留白充足。
- **网页**：横向构图，标题与图分列或叠在图上；可加编号、细引线、悬浮功能条；允许长页分章。
- **移动应用**：首屏即功能，用一张主图或一个大数字 + 卡片流，不做营销大标题；底部标签栏固定。
- **桌面软件**：首屏即工作台，一张主卡 + 一组数据卡 + 侧栏 / 顶栏，没有欢迎层。
- **收敛**：三类都只保留一个主角，其余元素退到小字号 / 浅色 / 中性色；差异只在「主角的形态与页面容器」，不在配色与装饰规则。

### 5.2 导航

> 本节说明：导航要提供秩序而不制造视觉重量。

- **通用范式**：单一主导航、分组清晰、选中态唯一且用填充表达、图标统一线性、hover 只有微反馈。
- **网页**：顶部细横条，小 logo + 少量小字链接 + 一个实心按钮；滚动时可转半透明毛玻璃。
- **移动应用**：底部 3–5 项标签栏，选中换实心图标 / 强调色；顶部只放返回、标题、单个操作。
- **桌面软件**：左侧竖栏分组 + 选中胶囊；顶栏只承担全局操作（搜索、账户、视图切换）。
- **收敛**：形态按容器选，但「分组用小标题 + 留白」「选中唯一」「一套图标」三条不变。

### 5.3 列表 / 数据浏览

> 本节说明：列表最容易出现「满屏卡片 + 每卡都描边加阴影」的问题，这里给替代做法。

- **通用范式**：优先用间距与发丝线分组，卡片只在一组内容需要整体抬起时使用；行内按「主信息 + 浅色元信息 + 右对齐数值」三段组织；图标小且线性。
- **网页**：可编辑式错落（大小图混排、编号），不必等宽栅格铺满。
- **移动应用**：单列等宽卡片、大圆角、卡内留白充足；卡与卡之间只留间隙，不加阴影。
- **桌面软件**：多列卡片 / Bento 网格，格子尺寸可变但内部规范统一；数值右对齐成列。
- **收敛**：无论形态，都靠「统一内边距 + 统一圆角 + 小标签 / 大值的对照」建立秩序，不靠逐卡描边。

### 5.4 详情 / 内容页

> 本节说明：详情页要让主体尽可能大，同时把辅助信息收得干净。

- **通用范式**：主视觉占最大面积且不加容器；标题与主体形成字阶对比；规格 / 参数拆成「小标签 + 值」；主操作只有一个且形状唯一。
- **网页**：左文右图或全幅图叠字；可用细线信息组、编号、上一项 / 下一项导航。
- **移动应用**：去背产品悬浮 + 居中品名 + 圆形主按钮；底部固定操作行。
- **桌面软件**：详情多为面板 / 抽屉，主区不被打断，辅助信息放右侧或折叠区。
- **收敛**：主体是唯一彩色源与唯一重心；文字层级靠字号与明度，不用彩色标签堆。

### 5.5 表单 / 输入

> 本节说明：表单的重点是状态清楚、反馈就地，不做装饰性包装。

- **通用范式**：标签小且浅、输入框统一圆角与内边距、聚焦态用边框色变化而不加外发光；一个表单只有一个主提交按钮。
- **状态齐全**：默认 / 聚焦 / 输入 / 校验失败 / 提交中 / 成功，每个状态都在同一元素上表达；密码显隐用图标开合 + 底色反转；提交结果就地替换文字或按钮形态。
- **网页**：可多列排布字段，但左缘对齐；**移动应用**：严格单列，输入框宽度撑满内容区；**桌面软件**：字段密度高，用分组间距而非边框切分。
- **收敛**：反馈就地、闭环、可重复；不弹模态解释状态，不在界面上写说明性文案。

### 5.6 空状态 / 加载 / 反馈

> 本节说明：这些「非主流程」页面最容易被漏掉，也最影响完成度。

- **空状态**：一句真实业务语境的现状说明 + 一个下一步动作；控件可用虚线拖放框；不用大插画、不用教学标注。
- **加载**：内容区用骨架占位（形状与真实内容一致），局部动作用细进度条 / 转圈；不用整屏遮罩。
- **反馈**：小圆角 Toast + 一个状态图标 + 一行文字；成功 / 失败用语义色但面积很小；短暂停留后自动复位。
- **收敛**：三者都遵循「就地、轻量、不打断」；状态变化连续可逆，不新增说明层。

### 5.7 弹层 / 抽屉

> 本节说明：浮层既要清楚表达层级，又必须严格留在产品画布内。

- **通用范式**：内容多时用横向对话框（16:9 / 4:3 取向），单一长列表才用纵向；头部与底部固定、只让内容区滚动；遮罩变暗 + 模糊的作用范围严格等于画布。
- **桌面软件 / 移动应用**：一律挂在画布容器内（`position: absolute`），不用 `fixed`，不用视口单位定尺寸。
- **网页**：可以用浏览器视口作画布，但遮罩仍不应溢出到页面之外。
- **收敛**：浮层用「明度差 + 低透明大扩散阴影」表达层级，圆角与页面组件同体系；打开 / 关闭复用同一条可逆时间轴。

## 六、设计禁忌与边界

> 本节说明：把前面反复出现的「不要」集中成一份可核对的清单，并说明本文件管到哪里为止。

### 6.1 明确禁止

> 本节说明：这些做法会直接破坏本风格，看到就改。

- 满屏卡片化，卡片里再套卡片；每个卡片都描边 + 阴影。
- 一屏出现两个以上等重主角，或两个并列主 CTA。
- 用大面积渐变、发光、玻璃态、随机几何碎片充当「高级感」。
- 多个强调色同时铺开，或给每个列表项配不同底色 / 彩色标签。
- 纯黑背景配高饱和彩色光晕（廉价科幻感的主要来源）。
- 所有文字大小相近，只靠颜色变化制造层级。
- 混用多套图标库、图标线宽不一、用 emoji 当功能图标。
- 界面里出现「演示 / 原型 / 模拟 / 示例 / Mock / 占位」字样，或教学标注、序号箭头、说明气泡。
- 模糊、遮罩、变暗、阴影溢出产品画布边界（软件 / App / 组件尤其严格）。
- 动画全部线性、统一淡入上移，或每个元素各自独立表演。
- 装饰性图形悬空在内容中段；留白区用装饰补空。

### 6.2 容易过量的手法与上限

> 本节说明：这些手法本身没错，错在用量。给出可核对的上限。

| 手法 | 建议上限 |
| --- | --- |
| 强调色 | 一屏一个；有语义必要时才加第二、三个 |
| 字体 | 最多两套家族；字号层级 4–5 级 |
| 装饰手法 | 一屏 1–2 种（描边 / 阴影 / 渐变 / 玻璃不同时上） |
| 毛玻璃 | 只给顶栏、浮层、通知卡 |
| 阴影 | 只给浮层、悬浮卡、hover 抬起 |
| 渐变 | 只给主视觉、插画或单个按钮 |
| 编辑式点缀 | 一屏一组（编号 / 引线 / 热点） |
| 动效主角 | 一次一个，跟随元素轻微错峰 |
| 点缀图形 | 只在边缘、角落或主体背后 |

### 6.3 不建议沿用的做法

> 本节说明：列出几类与本风格目标相冲突的常见做法，说明原因，避免被当成「风格选项」误用。

- **新拟态（Neumorphism）**：双向柔和阴影、与背景同色的凸起感有一定辨识度，但对比度低、状态难表达，不建议作为默认手法。
- **旧一代工具皮肤**：高密度小图标、强描边、金属质感，可参考其信息组织，不参考其装饰。
- **单控件练习式构图**：为突出一个控件而把整页做成舞台布景，适合练习稿，不适合正式产品界面。
- **作品集展示包装**：斜排样机、多屏拼贴、彩色展示背景、大投影是给作品拍照用的，不是界面元素，生成原型时不要复现。

### 6.4 与 SKILL.md 的关系

> 本节说明：说明本文件的定位，避免两份文档相互覆盖。

风格判断看本文件，能不能做、必须怎么做看 `SKILL.md`。任何冲突以 `SKILL.md` 为准。特别地：

- 配色选型以 `SKILL.md` 4.5 为准（雾绿 / 青绿 / 雾蓝放到最后考虑）。
- 字体下限、assets 目录、原生控件、边框裁剪、画布约束等硬规则以 `SKILL.md` 为准。
- 界面文案与「正式感」要求以 `SKILL.md` 4.3 / 第七节为准。

> 本节说明：明确哪些问题由其它文档或项目实际约束决定，避免把本风格文档当成万能规范。

## 七、回归检查清单

> 本节说明：设计完成后再次通读本文档与 `UI设计原则.md` 时，用这份清单逐项核对风格与审美；检查阶段可以先看章节标题与解释文字，拿不准再回到对应维度细读。可机检的技术合规项（画布边界、原生控件、边框、以图还原比例、适配基准等）不在这里，统一按 `SKILL.md`「〇.1 硬约束清单」逐条举证，避免两套清单互相稀释。

1. **重心**：每屏是否只有一个主角？有没有第二个等重标题 / CTA / 大图？
2. **层级**：层级是否主要靠字号差与留白建立，而不是靠卡片、边框、颜色？
3. **留白**：主体周围是否有一条明显空白带？留白区有没有被装饰补空？
4. **配色**：中性色是否占绝大多数面积？强调色是否一屏一个？有没有误用雾绿 / 青绿 / 雾蓝当默认？
5. **字体**：是否按品类选了合适字体？字阶是否只有 4–5 级？数字是否表格对齐？小标签有没有误用中文全大写？
6. **间距 / 对齐**：同类组件内边距是否一致？文字块是否共用基线？数值列是否右对齐？
7. **装饰**：一屏是否只用了 1–2 种装饰？有没有每卡描边加阴影？毛玻璃 / 阴影有没有溢出画布？
8. **首屏**：是否符合所选容器的范式？导航有没有抢主视觉？CTA 是否只有一个？
9. **导航**：形态是否匹配容器？分组是否用小标题 + 留白？选中态是否唯一且用填充？图标是否一套线宽？
10. **状态**：空 / 加载 / 失败 / 成功 / 禁用是否齐备？反馈是否就地、闭环、可逆？
11. **动效**：是否非匀速、单焦点、可逆？连续操作会不会跳帧或跳回起点？有没有无限循环装饰动画？
12. **文案**：通读全部文字，有没有演示 / 示例 / 占位 / 教学标注？是否都像真实业务内容？
13. **一致性**：圆角、间距、字阶、描边、图标尺寸是否全页统一？
14. **边界**：对话框、抽屉、下拉、Toast、遮罩、模糊是否全部落在产品画布内？
15. **禁忌**：对照 6.1 逐条扫一遍；对照 6.2 检查用量有没有超上限。
16. **规范**：是否与 `SKILL.md` 的硬规则冲突？冲突处是否已按 `SKILL.md` 修正？
17. **风格定位**：整体读起来是不是本文件描述的那一套？有没有为了丰富而把重心、留白或克制用色让出去？
