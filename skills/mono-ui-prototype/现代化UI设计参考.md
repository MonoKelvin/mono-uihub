# 现代化 UI 设计参考：风格、构图、组件与实践

> 本文从专业设计师的图片与动态 UI 参考中提炼可迁移的设计关系，用于指导 Agent 和大模型生成高级、简约、美观且可用的界面。学习的是内容取舍、视觉性格与组织方法，不是复制某一张图的皮肤。
>
> 设计前完整通读本文与 `UI设计原则.md`，完成后再次阅读并执行第七节回归。技术合规的唯一判定依据仍是 `SKILL.md`「〇.1 硬约束清单」17 条；本文负责审美与设计判断，不增设另一套技术硬约束。冲突处理遵循 `CLAUDE.md` 与该清单。

## 一、设计目标与使用方法

### 1.1 高级简约的本质：少量选择，形成强关系

**用必要的内容、清楚的主次、有性格的构图和一致的细节，让界面既容易使用，又能被辨认。**

高级感不是白底、浅灰小字、大圆角、细线或某种流行字体的总和。深色创作工具、鲜明的潮流网站、温暖的生活方式页面、紧凑的金融工作台、触感细腻的单一控件，都可以达到这一目标。它们共同的特点是：

- 重要对象得到与任务相称的空间，第一阅读落点明确。
- 信息有归属，重复内容有节奏，辅助信息不制造第二个竞争中心。
- 字体、影像、色温、表面、图标和动作表达相容的性格。
- 不需要的内容真的被删除，需要的能力在恰当的阶段出现。
- 默认、选中、展开、加载、失败等状态像同一个产品，不只首屏漂亮。
- 每种视觉效果都能解释它帮助了什么，而不是只说「增加高级感」。

简约不是元素越少越好，而是**理解与操作所需的负担越少越好**。一张信息密集但能快速比较的交易表，比只有几个巨型数字、却找不到明细的概览更简约。一个工具丰富但工作对象清楚的编辑器，也比把所有功能缩成不可辨图标的空画布更成熟。

### 1.2 学习单位：关系，而不是孤立效果

不要摘取「好看的按钮」「漂亮的渐变」「很大的标题」后拼成一页。先理解它们与其他内容的关系。

| 观察维度 | 要提炼的关系 | 不应变成的固定规则 |
| --- | --- | --- |
| 主次 | 谁先被看到，哪些对象共同成为主体，辅助区如何退后 | 每页只能有一张主卡或一个深色块 |
| 构图 | 图与字怎样共享空间、互相平衡，观看顺序如何推进 | 所有首屏左文右图或必须非对称 |
| 留白 | 哪些空隙保护主体，哪些距离说明分组 | 全页统一大间距，内容越少越高级 |
| 字体 | 字形怎样表达品牌，正文与数据怎样保持易读 | 所有标题都用衬线或所有标签都用等宽体 |
| 颜色 | 品牌、内容、状态、数据、表面分别由什么颜色承担 | 所有页面只能一种强调色或某色相禁用 |
| 容器 | 哪些对象需要边界，哪些信息可以直接排版 | 一律去卡片或一律套圆角卡片 |
| 动效 | 什么操作导致变化，哪些元素连续跟随，终态是什么 | 所有控件形变或所有区块淡入上移 |

「一个主角」指清楚的视觉或操作主线，不是只允许一个物体。一组商品、标题与建筑的组合、同一任务下的多项读数，都可以成为一个整体。

### 1.3 使用顺序：先完整理解，再按任务应用

1. **界定任务**：产品是什么、谁在使用、这一屏帮助什么判断或动作。
2. **分配内容**：当前必需的直接呈现，相关但低频的进入下一步，重复或无关的删除。
3. **选择视觉方向**：从第二节选适合的关系，结合当前品牌与素材重新推导，不机械认领风格名称。
4. **安排空间**：依据第三节组织对象、信息、导航与操作，先不靠装饰补版面。
5. **解决具体问题**：第五节的案例可直接用于构思，但不是整页模板；只借当前任务需要的做法。
6. **精修与回归**：用第四节识别组合错误，再按第七节检查实际画面和状态。

用户当次的文字要求与具体参考优先。用户给图要求还原时，要实际查看画面，并执行技能的还原规则；只借鉴风格时，不自动把任务改成逐像素复刻。

本文的案例是自包含的设计描述，不要求后续设计者打开某个旧项目才能理解。需要核对未讲清的关系时，可以按需研究相关资源；不能用项目名、截图链接或「参考某页面」替代正文中的设计解释。

### 1.4 动手前的方向说明要能指导取舍

用简短说明回答以下问题，不必另建规划文档：

- 当前最重要的对象是什么？用户看到后要做什么？
- 记忆点来自字形、实物、影像、图形还是数据关系？
- 哪个区域需要宽松，哪个区域应该紧凑？
- 哪些信息成组，哪些需要独立容器，哪些进入详情？
- 字体、色彩、素材与控件各承担什么职责？
- 不准备添加哪些常见模块或效果？为什么？
- 哪些状态与转场必须连贯，哪些变化可以直接完成？

可执行的说明是「商品系列直接形成展陈，名称和价格跟随各自图片，尺码进入详情」，不是「采用高级极简风，搭配大圆角与高级色」。颜色、字体与尺寸变量随后由这些决定推导，而不是先选一套参数再填内容。

### 1.5 研究范围与证据边界

本次研究覆盖 Eagle 的四个目标文件夹：

| 文件夹 | 文件夹内资源数 |
| --- | ---: |
| Application 软件 | 56 |
| Web 网页 | 49 |
| App 手机App | 42 |
| Widget 控件 | 67 |

文件夹归属共 214 项，按资源 ID 去重为 **213 项**：188 项静态资源、25 项动态资源，动态中包括 5 个 MP4 与 20 个 GIF。全部静态资源进行了保比例构图缩览查看，全部动态资源查看了覆盖主要时段的关键帧序列；另对长页、App 画板和密集组件进行了分段放大核验。

这些研究支持风格、尺度、分组、色彩、组件形态与可见状态变化的提炼，但不等于每张原件逐字核对或每段视频逐帧审查。具体字体名称、像素值、交互触发方式、缓动曲线、弹簧参数和生产可用性，不能仅由画面确定。本文中的流程、可访问性与实施建议是设计推导，不冒充原作品已验证的功能。

研究中还需分清三层：**产品界面、作品展示包装、讲解标注**。外部渐变舞台、斜放样机、多屏拼贴、注释箭头、镜头推进和循环复位，不自动属于产品的默认界面。原作中可见的低对比文字、跨题材文案、旧平台名称或重复数据，也不因整体精美就成为推荐标准。

## 二、视觉方向：不同风格怎样形成高级感

本节是可探索的风格家族，不是互斥分类，也不代表每类出现频率。一个产品可以组合相邻的关系，例如「安静的工具框架 + 有色的对象缩略图」，但应有主导语言，不能把所有醒目的特色同时叠上去。

每个方向都要同时看构图、字体、颜色、影像和控件；只改背景色不能建立风格。

### 2.1 安静、精确的功能型界面

**气质**：可信、清楚、轻负担；主要魅力来自信息组织和细节准确，而非装饰。

- **空间**：工作区、列表、概览和操作区有明确分工。关键读数可以放大，但不会所有指标都占一张同样大的卡。重复记录连续排布，列关系稳定。
- **字体**：正文与工具标签易读，标题只比正文明确高一级或数级，不需要海报式巨字。金额、日期和时长对齐，单位有稳定位置。
- **颜色**：基底安静，操作与状态有清楚职责；内容可以有自己的颜色。浅色不是把所有文字减成淡灰，深色也不是把所有信息染白。
- **容器**：独立账户、设备、可选对象可以有边界；同一对象的字段、交易和费用优先直接排版。轻分隔与间距常已足够。
- **细节**：搜索、筛选、行菜单和选中态都服从同一控件语法，边界不因悬停突然变厚、内容不跳动。

**适合**：金融、管理、记录、专业信息检索等以判断和效率为主的任务。

**容易失手**：误把安静做成匿名的浅灰卡片墙；删除单位、名称与入口以制造留白；每张卡再加图标、趋势和一句泛泛洞察。

### 2.2 深色、聚焦工作对象的工具界面

**气质**：沉浸、专业、集中；深色框架把注意力留给模型、媒体、画布或仪表。

- **空间**：工作对象获得连续的大区域，图层、素材、时间轴、属性检查器围绕它各司其职。中间留白是工作空间，不是待填充的空白。
- **层次**：用相邻表面的明度差、局部分隔和清楚标题区分区域，不靠每个面板发光。浮动工具可有更高的表面层级，但不能遮住正在编辑的关键部分。
- **字体**：工具文字紧凑而清楚，数据与参数稳定；特色展示字最多用于字标或少量对象名称，不侵入密集字段。
- **颜色**：模型、材质、封面和选区提供内容色；强调色指向当前工具、关键操作或选择。危险与警告保持独立语义。
- **交互**：选中对象后属性区对应更新，上下文操作就近出现；切换工具不需要整页入场动画。

**适合**：编辑、建模、音视频、设备调节和需要持续观察对象的工作流。

**容易失手**：把「科技」翻译成蓝紫光晕、点阵、发光按钮和永久旋转球；把工作对象关进小卡，上方却放欢迎横幅与使用统计。

### 2.3 有色对象与模块化概览

**气质**：丰富但有秩序，颜色帮助识别不同对象、状态或任务。

- **空间**：模块大小由用途决定。趋势需要宽度，直接控制需要手指与读数空间，照片需要构图，状态确认可以紧凑；不是先凑一套大小不等的 Bento 再找内容。
- **颜色**：有色设备、作物、账户或类别形成重复体系；相同类别沿用相同规则。色块可以较多，但模块内部文字、控件和图表不再各配一套竞争色。
- **字体**：对象名有辨识度，辅助读数有清楚秩序；各模块共享标题基线、数字语法和边距逻辑。
- **容器**：每块是完整对象或独立判断范围。颜色、轮廓和间距共同说明归属，不需要模块内部继续层层套卡。
- **状态**：多个对象同时处于开启或异常状态时，可以同时得到相应表现，不为了「只有一个主卡」篡改状态逻辑。

**适合**：设备概览、健康训练、生产对象管理、专题数据和有明确对象集合的首页。

**容易失手**：随机把卡片染成不同颜色；为填满网格增加天气、用户数、助手、推荐和重复指标；把所有内容拉成同一种卡片高度。

### 2.4 内容丰富、框架退后的媒体界面

**气质**：由作品、人物、赛事、封面和现场影像建立氛围，软件框架保持可预测。

- **空间**：焦点内容可以较大，专辑或文章按图文浏览，曲目、直播和动态采用紧凑行，播放控制集中。不同内容不必同形，但都能看懂所属区域。
- **色彩**：多彩内容不等于多色 UI。封面和队徽可以鲜明，导航、分隔和次操作收住；深浅基底根据内容与品牌选择。
- **字体**：内容标题有辨识度，作者、类别和时长次之；框架标签不与内容争抢展示字。
- **图像**：封面保持完整艺术方向，人物和赛事照片有题材关系；选中反馈不能只是把所有图片统一覆盖一层强色。
- **控制**：一个正在播放的对象对应一套连续的进度与控制，列表内的状态能与播放器互相确认。

**适合**：音乐、视频、游戏赛事、内容社区、图片与作品浏览。

**容易失手**：在内容之前先放巨大口号、听歌 KPI 或通用宣传卡；给每行配置同样醒目的按钮组；为了去 AI 味把品牌能量磨成中性后台。

### 2.5 温暖、材质同源的编辑式界面

**气质**：从实物、人物、空间与文字的关系建立细腻感，不以「奶油底 + 衬线」作为万能答案。

- **构图**：照片与文字有明确面积差，可以采用大图、小注释、窄信息列、错位双图或连续展陈。观看顺序不是平均分配四块卡片。
- **字体**：展示字可有衬线、细节对比或舒展比例，正文与操作使用清楚的阅读字体。大标题与小注释之间仍要有可读的中间层级。
- **颜色**：肤色、金属、木材、织物、纸面和背景共享合适色温；深区与浅区是章节关系，不逐模块随机换温度。
- **影像**：佩戴或使用场景负责气氛与尺度，局部产品图负责识别和质感。两者不能拿同一张图反复替代。
- **表面**：较少但准确的边界，阴影轻或不用；材质来自内容，不靠在全页加纸纹、噪点、印章和装饰外语。

**适合**：珠宝、家居、服饰、空间、文化和生活方式展示。

**容易失手**：只选一张色调温暖的照片就当作主题成立；所有产品都套同样的陶土色和艺术衬线；关键操作过淡，长正文也使用展示体。

### 2.6 大字体、强节奏的海报式表达

**气质**：有能量、直接、容易记住；文字本身成为构图中的形与面积。

- **构图**：标题可跨越较宽区域，与人物、建筑、几何或实物形成层叠；有计划的遮挡、断行、错位和边缘裁切形成张力。名称与核心语义仍须辨认。
- **字体**：窄体、宽体、厚重 Grotesk 或其他展示字的字宽、字重、行高要与主素材配合，不是简单把正文放大。段落与操作退回易读字阶。
- **颜色**：黑白、高对比双色或鲜明品牌底都可以成立。强色与粗字已足够有力，周边不需要再堆渐变、星点、描边字和徽章。
- **节奏**：密集的大字或实物区后可以留出停顿；后续章节换观看任务，而不只是重复同款封面。
- **导航**：短而明确，入口位置可探索，但不能让用户猜哪个文字能点。

**适合**：时尚、活动、文化、产品发布和品牌概念展示。

**容易失手**：把每节都做巨字；遮住商品名称、正文和操作；以随机倾斜代替构图；把英文紧行高与字距原样搬到中文。

### 2.7 实物主导的整幅产品舞台

**气质**：产品本身承担冲击力，页面像有目的的展陈，而不是产品缩略图旁的一套营销模板。

- **构图**：先定实物机位、姿态、尺度和朝向，再安排型号、标题、价格与操作。整车侧视、低机位物体、去背家具或建筑都可能成为主体，不要求一律去背。
- **空间**：实物可以占据主要区域，标题与它共处；辅助参数沿稳定边缘收拢。不是把产品放大后继续保留完整的三卡卖点区。
- **颜色与光**：背景与实物材质相容，局部对比托住轮廓；投影说明落地或悬浮，不给物体外围额外套一圈厚背板。
- **后续**：总貌、局部、使用场景、结构细节与系列浏览承担不同任务；大图变化要提供新的观看价值。
- **购买路径**：型号和购买入口清楚，决定购买所需的规格与费用在合适阶段完整出现。

**适合**：出行、家具、硬件、建筑、工业产品与高质感单品。

**容易失手**：素材弱却用光球与轨道补气势；重复同一视角假装产品细节；把所有页面都变成无参数、无价格的纯情绪海报。

### 2.8 图形、插画与轻触感的亲和界面

**气质**：亲切、有趣、可识别；简化的场景、人物或对象直接表达主题与状态。

- **构图**：一个天气场景、活动图形或任务对象可以成为主视觉；读数、标题和动作围绕它成组，而不是每个小区域都配插画。
- **图形**：轮廓、透视、线条、阴影和色彩属于同一套语言。轻立体对象与扁平工具图标可以分工，但不能把多种渲染风格混成素材拼盘。
- **字体**：可以柔和或圆润，但操作与数字仍清楚；亲和不等于所有文字都粗大、所有控件都巨大胶囊。
- **颜色**：场景色与界面色呼应，状态有文字或形态补充。图形已经丰富时，容器减少额外装饰。
- **动效**：按对象语义变化，例如选择位置、进度、场景亮度；趣味动作只在适合的频率和场景使用。

**适合**：天气、轻量个人工具、活动、教育与具有亲和品牌语言的应用。

**容易失手**：把普通功能图标放大当专业插画；每张卡都放 3D 小球；为了可爱让关键信息和操作变小。

### 2.9 触感、拟物与软浮雕控件

**气质**：像能被按下、拨动或旋转的实体，细节集中在局部对象的手感。

- **形态**：槽体、滑块、旋钮、按钮有统一光源，外凸、内凹和按下的关系可读；材质不是几组彼此矛盾的阴影。
- **状态**：高光或阴影的变化只是辅助，开关位置、符号、读数和选中关系仍清楚。不能只靠浅底上的浅阴影告诉用户是否可点。
- **尺度**：材质细节在目标尺寸仍成立。按钮轮廓细腻不等于点击区域细小；小图标不应因低对比融入背景。
- **范围**：可用于音乐、计时、灯光、设备和单组件；大面积业务表单与长列表不应为了统一而全部雕成浮雕块。
- **克制**：表现最值得感知的部位，其余信息保持直接排版。

**适合**：设备控制、模拟器、单一交互组件及明确要求物理触感的产品。

**容易失手**：把软浮雕当所有 App 的默认高级皮肤；影子比文字更明显；按下态像禁用；展示循环使已选择状态自动复位。

### 2.10 透明、玻璃与空间分层

**气质**：轻、悬浮、有空间连续性；透叠让用户仍感知后方对象。

- **空间**：工具条、局部面板或覆盖层浮在内容之上，透明用于说明覆盖关系，不是每个模块都变半透明。
- **表面**：适量底色、模糊、边缘高光和投影协同；后方越复杂，文字所需的稳定底面越重要。
- **颜色**：背景颜色可以影响表面氛围，但不能改变正文可读性与状态识别。不要依赖不可预测的背景混色作为对比保障。
- **构图**：先让前后层的面积与位置成立，再细化材质。玻璃不能救一个已经拥挤或没有主次的面板堆。
- **动效**：浮层从相关位置出现、回到合理位置；大面积模糊与实时跟随要考虑成本。

**适合**：内容上方的工具、空间型产品、明确要求透明材质的设备或品牌界面。

**容易失手**：把所有文本都放在玻璃上；亮背景里白字失读；同时叠光晕、彩边、噪点和多重阴影；借毛玻璃隐藏结构问题。

### 2.11 组合风格时保持一套主导语言

组合的是职责，不是特色清单。可以让安静框架承载鲜明内容，可以让产品舞台使用海报字体，也可以让轻量工具采用少量触感控件。判断组合是否成立，检查：

- 标题、正文和工具文字是否有清楚角色，而非多套字体争夺性格。
- 摄影、立体对象与图标是否各有职责，且色温与空间关系相容。
- 主区域大胆时，辅助区域是否真正降低竞争。
- 同类控件是否仍遵循相同形态与状态规则。
- 去掉某种效果后若不损害识别、构图或状态，是否可以不使用它。

风格选择最终要能由当前产品解释。不是先决定「我要做一个玻璃 Bento」，再把产品内容塞进去。

## 三、设计规范：从空间到组件建立一致关系

### 3.1 信息架构：先分阶段，再做减法

把内容分成三类：

- **当前必需**：对象名称、关键读数、价格或单位、必要风险、当前选择、判断依据与主要动作。
- **相关但低频**：完整历史、详细规格、高级设置、更多筛选、帮助说明，进入可发现的次级视图或上下文面板。
- **重复或无关**：解释标题的段落、无依据背书、装饰性统计、与产品无关的天气和推荐，直接删除。

完整度检查整个流程，简洁度检查当前这一屏。浏览、判断、填写、核算、确认可以是连续阶段，不必同时常驻首页。核心能力做成真实视图，不能用一段 Toast 或一批相似对话框替代。

少文案不等于少信息。名称、值和状态可以直接表达对象；陌生规则、费用、错误原因、风险和表单标签不能为了清爽被删。

### 3.2 视觉层级：先减少竞争，再强化主体

先确定第一落点，再确定第二步要看什么。层级来自面积、位置、字形、明暗、密度、方向和间距的组合，不只来自字号。

- 主体可以大，但不要同时把背景装饰、导航、徽标、图表、按钮全部拉到高对比。
- 辅助区退后不等于不可读。用较轻字重、较少底色或较紧凑面积降权，比继续缩小文字可靠。
- 主动作的权重与当前阶段一致；多个同类对象可以各有直接操作，不能机械删成全页唯一按钮。
- 内容组先在内部建立归属，再与周围拉开距离。视觉上像一组的东西，应属于同一对象或任务。
- 深色面积、鲜明颜色与大字都很有重量；增加其中之一时，检查其他部分是否需要收住。

如果页面看起来处处有重点，优先减弱竞争区域，而不是给主角再加描边、发光与动画。

### 3.3 四类容器：不同任务需要不同空间

容器分类决定展示与边界，不规定某种风格。比例、滚动、浮层定位和单位策略按 `SKILL.md` 执行；以下只解释设计关系。

#### 软件：把持续工作放在中心

- 创作工具围绕当前对象安排列表、画布、时间轴与属性区；业务软件围绕查询、比较、编辑与处理安排列表和详情。
- 导航是到达工具，不是视觉主角。顶部操作区不能因头像、搜索、通知、主题按钮堆叠而挤占工作区域。
- 专业密度可以紧凑，但要有稳定行高、字段对齐与分组间距；不把桌面软件做成一组巨大的手机卡片。
- 列表与详情可并置，工具面板可以复用；同一属性不在多个位置重复控制。
- 有意义的空画布保留操作空间；没有工作意义的空档，不用欢迎横幅填满。

#### 网页：组织观看与阅读的纵向节奏

- 首屏先出现最能代表主题的内容，可以是实物、标题、影像、图形或交互，不默认「小标签 + 口号 + 三卖点 + 右侧图」。
- 每个章节回答一个新的问题：识别产品、理解细节、观察使用、比较系列、采取行动。段落变化应来自观看任务，不是随机换背景。
- 大图、小图、连续商品行、短正文与较密的信息组交替，既有停顿也有推进。
- 版心、标题边缘与图像边缘保持跨章节呼应；错位也要能找到秩序。
- 网页自然文档流与滚动叙事分开考虑，不因一张参考是固定尺寸就把整个网站压成一屏。

#### App：按阶段与触控建立短路径

- 浏览先认对象，详情先支持判断，订单先支持核算；同一品牌语言贯穿，而信息权重随阶段变化。
- 顶部表达位置与返回，底部承载常用导航或当前主动作；不让两组底部控制竞争同一空间。
- 横向浏览、双列对象、成组规格都可以使用，但可点区域、字长与手指空间必须在真实尺寸成立。
- 地图或照片可以占主区，信息面贴近相关对象；不是在影像上叠满所有字段。
- 多屏画板用于理解流程，交付产品时按任务形成可切换视图，不把多部可操作手机拼成默认界面。

#### Widget：把一个对象做精，不扩展产品范围

- 播放器、上传框、开关、工具条、侧栏或日期选择器按自身用途成形，不添加欢迎区、统计、账户与无关业务模块。
- 默认、悬停、聚焦、展开、选择、处理和终态共享同一对象身份。
- 控件变形时保留可识别的锚点，例如图标、标题、主要按钮或共同边缘。
- 侧栏演示只需必要的选中与折叠反馈，不因此扩展消息阅读、回复草稿或账户设置。
- 展示包装可以帮助看清组件，但产品内部不出现讲解箭头、编号与演示文案。

### 3.4 栅格、对齐与有秩序的非对称

先确定少量共同的对齐线，再安排变化。栅格是隐形骨架，不需要让每个对象都被可见边框圈起来。

- 标题、正文、图像、列表与按钮尽可能共享明确的左边缘或基线。
- 同级对象重复时，统一图像舞台、名称位置与元信息列；不要靠不同 padding 补每个条目。
- 数字列、时间列和短状态列保持稳定位置，方便纵向比较。
- 非对称通过面积差、留白差与对象方向建立平衡，不是每块任意移动。
- 错位可发生在章节之间或图文之间，但每个局部组内部仍应准确。
- 光学对齐允许小幅修正：圆形图标、去背实物和字形黑色面积不一定等于几何盒子中心。修正要按同类逻辑，而非随机偏移。

**案例式关系**：一张竖向佩戴照片占较大区域，相邻窄列放类别与短介绍；下一张局部产品图向下错开，但说明仍与自己的图像边缘对齐。变化发生在两组之间，不让每一行文字都游离。

### 3.5 留白与密度：空隙要说明关系

留白有四种常见职责：保护主体、区分组别、给操作留空间、形成章节停顿。没有这些职责的大空档不自动高级。

- 标签与值、图像与名称、字段与帮助信息距离较近；不同对象组之间更宽。
- 密集行保持稳定节奏；宽松主视觉与紧凑列表可以共存，不必全页统一松散。
- 内边距与内容量相称，不能单行读数住在巨型卡里，完整表单却挤在窄角落。
- 将同一对象的信息合并，通常比缩小字号更能降低拥挤。
- 栅格中空着的空间可以是刻意平衡，不为填满新增模块；但要确认不是遗漏必需内容。

间距可以用少量档位建立变量系统，重点是**组内、组间、区域之间的相对差异**。实际取值由文字、控件、容器和密度决定，不把一张图测出的数值当通用标准。

### 3.6 字体与排版：字形是构图，不只是样式

#### 字体角色

- **展示文字**：用于字标、短标题或主要数字，承担性格与视觉面积。窄体、宽体、衬线、几何或书写体应由主题决定。
- **阅读文字**：用于正文、表单与操作，承担清楚、稳定和持续阅读。
- **比较数据**：用于金额、时间、参数与列读数，承担对齐与快速扫描。

一套字体也能完成不同角色，两套字体则应有明确分工。不要给每个区域分配一款字体；也不要用等宽字体自动给普通标签增加「专业感」。

#### 字阶与字重

- 先安排角色，再定字号。页面标题、组标题、对象名、正文、元信息有可感知差异，但不必每级固定倍率。
- 层级不够时，检查字重、位置、行距与背景竞争，不只继续放大标题。
- 辅助文字不能像禁用态；正文与操作的最低要求执行技能清单，审美上还要在实际阅读尺寸检查。
- 展示字可以强烈，操作字不随它一起变粗；紧凑工具标题不需要每个都像品牌口号。

#### 行长、断行与字距

- 长正文放在舒适的阅读列中，不横跨整个大屏；宽度按实际语言、字号和内容调整。
- 标题按语义与构图断行，避免短介词、单位或孤字落成尴尬尾行。
- 英文大写、紧行高、负字距和压缩字形只在可读条件下使用；中文不能照搬同样处理。
- 中文标点、数字与拉丁字符在同一行时检查基线和视觉大小，字体回退后也要成立。
- 小标签不默认全大写加宽字距；只有类别辨识或品牌语言真正需要时使用。

#### 数字、单位与光学修正

金额与时长可采用等宽数字以减少变化时的跳动；商品海报上的独立数字则按构图选择。单位、百分号、币种与小数需要稳定归属，不能因缩小退到无法读的位置。价格、日期、时长与参数分别保持格式一致，不混用多套小数、符号和空格规则。

字体加载、CDN 和回退按技能约定执行。不能只核对主字体加载成功的画面，忽略回退导致的碰撞与无效换行。

### 3.7 配色：先定义职责，再选择色相

可先为当前页面定义以下角色，再把它们落实为变量：页面底、内容面、主文字、辅助文字、边界、当前选择、主动作、状态、数据系列。角色可以共享颜色，不必每个角色一套色相。

- **品牌色**建立身份，不应被随意当作所有状态的颜色。
- **内容色**来自封面、商品、作物、地图与图像，框架不必跟每张图重新配色。
- **语义色**表示错误、警告、成功或离线，并用文字、符号或位置补充。
- **数据色**表达系列、顺序、范围或偏差，不能随机随卡片变化。
- **表面色**区分层级与覆盖关系，相邻层的差异应足够辨认。

不规定中性色必须占某个面积，也不限制只有一种强调色。鲜明品牌底可以大面积存在，只要内容、控件和状态仍清楚；多张有色对象也可以成组。

深色界面检查高亮是否刺眼、灰字是否过淡、边界是否消失；浅色界面检查辅助文字与空闲控件是否被误读为禁用。图像上的文字要选择稳定可读的位置与处理，优先重排构图，不默认补一个遮住主体的纯色矩形。

渐变可以表达光、材质、品牌或连续数据；如果只用于给普通卡片增加「高级感」，应先检验是否可以不用。

### 3.8 影像与实物：素材在布局之前参与决策

先决定图片负责什么，再选择素材和排版。

| 影像职责 | 应关注的内容 | 不能用什么冒充 |
| --- | --- | --- |
| 产品识别 | 完整轮廓、型号差异、颜色与比例 | 任意同类商品或普通大图标 |
| 质感判断 | 材质、接缝、反射、细节与真实光线 | 模糊放大的缩略图 |
| 使用与尺度 | 人物、环境、佩戴或操作关系 | 仅色调相近但题材无关的照片 |
| 情绪与品牌 | 摄影方向、姿态、色温、画面张力 | 多张各自漂亮但不相容的图库图片 |
| 内容浏览 | 清楚缩略图、主题与一致裁切规则 | 同一张图复制成多个不同对象 |
| 工作对象 | 当前模型、文件、地图、媒体或设备 | 与实际任务无关的装饰场景 |

系列影像统一机位、主体占比、光线、背景与裁切语法；统一不等于完全相同。两个产品视觉重量差异很大时，要在共同舞台中做适当光学调整，而不是强行拉伸。

去背图可以与文字共处，摄影可以整幅成为场景；选择依据是观看任务，不是一律透明底。图片裁切应保留识别所需部分，有意边缘裁切不能变成漏掉产品关键结构。

主图质量不足时，先修素材、尺度与图文关系，别用渐变、圆轨道和徽章遮掩。来源、许可、取用工具与生图次数执行仓库约定；本节不改变获取流程。

### 3.9 图形、插画与装饰：每个结构装置都要有职责

图形可以用于识别对象、解释关系、表达状态、建立品牌或形成构图张力。它不只是照片找不到时的填空物。

- 天气插画可以说明晴雨与时间，地图路线可以说明出行关系，材质缩略图可以说明选项；这类图形承载内容。
- 放射线、几何块或大面积品牌符号可以与标题形成整体海报；不是先排通用页面，再四处撒星形。
- 线条、箭头、编号、点阵与十字若无真实的信息关系，先不添加。流程或时间顺序需要编号时，才让编号承担顺序。
- 同一组插画保持轮廓、线宽、视角与渲染方式；功能图标与品牌图形可以分工，不必长成同一种对象。
- 图形已经有力，周围减少复杂边界、噪点和阴影。

不能因为某些效果被 AI 滥用就一概禁用。用户明确要求的 HUD、电影 FUI 或其他题材可以使用对应语言，但数据、操作与装饰仍须分层，不能以题材为由模糊数字和遮挡控件。

### 3.10 容器、圆角、边界与深度：先去包装，再补必要关系

为一个区域加容器前，问它是否需要：独立选择、独立操作、独立移动、独立状态、范围约束或明确的对象身份。若只是同一记录的一项字段，通常无需再套一层卡。

- 图片、名称和价格可以直接落在共同背景上；交易、费用与曲目可以连续排版。
- 卡片内部优先用间距、字阶和轻分隔，避免卡片里再套指标卡、说明卡与按钮卡。
- 圆角由尺寸、层级和性格共同决定。大容器、输入框、按钮和小标签不必相同数值，也不能各自随机取值。
- 内外嵌套时边距与轮廓应协调；不要让内圆角挤到外圆角边缘造成不自然的夹角。
- 边框用于范围、选中或分隔，阴影用于高度与覆盖，玻璃用于透叠，纹理用于材质；功能已经清楚时不必同时使用全部效果。
- 深色中阴影往往不够明显，可用表面差与边界建立层次，不因此给每张卡发光。

**去包装实验**：临时隐藏不承担信息的底板、边框、阴影与徽标。还能读懂的组，不把包装全加回去；读不懂的组先修位置与对齐，再补必要边界。真正承担品牌、材质和状态的表现保留，不把减法做成去个性。

边框、聚焦环与裁切完整性按技能清单处理。视觉上还要检查 hover 与选中是否导致布局跳动、阴影是否脏、相邻边界是否过密。

### 3.11 图标：统一系统，区分功能与内容

- 功能图标用于快速识别与操作，尺寸、线宽、视觉重量和留白属于同一套系统。
- 不给每个标题加装饰图标，不用 emoji 当功能图标。
- 收藏、书签、播放、开关和导航等状态有可见差异，不能只在浅底上换一丝颜色；具体两态写法遵循技能约定。
- 图标与文字并排时检查基线、间距与光学高度，不因 SVG 盒子一致就认为视觉一致。
- 仅图标操作需要可访问名称；陌生或低频命令提供简短 tooltip 或明确标签，触控用户也能找到含义。
- 内容插画、设备对象和品牌符号可以比功能图标丰富，但不要混成多个功能图标库。

### 3.12 导航、侧栏、搜索与工具栏

导航回答「去哪里」，工具栏回答「对当前对象做什么」，筛选回答「看哪些内容」。三者不能混成同一排不分语义的胶囊。

#### 导航与侧栏

- 当前页面、当前分组与悬停是不同状态；选中不能只靠鼠标停留显示。
- 折叠侧栏时保留图标顺序、当前位置和相关层级，必要时用 tooltip 或子菜单继续说明目的地。
- 顶级导航、局部 tab 与视图切换分工明确；避免上下两组同名入口重复控制同一件事。
- 返回恢复合理上下文，不无故清空筛选、对象或正在编辑的内容。
- 次级入口轻但可发现，不把所有能力藏进无标签的省略号。

#### 搜索与筛选

搜索靠近被搜索的集合，筛选只提供影响当前任务的维度。生效后在结果与选择状态中可见，清除操作可找到。查询无结果与系统失败分开表现，不能都显示一个通用空白插画。

#### 工具栏

按命令关系分组，例如剪贴板、文本样式、对齐、插入；组间留白或轻分隔比逐工具卡片更清楚。工具大小由频率、作用与标签需要决定，主动作可以突出，但不是每个工具都做大按钮。

选区工具条靠近选中对象，并避开阅读与操作区域；持续通用工具固定在稳定位置，低频命令进入上下文菜单。组件展开时尽量延续共同边缘与主要锚点。

### 3.13 按钮与动作层级

动作先按语义分层，再决定外观。

| 动作角色 | 视觉目标 | 典型安排 |
| --- | --- | --- |
| 当前主动作 | 容易发现并知道结果 | 与当前对象或表单相邻，较明确的填充或对比 |
| 次动作 | 可发现但不争主线 | 轻底、描边、文字或图标，仍有完整热区 |
| 行内动作 | 作用范围明确 | 跟随对应行，必要时进入菜单 |
| 状态切换 | 能认出当前值 | 位置、形态、文字与选中表现一致 |
| 危险动作 | 理解影响并避免误触 | 与普通动作分隔，明确对象和恢复条件 |

- 按钮名称说清结果，例如「保存更改」「添加到清单」，不让所有阶段都叫「提交」。
- 同级按钮共享高度、内边距与字阶，长短名称不随意换一套造型。
- 默认、hover、按下、focus、禁用与忙碌分别可辨；按下可以用轻微压感、颜色或阴影，不要求所有按钮缩放。
- 加载时保留合理宽度和动作含义，状态变化不要让整组控件左右跳动。
- 危险色不能当普通品牌色随处使用；只有无法恢复或需确认的操作才增加确认负担。
- 主次购买动作可以共存，不能为了全页只留一个主按钮而删掉合理流程。

### 3.14 输入、表单与复合字段

表单的精致来自清楚的分组、稳定对齐和状态，而不是把每个字段包进一张大卡。

- 标签说明字段，placeholder 说明格式或示意，不能用 placeholder 替代必要标签。
- 相关字段成组，例如姓名与联系方式、日期与时间、位置与尺寸；跨组间距较大。
- 短字段按内容合理宽度，长内容得到足够空间；不为整齐把所有输入拉成一样窄。
- 帮助信息只在有理解成本或限制时出现，不在每个输入下写一段用途说明。
- 错误靠近问题字段，说明原因与恢复动作；不要清空用户输入，也不把整页染红。
- 必填、只读、禁用、未选择和已填写是不同含义，外观与语义不能混淆。
- 密码显示在原字段内切换遮蔽与图标，保持值、焦点、尺寸与字段身份，不新开弹窗。
- 日期、时间、颜色等复合选择器与普通输入共享边界、字号、聚焦和选中语法；下拉打开后也要像同一个产品。

所有系统控件的定制、下拉面板与焦点技术要求执行硬约束清单；不只把静态输入边框画漂亮，却留下完全不同的原生弹出层。

### 3.15 选择器、开关、滑杆与进度

#### 离散选择

Tab、分段控制、radio 和多选各有语义：切换视图、选择一个值、选择多个值不能混用。选中通过轮廓、位置、填充、符号或文字共同确认，不要求只靠颜色。

色款与材质样本应有名称和选中标记，浅白样本在浅底上仍有可辨边界。样本色服务产品选项，不代表普通操作都要跟着染成相同颜色。

#### 开关

开关位置稳定，开启与关闭通过滑块位置和必要文字区分；设备离线或处理中不能伪装成普通关闭。开关控制什么，要从相邻名称明确知道，不把同一状态重复写成多枚徽标。

设备对象或局部场景可以同步变化，形成「操作 → 状态 → 对象」的短路径。仅为演示而出现的日夜大场景切换，不作为所有开关的默认反馈。

#### 滑杆与旋钮

轨道、当前值、范围、单位、步长和端点语义清楚。亮度、音量和温度有各自范围，不用一套装饰刻度冒充全部参数。拖动时读数就近更新，离开拖动后关键值仍能确认。

旋钮可有触感和阻尼，但数值不能难以选择；拖动方向、边界与替代输入要能理解。不能靠视觉物理感掩盖功能不准确。

#### 进度

已知进度与未知等待用不同表达。确定比例来自真实任务，不为了漂亮匀速跑到完成；阶段进度、播放时间、任务完成比例也不能混成一种含义。轨道、填充与终态共享组件语法，完成后的对象与结果可观察。

### 3.16 列表、表格与重复内容

重复对象最重要的是比较关系。先决定识别列、比较列、状态列和操作列，再画容器。

- 名称是识别入口，缩略图或头像辅助；作者、类别、地点等元信息紧邻但退后。
- 金额、时间、数量等比较值放在稳定位置，格式一致；不要每行都把字段随机排成两层。
- 行间通过一致间距或轻分隔形成节奏，不必每行都有独立投影。
- 行 hover、选中、当前播放与键盘 focus 分开表现；多选与打开详情的热区不能互相冲突。
- 低频动作进入行菜单，但触控、键盘与批量操作仍可发现。
- 头像、徽标、状态与操作只保留必要项，不让每行成为微型宣传页。

表格保留必要列头、单位、排序与时间范围；宽度不足时按任务调整呈现，不能无条件删除关键列。长名称允许合理换行或提供查看完整内容的路径，不把所有字符串一刀截断。

### 3.17 不同对象的卡片应表达不同任务

卡片可以有统一语言，但内容关系不必相同。

- **商品**：图片先识别，名称和价格跟随；颜色、材质与必要差异按浏览任务呈现，不逐商品展开完整购买流程。
- **银行卡或账户**：对象身份、关键金额与必要识别信息清楚；交易不继续复刻卡面结构。
- **项目或任务**：名称、截止、参与者、状态与进度成组；进度要能说明实际完成程度，不是装饰。
- **设备**：名称、关键状态与直接控制形成短路径；详细参数进入设备视图。
- **文章或内容**：图片与标题承担主题，作者、日期或类别退后；摘要只在帮助判断时出现。
- **播放器**：封面、曲名、作者、时间、进度与播放控制属于同一个对象，不能散成多张不相关小卡。
- **天气**：地点、温度、天气对象与预测有主次，氛围图不挤掉必要读数。

共享的是字阶、边距、边界与状态语言，不是「图标 + 标题 + 大数字 + 趋势 + 按钮」这一套内部结构。

### 3.18 图表、仪表与地图：图形必须帮助判断

每张图先回答一个问题：变化怎样、对象怎样比较、比例怎样组成、哪里异常、路线如何、当前值离目标多远。没有判断用途，就先不用图表。

- 趋势获得足够横向空间，瞬时状态紧凑呈现；同一任务的指标可成组，不逐指标配一张图。
- 时间范围、单位、刻度与必要基准清楚；装饰性迷你图不能代替需要读数的分析图。
- 类别色、顺序色与偏差色各有逻辑，跨图保持相同对象映射；不因卡片颜色变化就重配系列。
- 标签与 tooltip 不覆盖核心内容；重点只标当前关注或必要异常，不把每个点都高亮。
- 平滑曲线不能编造原数据之间的变化，图形不为美观改变关系。
- 仪表的尺度、范围和当前值可理解；半圆、环形与仪表盘不是所有指标的默认表现。
- 地图保留方向、地点、路线与关联详情；路线和地图信息面互为上下文，不拿模糊世界轮廓当真实导航。

数据少可以用直接读数，数据多可以高密度排布；高级感不是把所有刻度删掉。参考中的指标、百分比、评分和技术断言需独立核验，不能照搬成业务事实。

### 3.19 浮层、菜单、抽屉与对话框

先判断内容需要哪种空间，再决定覆盖形式。

| 内容性质 | 优先考虑的形式 |
| --- | --- |
| 当前控件的一组选项 | 锚定触发控件的局部面板或菜单 |
| 当前对象的补充信息 | 内联展开、相邻检查器或局部详情 |
| 暂时且原子的确认或轻量输入 | 对话框 |
| 需要持续浏览、比较或编辑的模块 | 真实页面、视图或工作区 |

- 浮层与触发对象有空间联系，打开与关闭保持合理方向；靠边时调整位置，不逃出产品画布。
- 内容、内边距、圆角、阴影与前景层级一致；菜单不能像另一套组件库。
- 菜单按语义分组，当前值、不可选项与危险动作清楚。
- 遮罩只在需要限制背景操作时使用；不是每次展开都把整个产品盖住。
- 关闭方式、键盘行为与焦点恢复要完整；淡出结束不能把焦点留在消失的控件上。
- 对话框尺度与画布边界按硬约束执行，不在本文另设比例标准。

截图中同时摆出的多个面板可能是状态说明，不代表真实产品默认应同时打开它们。

### 3.20 状态：把结果放在被操作的对象上

状态不是收尾时加几张插画，它们应从组件设计开始就参与构图。

| 状态 | 应表达什么 | 常见错误 |
| --- | --- | --- |
| 空 | 为什么没有内容，下一步能做什么 | 长段产品介绍或无关大插画 |
| 加载 | 哪个对象或动作在等待，已有内容是什么 | 整页遮罩覆盖一个局部操作 |
| 成功 | 哪个对象发生了什么变化 | 只弹「成功」，对象没有结果 |
| 失败 | 哪步未完成，如何恢复 | 输入清空、全页变红、原因含糊 |
| 禁用 | 不能做什么及必要原因 | 与空闲或未选中混淆 |
| 选中 | 当前对象或值是哪一个 | 只有 hover 看得出，持久状态不明确 |
| 离线或不可用 | 对象真实可用性 | 直接画成关闭并允许假控制 |

处理中保留对象、上下文与布局稳定。失败尽量就近说明，保留可恢复输入。收藏、排序、添加、删除、保存等前端结果直接体现在对象或集合里，短通知仅作补充。

持久状态不因动画播放完自动复位。真实服务未连接时不伪造支付、上传或云端协作成功；可本地完成的操作用本地结果，服务限制按技能约定说明。

### 3.21 动效：连续、因果、可中断

动态参考最值得迁移的是状态之间的连续关系，而不是展示视频的全部运动。

#### 先判断是否需要

- 状态切换、展开收起、对象移动与视图关系需要被理解时，可以有短而准确的过渡。
- 高频工具操作以即时响应为先，不强制每次播放完整动画。
- 品牌叙事可以有较长编排，但用户必须能及时看到内容、继续浏览和操作。
- 静态构图不成立时，先重排内容，不用运动转移注意力。

#### 保留对象身份与空间锚点

开关滑块从当前位置到新位置；选中底板跟随新选项；侧栏收拢时图标顺序保留；文件拖入时目标先确认接受，再更新集合；播放器展开时封面或主控制延续。不是每个状态都先消失，再从零缩放出现。

#### 同一次变化由一套节奏管理

主对象先明确，相关文字、图标、背景与控制协调跟随；无关区域不陪着表演。错峰用于说明阅读或对象关系，不给每张卡任意加 delay。快速反向与连续输入从当前视觉状态衔接，避免跳回起点。

#### 速度、缓动与触感

较小、较频繁的反馈通常更短，较大的空间转场可以略长，表达性叙事按内容编排。调试时可把小控件过渡约 120–200ms、一般局部面板约 180–300ms 作为起点，但这些不是原图测量值，也不是通用合规参数；应按距离、设备、频率与实际感受调整，必要时不动画。

移动与展开可用自然减速，屏内连续形变可用合适加减速，确有物理语义的拖拽或旋钮可有克制阻尼。匀速过程使用线性并不错误；夸张回弹、连续弹跳和每次点击都缩放并不自动精致。

#### 终态比展示过程更重要

采样帧能显示位置、形态和色彩变化，但不能精确证明触发、曲线和时序。GIF 的循环、自动复位、摄影机推进与外部场景变化不照搬为产品行为。完成态保持，失败可恢复，进度不伪造。

#### 减少动效与性能

减少动效时保留直接状态和全部功能。触控不依赖 hover；键盘操作不因动画被延迟。优先采用成本较低的运动属性，谨慎使用大面积实时模糊、滤镜和连续背景效果，不能笼统断言任何效果都由 GPU 无成本完成。具体实现与中断策略执行 `SKILL.md` 第五节及硬约束，不因审美参考更换仓库技术栈。

### 3.22 文案：具体、必要、从用户视角命名

文字是信息，不是填充版面的纹理。

- 用对象、值、状态和动作说话，不反复介绍页面是什么。
- 动作名称与结果一致，「添加」对应已添加对象，「保存」对应更新结果。
- 列表名称、类别、价格、时间和单位直接组织，不默认每项都写「名称：」「价格：」。表单标签和必要说明仍保留。
- 只在用户需要理解限制、规则、费用、风险与恢复方法时增加解释。
- 不用「智能、高效、重新定义、为您打造」代替具体内容，不默认每屏都有口号、眉题、编号与外语氛围字。
- 用户数、评价、促销、认证、性能数据和承诺要有依据，不为了填空编造背书。
- 跨页面用词与语言一致，不把不同题材的模板文案残留在一起。

文档可以用假设内容说明排版关系，实际界面仍须遵守正式文案与业务可信度要求，不把案例中的数字或名称当成已验证数据。

### 3.23 适配与极端内容：保持关系，不只是缩小

先按技能确定当前是网页流式布局、一般固定容器还是参考还原画布；不要把不同模式的比例、单位与滚动策略混用。

审美验证至少观察：

- **整体缩览**：第一落点、明暗面积、疏密节奏、是否像通用模板。
- **实际阅读尺寸**：正文、名称、单位、图标、边界、触控与焦点是否清楚。
- **关键状态**：展开、选择、加载、失败、返回后是否保持同源。
- **目标视口变化**：短屏、窄屏与较宽视口下关系是否仍成立，是否出现多余空档或碰撞。
- **最差内容**：长商品名、中文与英文混排、大金额、零记录、多项选中、缺图与字体回退。

缩览不能证明小字可读，截图保存成功不能证明看过，静态截图不能证明流程完成。网页需要重排时按内容关系重排；固定画布与还原策略按技能执行。任何策略都不能用裁切关键内容或整体糊缩来掩盖设计问题。

## 四、识别「一眼 AI」：组合症状与纠正顺序

判断的是没有依据的组合，不是某种颜色或控件本身。以下症状出现时，先回到任务、内容和构图，再修表面。

### 4.1 不理解产品就先放通用外壳

**症状**：任何产品都有侧栏、欢迎横幅、四个 KPI 与等宽卡，真正对象只剩一小块。

**改法**：先排工作对象、判断内容与动作，再安排导航。编辑器保护画布，浏览页显示内容，业务页支持比较；不靠换标题把一套后台变成另一种产品。

### 4.2 把完整度理解成首页全展示

**症状**：设置、历史、推荐、参数、帮助和统计全部常驻，首屏没有阶段。

**改法**：划分发现、判断、填写、核算与确认。当前必需直接显示，低频进入真实次级视图；无关能力删除，不只是藏起来。

### 4.3 所有信息都住进同款卡片

**症状**：每个金额、标签、交易和说明都有底板、图标、阴影，卡片里面继续套卡片。

**改法**：做去包装实验。连续记录用行，同一对象的字段直接成组，只给独立对象或操作范围补必要边界。

### 4.4 所有区域平均用力

**症状**：每张卡同尺寸、每个动作实心、每段文字有眉题、每幅图都一样大。

**改法**：按任务分配面积与对比。明确第一落点，降低竞争区域，不继续给主角加效果。

### 4.5 用极小、极淡文字换干净缩略图

**症状**：整体看似轻，实际读不清状态、价格、单位与操作。

**改法**：在真实阅读尺寸检查。先删重复、合并分组、扩展合理空间或重排，再调整字阶；辅助信息退后但不消失。

### 4.6 留白均匀而没有职责

**症状**：单行数据占巨型容器，主图与动作相隔很远，信息区却挤成一团。

**改法**：让空隙说明归属与观看节奏。主体可以宽松，比较行应紧凑；不以增加模块填无用空白。

### 4.7 只换高级色，没有改变关系

**症状**：金融、音乐、家居都用同一套雾色、胶囊和大圆角；或见强色就磨成白灰。

**改法**：从对象、素材和品牌决定色彩职责，同时检查骨架、字体与图文关系。结构问题不能靠换色解决。

### 4.8 主体弱，装饰比产品更有力

**症状**：小产品图周围堆光球、轨道、星点、徽章、描边大字与发光按钮。

**改法**：先修机位、尺度、取景、字形和留白。只保留加强同一构图的图形，不另造视觉中心。

### 4.9 素材各自漂亮却不属于同一世界

**症状**：摄影、3D、线性插画混杂，产品光线和比例不同，同一图当多个视角。

**改法**：建立素材共同语言与职责。主题真实性和系列一致性先于色调相近，不能用滤镜统一一切。

### 4.10 字体只在样式名里有个性

**症状**：选了展示字体却仍按普通段落排，或所有标签等宽、全大写、加宽字距。

**改法**：让字宽、字重、断行与主素材共同构图。正文、数字和操作保持清楚，中文不照搬英文特效。

### 4.11 文案反复解释界面

**症状**：标题下解释标题、每个图表解释图表、每页都说智能与高效。

**改法**：直接呈现名称、状态、结果与动作。说明只承担理解成本、规则或风险，不为填满区域写段落。

### 4.12 用无依据背书填首屏

**症状**：每页都有头像堆、万人信赖、评分、认证与上涨百分比。

**改法**：只有有来源且帮助当前判断的证据才留下。没有依据就删除，不用假数字补完成度。

### 4.13 图表只是后台装饰

**症状**：数据重复、单位不明、曲线全向上、每张卡一句泛泛洞察。

**改法**：先写清图表回答什么问题。合并重复指标，保留时间、单位与必要基准，按真实比较关系选形式。

### 4.14 导航、筛选和工具混为一排胶囊

**症状**：相邻控件长相相同却有不同作用，上下两组入口重复，没有当前位置。

**改法**：按去哪里、看什么、对对象做什么分工。空间与外观表达层级，选中与悬停分开。

### 4.15 所有模块都用弹窗代替

**症状**：导航只弹说明，详情、设置、编辑和列表都是相似对话框。

**改法**：有持续内容的模块做真实视图；轻确认和快速选择才覆盖。简洁通过流程实现，不靠假入口。

### 4.16 默认精致，其他状态像另一套库

**症状**：下拉突然系统风、失败整块红、加载全页遮罩、选中只换浅色。

**改法**：从组件开始设计状态，共享字阶、边界与反馈语言。局部问题局部反馈，输入与上下文保留。

### 4.17 用整页淡入上移代替动效设计

**症状**：每块独立 delay，背景永久漂浮，内容要等动画结束。

**改法**：先找原因、对象与锚点，一次变化协调一组相关元素。高频操作短而清楚，品牌编排服务叙事。

### 4.18 把展示视频当真实产品行为

**症状**：已选状态几秒后复位，成功自动消失，镜头推进让控制跟着飘。

**改法**：分清展示循环与用户状态。持久结果保持，控件稳定，外部拍摄运动不搬进默认界面。

### 4.19 只在理想内容与单一尺寸成立

**症状**：短名称漂亮，长名称碰撞；大屏空洞，短屏裁切；字体回退后标题遮挡按钮。

**改法**：验证实际尺寸与最差内容。按容器规则调整伸缩与呈现，不藏核心内容，也不把网页当图片糊缩。

### 4.20 把一种成功做法变成新模板

**症状**：后续所有产品都用同样骨架、字形、色板与动效，或拼贴多个参考最醒目的部分。

**改法**：明确借的是哪种关系、为何适合，重新用当前内容构图。保留主导方向，不借无关模块与品牌道具。

## 五、自包含设计案例：不知道怎样设计时，可以怎样组织

### 5.1 从具体问题推导可观察的安排

以下是文字型实践案例，不是具体图片说明、项目列表或要求照搬的参数表。每例给出场景、安排、关键细节与边界；后续设计可只借其中一种关系。假设名称、金额与数据仅用于说明信息位置，不构成业务事实。

#### 案例 1 · 让商品系列成为连续展陈

**场景与问题**：用户浏览同系列服装，每件商品被评分、角标和购买按钮包围，产品像卡片配图。

**一种安排**：让衣物共享背景与展示基线，取景、尺度、光线相容。每张图下直接跟品名与价格，颜色或材质作为轻量次信息。系列名称放在整组上方，切换与查看更多放在组边缘；尺码、护理与配送进入详情。

**关键细节**：图片舞台相同，但根据实物视觉重量微调占比；名称与对应图片靠近，组间留白更大。不同商品使用不同且真实相关的图片。

**效果与边界**：一组商品先形成品牌展陈，归属不依赖重卡片。快速比价任务仍需直接显示价格和必要差异，不能为了气氛隐藏。

#### 案例 2 · 让产品与大标题组成整幅舞台

**场景与问题**：出行产品首屏右侧是一张小车图，左侧长介绍，周围用光效补气势。

**一种安排**：先选能看清轮廓与结构的整车机位，让实物成为首屏主要面积。短型号或品牌标题与车身方向形成关系，可以在不损害辨识的部位前后层叠。必要说明与购买入口收在稳定边缘，不再并列三张卖点卡。

**关键细节**：车轮、车头与文字留白有计划，操作不压到高频图像细节上。背景色与物体材质、光线相容，阴影只说明落地关系。

**效果与边界**：记忆点来自实物与字形，而非特效。适合展示与发布，购买前所需规格仍在后续清楚呈现，不套到高频工作台。

#### 案例 3 · 用观看任务组织产品长页

**场景与问题**：每节都是同样的标题、正文、三张卡和按钮，长页很整齐却没有推进。

**一种安排**：首段看完整产品；下一段看一个关键局部，短文字解释这处细节；再下一段看真实使用场景；随后以连续商品或配置组支持比较；最后用明确动作收束。图像总貌、局部与场景各提供新信息。

**关键细节**：不同章节面积可以变化，标题与图像边缘保持跨段呼应。深浅区切换跟随材质、影像或观看任务，不每节随机配色。

**效果与边界**：用户从识别推进到理解与选择。不是规定每个网站必须五段，也不为凑节奏增加无依据技术断言或促销。

#### 案例 4 · 商品详情按判断顺序展开

**场景与问题**：图片、价格、参数、评价与优惠同样醒目，用户不知道先判断什么。

**一种安排**：图片负责识别与质感，紧邻信息组放品名、价格与购买前必选规格。数量与主购买动作就近，加入清单等次动作降低重量。详细材质、尺寸与护理分组放在后续区域。

**关键细节**：色款选中同时体现在样本标记、名称和对应图像；关键费用或限制不藏在低频说明。照片、参数和动作在窄空间重新组织，但关系不散。

**效果与边界**：阅读从是什么、是否适合推进到如何购买。并排或上下由内容与容器决定，不固定左文右图。

#### 案例 5 · 购物袋与订单只负责核算

**场景与问题**：结算页继续放大幅促销、推荐、安全徽章与 FAQ，价格信息散落。

**一种安排**：商品缩略图、名称、已选规格与数量成组；单价和小计放在稳定列。配送、折扣与总额组成连续费用区，下一步动作靠近总额，修改与删除跟随对应商品。

**关键细节**：费用标签和值形成稳定两列，币种与小数一致；数量变化直接更新对应小计和总额。错误提示靠近导致问题的条目或字段。

**效果与边界**：用户能核对而不是重新浏览营销。真实支付未接入时不伪造支付成功，风险与必要费用仍明确。

#### 案例 6 · 用图文面积差建立生活方式专题

**场景与问题**：精美照片都被裁成等大的小卡，标题和介绍平均铺满，材质氛围消失。

**一种安排**：一张佩戴或使用照片占较大区域，相邻窄列放短标题与必要信息；另一张材质细节图稍小且位置错开。照片负责尺度与情绪，局部图负责质感，文字不重复解释画面。

**关键细节**：两组各自内部对齐，错位发生在组间。肤色、实物与背景色温相容，阅读字体和操作清楚，衬线只在适合的短展示文字中使用。

**效果与边界**：温暖与精细来自同源素材和观看顺序，不来自统一奶油色皮肤。若主要任务是参数比较，应增加直接比较信息。

#### 案例 7 · 编辑器围绕当前对象组织

**场景与问题**：上方是平台介绍和使用统计，四周常驻所有工具，模型只剩小块空间。

**一种安排**：中央留给模型或画布，相邻一侧放对象列表，另一侧放当前对象属性。参数按位置、外观、内容等任务分组，类别切换复用面板；相关对象操作在选中后就近出现。

**关键细节**：选择对象时，画布、列表和属性标题能互相确认。缩略材质直接表达选项，工具不为每个字段新建卡片，浮条避开关键对象。

**效果与边界**：功能丰富但默认工作区安静。未选中状态与触控、键盘仍能发现必要入口，不能以隐藏工具制造假简洁。

#### 案例 8 · 工具栏按命令语义成组

**场景与问题**：剪切、字体、对齐、插入和查找排成一串同样大的按钮，没有扫描路径。

**一种安排**：剪贴板为一组，字形与字号为一组，段落与对齐为一组，插入为一组。组内紧凑，组间以空隙或轻分隔断开；常用命令直接可见，低频通过菜单。

**关键细节**：字号输入、下拉与图标按钮共享高度和基线；状态按钮有明确选中表现。Tooltip 短而具体，不悬浮长篇功能介绍。

**效果与边界**：用户按任务定位命令，不需要每个按钮一个容器。分组由实际命令决定，不机械照搬办公软件结构到所有工具。

#### 案例 9 · 侧栏折叠不丢失空间记忆

**场景与问题**：折叠后图标重新排列，当前页面不可辨，展开像出现另一组导航。

**一种安排**：保持图标顺序与主要垂直位置，标签随宽度收拢，当前项保留轮廓或填充关系。折叠状态用 tooltip 说明名称，必要子级由相应项的局部菜单承载。

**关键细节**：折叠按钮仍在可预期位置，当前项与 hover 区分，快速展开收起从当前状态衔接。标签消失不能留下可聚焦但看不见的入口。

**效果与边界**：节省空间但不丢位置。单组件任务只做必要导航反馈，不追加账户、消息和无关业务弹窗。

#### 案例 10 · 资金概览分清对象卡与比较行

**场景与问题**：余额、额度、每笔交易与每个状态都变成同款统计卡。

**一种安排**：账户或银行卡作为独立对象保留卡面；可用金额与必要账户识别就近。交易使用连续行，名称为入口，类别与日期退后，金额在稳定列，完整明细有清楚入口。

**关键细节**：金额、币种与小数统一，收入支出不只靠颜色区分。没有比较价值的趋势不添加，同一读数不多处重复。

**效果与边界**：可信感来自清楚读数与对象关系，而非卡片数量。需要多账户比较时，信息与控制可适度增加，不为干净隐藏关键状态。

#### 案例 11 · 音乐内容与播放器各司其职

**场景与问题**：曲目每行都是宣传卡，封面、播放按钮和时长散成多个模块。

**一种安排**：专辑以封面和名称浏览，歌曲以曲名、作者、时长的连续行呈现。底部或局部播放器集中当前封面、曲名、播放控制与进度；当前曲目行有相应状态。

**关键细节**：封面承担气氛，框架降低竞争。时间和进度确实对应当前播放对象；音量与收藏有状态，不用波形变化冒充真实进度。

**效果与边界**：内容丰富但操作集中。播放器是单组件时，不扩展完整音乐社区；真实媒体加载失败要在原对象上恢复。

#### 案例 12 · 强品牌赛事与密集信息共存

**场景与问题**：角色、大标题、新闻、比分、直播和按钮都争主角，或被统一压成普通灰色后台。

**一种安排**：一组角色或现场影像与赛事标题形成焦点；新闻用图与短标题，直播用紧凑行，比分和赛程成组。辅助区域保留清楚数据，但视觉重量低于赛事主组。

**关键细节**：队徽和内容色保留领域身份，框架不用每区强色。相同赛事的进入动作不在同一处重复，时间与状态稳定对齐。

**效果与边界**：品牌能量保留，信息仍能扫描。强色不是错误，无关装饰与多处同权才是问题。

#### 案例 13 · 设备状态直接参与控制单元

**场景与问题**：设备名下有运行说明、状态徽标、趋势和多个按钮，开关反而不明确。

**一种安排**：名称、关键状态与直接控制形成一个单元。开启时滑块位置、状态文字和适当表面变化相互确认；离线与处理中使用不同表达。历史与配置进入设备视图。

**关键细节**：状态切换时名称、热区和开关位置稳定。多台设备同时开启，可以同时呈现开启状态，不人为只允许一张深色卡。

**效果与边界**：对象现在怎样、能做什么一眼可知。安全限制不能省，未连接设备不伪造真实控制成功。

#### 案例 14 · 灯光控制让值与对象同步

**场景与问题**：亮度、颜色、场景和开关各自一块，用户看不到它们控制同一盏灯。

**一种安排**：设备名称与总开关在同一控制面上，亮度滑杆带就近读数；色款为样本列并有选中标记，更多颜色从局部面板选。场景选择是一组离散值，影响对应亮度与颜色。

**关键细节**：拖动时亮度值和对象表现协调更新，释放后关键值仍可读。新增场景是短输入，完整设备配置进入相应视图。

**效果与边界**：参数之间的因果明确，不靠说明段串联。场景图只在有实际表达价值时使用，不让日夜动画成为所有开关模板。

#### 案例 15 · 同一次训练的信息合为一组

**场景与问题**：距离、时长、配速、心率与路线都各有同等大的卡和一张小图。

**一种安排**：距离、时长和配速在同一训练信息组内稳定对齐；心率趋势获得较宽区域；路线与该次训练相邻，目标或即时计时紧凑呈现。最近活动用连续行。

**关键细节**：单位、时间范围和当前训练名称清楚，比较值不重复。照片若使用，应说明运动或场景，不只提供暖色氛围。

**效果与边界**：空间对应比较与观察任务。专业分析可以更密集，不能为了清爽删掉必要刻度和指标。

#### 案例 16 · 生产概览先认对象，再看异常

**场景与问题**：农业或生产界面只是普通后台换绿色，作物、区域与问题被拆散。

**一种安排**：区域或生产对象以同源缩略图、名称和关键状态成组；需要关注的异常就近指出。趋势与作业列表直接放在相邻区域，详细记录进入对象视图。

**关键细节**：不同对象图像的光线、尺度和背景相容；异常有文字和符号，不能只靠卡片变色。辅助操作与对应对象连接。

**效果与边界**：领域身份来自真实对象与作业关系。没有任务依据时不加天气、助手或农艺口号，也不搬跨品类模板文案。

#### 案例 17 · 场景与监控读数互为上下文

**场景与问题**：场景照片上叠满指标、标签和按钮，既看不清环境也读不清数据。

**一种安排**：场景保持主要观看区域，关键读数集中在相邻信息面，选定区域在场景中有必要标记；切换监控对象时名称、读数和场景对应更新。

**关键细节**：图像标记只承担位置或异常，不重复完整信息面。图表进入相应分析视图，不压进照片所有角落。

**效果与边界**：用户知道数据来自哪里。照片要与管理对象相关，不能用任意漂亮风景充当实时监控证据。

#### 案例 18 · 旅行 App 分清发现、详情与路线

**场景与问题**：目的地封面同时常驻社交、评分、行程、支付与交通信息，图片被遮挡。

**一种安排**：发现页用目的地照片、名称与必要类别浏览；详情突出地点、活动或行程的判断信息；路线页让地图与起终点、时间、交通方式互相对应；费用与旅客信息进入核算阶段。

**关键细节**：影像保持同源，顶部返回明确，底部主动作随阶段变化但样式同源。地图里的路线与列表不是两个无关展示。

**效果与边界**：每屏有一个判断主线，整个流程完整。示意地图、评分与价格不能当作真实服务数据。

#### 案例 19 · 天气组件让场景与读数共同成组

**场景与问题**：天气对象漂亮，但地点、温度、预测和日期散落成多张卡。

**一种安排**：地点与当前温度建立主读数，天气插画或场景与它共处；高低温、简短状态与未来预测在相邻较轻区域连续排列。切换地点时读数、标题与场景一致更新。

**关键细节**：温度符号、单位和日期可读；场景色不降低文字对比。预测有真实时间关系，不用重复晴天图标填满。

**效果与边界**：情绪与功能相互支持。天气不是所有个人工具或业务首页的默认模块。

#### 案例 20 · 计时工具围绕正在发生的时间

**场景与问题**：为了丰富，计时器主界面塞历史趋势与大量解释，计时和暂停不突出。

**一种安排**：当前时间或倒计时为主读数，开始或暂停在稳定位置，重置与记录为次动作。分段记录用清楚时间列；只有帮助当前任务的环形或刻度才保留。

**关键细节**：数字变化不跳宽，运行、暂停与归零有可确认状态；按钮触感可以细腻，但文字与符号对比足够。装饰图表不冒充计时结果。

**效果与边界**：用户立刻知道当前状态与下一步。软浮雕或拟物不是必选，计时准确性优先于材质表演。

#### 案例 21 · 项目进度卡把相关信息压成一条主线

**场景与问题**：项目名、日期、成员、状态和完成比例各套一块，卡片很大却难以理解。

**一种安排**：名称作为入口，截止和参与者在次级信息行，状态与进度靠近；进度条横向连接当前比例与任务含义。更多操作放在稳定角落，详情进入项目视图。

**关键细节**：成员头像只承担参与者身份，不当信任装饰；时间格式一致。完成比例来源明确，异常或逾期有可读提示。

**效果与边界**：用户先认项目再看推进情况。任务数量少时可直接列项，不一定需要进度条。

#### 案例 22 · 上传从选择对象推进到可观察结果

**场景与问题**：点击上传后只出现进度动画，完成自动复位，用户不知道哪个文件被处理。

**一种安排**：初态给清楚选择或拖入入口；选定后在原组件显示文件名、类型与必要大小；处理状态围绕该文件，终态显示本地结果或真实服务结果，并给合理下一步。

**关键细节**：错误保持文件上下文，重试指向原动作；未知等待不伪装确定比例。长文件名仍可辨，删除与取消作用范围明确。

**效果与边界**：一个组件承载完整状态，而不是靠 Toast 宣告。无真实上传服务时不能声称已上传至服务器，可提供本地预览或明确服务限制。

#### 案例 23 · 拖入反馈先确认目标，再确认完成

**场景与问题**：拖到文件夹上时已经显示完成，或没有目标反馈，释放后列表突然跳变。

**一种安排**：拖动对象保留身份，进入可接受区域时目标边界或表面变化，并说明将添加的对象数量；释放并实际完成后，目标集合与计数更新，未完成时不提前宣告结果。

**关键细节**：不可接受区域有不同反馈；退出目标取消预期状态。键盘或菜单提供等效移动方式，快速改变目标时反馈跟随当前对象。

**效果与边界**：区分操作意图与已发生结果。外部展示中的放大、飞行与镜头运动不必全部复制。

#### 案例 24 · 密码显示保持字段身份

**场景与问题**：显示密码会打开新面板，图标难理解，切换时输入框尺寸或内容跳动。

**一种安排**：显示控制留在字段尾部，在同一字段切换遮蔽；名称、当前值和焦点保持。控制名称表达接下来将执行的显示或隐藏动作。

**关键细节**：图标两态清楚，热区足够，长内容不挤到控制上；错误与帮助仍在原字段位置，不因切换消失。

**效果与边界**：一次局部变化完成一个明确动作。视觉参考中的样例密码不应复制为实际业务内容。

#### 案例 25 · 分享从一个动作扩展为局部选择

**场景与问题**：单按钮扩展后像另一张应用首页，出现无关统计、平台解释与多个大卡。

**一种安排**：以触发按钮为锚点，展开紧凑的目的地或方式列表；当前选择和执行动作清楚。复制链接后原位置给可确认反馈，关闭回到原按钮身份。

**关键细节**：平台名称、图标和可用方式根据当前产品决定，不搬旧平台列表。多项选择与直接执行的语义分清，忙碌时组件宽度稳定。

**效果与边界**：保持局部任务与空间连续。只有确需额外内容时才进入下一视图，不为功能完整扩展社交系统。

#### 案例 26 · 来电条由简到详，但主操作始终可认

**场景与问题**：短状态条扩展后接听与挂断位置完全变化，辅助控制争主线。

**一种安排**：初态以联系人和当前来电状态为识别，接听与挂断明确分工；展开态补充通话信息与低频控制，联系人或主控制保持连续锚点。

**关键细节**：危险与接受动作不仅颜色不同，符号和名称也明确；扩展时不压住重要内容，状态文字与计时对应实际通话阶段。

**效果与边界**：复杂状态从同一对象自然长出。展示样机与场景音效不是产品默认需求，未接通信服务不能伪造真实接通。

#### 案例 27 · 失败在原位置恢复，而不是重做页面

**场景与问题**：提交失败后输入清空、组件变成大红块，只剩一个重试按钮。

**一种安排**：保留原内容和已选对象，问题字段或操作旁给短原因，恢复动作就在相邻位置。若部分完成，区分已完成与未完成，不让用户重新操作全部内容。

**关键细节**：错误沿用原有字阶和边界，只在需要处增加强调；焦点能到问题位置。重试进行中保持布局，成功后结果落在对应对象。

**效果与边界**：失败仍像同一产品，也降低重复劳动。不能仅靠屏幕角落一条通用错误 Toast 代替恢复路径。

#### 案例 28 · 从说明书文案改为对象、值与状态

**场景与问题**：每块都解释用途，例如「灯光控制：用于开启或关闭客厅灯光」。

**一种安排**：直接用「客厅灯光」和实际开关，必要时保留「已开启」或「离线」；账户用「可用余额」与带币种的金额，文件用名称与处理状态。结构已表达归属时不重复标签。

**关键细节**：单位、表单标签、费用、限制与错误原因仍保留；陌生命令用短名称或 tooltip，不能只剩猜不出的图标。

**效果与边界**：字少但信息不减，主次更清楚。减少文字不意味着把可访问名称和必要解释一起删除。

### 5.2 从案例提取关系，不复制整页

应用某个案例时，明确三件事：

1. **借什么**：例如连续展陈、稳定比较列、对象与状态的短路径、图文面积差。
2. **为何适合**：当前任务确实需要这类识别、比较、控制或观看方式。
3. **改什么**：当前内容长度、素材、语言、风险、容器与输入方式不同，必须调整哪些安排。

可把商品展陈关系用于工具素材浏览，但不能把服装影像、价格和购买模块一起搬去；可把稳定列用于曲目与交易，但两者的状态和动作仍不同。一个关系解决一个问题，不从多例各摘一块拼成无主导语言的页面。

### 5.3 内容减法与去包装的两次检查

**第一次：去内容冗余。** 暂时拿掉泛泛介绍、重复读数、装饰性统计、无依据背书、无关模块，检查用户任务是否受损。受损的必要信息恢复，不受损的不加回。

**第二次：去视觉包装。** 暂时拿掉非必要底板、边框、阴影、徽标与装饰，检查分组是否仍清楚。先修位置、间距、字阶和素材，再恢复确有职责的表面。

这两次检查不用于磨平品牌性格，也不用于删掉核心能力。目标是让每项内容与表现都值得存在。

### 5.4 从简短说明落实为当前页面系统

可以在对话中写出这样的方向说明：

> 用户先识别正在管理的设备，再完成开关与亮度调整。设备名称、关键状态与直接控制组成独立单元，历史进入设备视图。框架安静，设备对象提供内容色；当前值与控件位置共同表达状态。主区域不加欢迎横幅、能耗装饰图表或天气。只有控制变化与面板展开需要短过渡。

接着为这页建立自己的颜色职责、字体角色、间距档位、轮廓层级与动效规则。另一种产品重新推导，不把这段说明和变量系统当万能模板。

### 5.5 精修顺序：结构问题不交给特效解决

**任务与范围 → 信息分阶段 → 主次与骨架 → 素材与图文尺度 → 字体、间距和对齐 → 表面与控件 → 状态与动效 → 实际验证。**

- 没有记忆点，先改对象、构图与字形，不先加光效。
- 太拥挤，先删重复、合并信息或分阶段，不先缩字。
- 太空，先看缺少了什么必要关系，不先加统计与装饰。
- 不统一，先查素材、字阶、颜色职责与控件语法，不给全页套同一滤镜。
- 交互露馅，先补可观察状态与真实视图，不加更多成功 Toast。

## 六、实施、验证与研究边界

### 6.1 用设计关系建立变量系统

设计系统是当前页面选择的记录，不是提前限制所有产品的参数表。

- **颜色**记录底面、文字、边界、操作、选择、状态与数据角色。
- **字体**记录展示、阅读、数据的职责及必要回退。
- **间距**记录组内、组间、区域之间与控件内的相对档位。
- **轮廓**记录容器、输入、按钮、小标签与浮层的层级关系。
- **动效**记录哪些变化需要过渡、锚点在哪、终态是什么、减少动效如何表达。

同类组件复用一致规则，不需要提前做一整套通用组件库。当前页面用不到的抽象、主题与扩展能力不为未来假设增加。

### 6.2 还原与独立设计分开处理

- **还原任务**：实际查看具体参考，识别产品界面与外部展示包装，保留有效视觉语言；比例、素材、来源归档与补齐视图执行技能规则。
- **风格借鉴**：应用本文关系，用当前内容重新组织；不自动复制原稿尺寸、业务模块或整套代码，不自动触发还原归档。
- **修改既有页面**：保留已经有效的语言，先修当前问题；用户要求重构时才重新组织主线，不为求新随意换皮。
- **单组件任务**：范围限于组件自身必要交互与状态，不从品类常识扩展完整业务应用。

新增视图必须与当前产品逻辑一致，完整不等于行业功能全集。参考没有展示的必要流程可以推导，但要标清验证边界，不声称已看见原作未提供的状态。

### 6.3 可用性与可访问性独立验收

设计师画面提供审美证据，不提供自动免检资格。

- 正文、辅助信息、单位、状态与操作在实际尺寸可读。
- 控件热区与触控间距合理，键盘焦点清楚，状态语义完整。
- 图标、颜色与位置不是唯一的信息通道，必要信息有可理解文字或语义名称。
- 触控不依赖 hover，键盘不会进入消失的对象，浮层关闭后焦点有合理归宿。
- 加载不阻断无关任务，失败保留恢复信息，减少动效保留全部内容与功能。
- 长内容、缺图、无结果、字体回退与目标视口下不碰撞、不裁掉关键内容。

截图美观与代码合规是不同证据，两者都需完成。任何无法验证的部分如实说明。

### 6.4 动态参考的观察方法

研究动态资源时可按「初态 → 触发线索 → 变化过程 → 终态 → 再次操作」观察：

- 什么位置保持，什么位置移动？
- 图标、文字、形态和表面是否同时说明同一次状态变化？
- 对象身份是否连续，还是两个无关画面简单交叉淡入？
- 终态是否需要保持，展示循环是否只是便于观看？
- 镜头、样机与外部舞台的运动是否误当作 UI 运动？
- 快速反向、键盘、触控和减少动效是否仍需另行验证？

关键帧适合观察主要形态与位置变化；精确时序、微小过渡和快速连续操作需要更密采样或实际运行验证。不要将近似观察写成精确测量，不据帧图编造 easing 或 spring 参数。

### 6.5 不将纠错变成新的风格禁令

以下都不是通用结论：

- 所有产品必须浅色、中性色或只有一种强调色。
- 所有高级界面必须用衬线、窄体、等宽标签或英文。
- 所有卡片都应删除，或所有容器都应大圆角。
- 所有后台必须侧栏，所有概览必须 Bento，所有 App 必须单列。
- 所有首屏必须左文右图，或所有有设计感的页面必须叠字与错位。
- 所有控制都要拟物、形变、压感缩放与动画。
- 玻璃、渐变、强色、星形、轨道、纹理和 HUD 图形一律是 AI 味。

真正要拒绝的是**没有当前任务依据的默认组合**。有内容贡献的个性保留并精修；不可读、无关、碰撞和操作不清不能用「创意」辩护。

### 6.6 后续补充本文的写法

新增研究要转成可直接使用的指导：场景是什么，怎样安排对象和信息，什么关系产生效果，哪里不适用。不要增长项目清单、图片编号或推荐链接，也不要只写风格形容词。

同一原则已有案例时，优先补清边界或增加不同任务的关系；不重复多个只有配色差异的例子。研究范围与证据声明只记录实际完成的动作，不继承旧文档未经当前核验的「已通读所有源码」等表述。

### 6.7 与仓库其他规范的分工

- **`SKILL.md`「〇.1 硬约束清单」**：技术合规唯一权威，按选择器、DOM、样式与状态逐项举证。
- **`UI设计原则.md`**：层级、间距、排版、色彩、深度与图像的基础方法。
- **本文**：风格关系、四类容器的设计判断、组件语法、AI 组合错误、自包含案例与审美回归。

## 七、回归检查清单

完成后再次阅读本文与 `UI设计原则.md`，可先由标题与章节解释定位问题，拿不准回到相应维度细读。下面检查审美、内容与实际体验；技术合规另按硬约束 17 条逐项举证，不混成一套样式参数检查。

### 7.1 任务、范围与视觉方向

1. **当前任务**：首屏直接帮助用户这一步的判断与动作，还是先宣传产品有多强？
2. **内容减法**：重复解释、装饰性统计、无关模块和凑数入口是否真正删除？
3. **流程完整**：必要能力在整个流程可发现、可走通，是否误把完整理解成首页全展示？
4. **范围克制**：单组件有没有被扩成完整应用，概念展示有没有被加上无关业务工具？
5. **主导语言**：字体、影像、表面、图形与动作能否表达同一种性格，而非拼贴多个参考？
6. **独立推导**：去掉名称后，能否从对象与构图辨认品类，是否只是换色、换图和文案？
7. **参考理解**：具体参考是否实际看过，本文案例是否被理解为关系而非模板？

### 7.2 构图、排版与视觉细节

8. **第一落点**：主体与下一步清楚吗？有没有多个同权区域争抢？
9. **空间分配**：面积与任务相称吗？工作对象、比较数据和主素材是否被无关外壳挤压？
10. **对齐与节奏**：同类图片、名称、数字和控件有稳定边缘、基线与重复关系吗？
11. **留白与密度**：空隙能说明分组或观看停顿吗？有没有无用大空档与局部拥挤？
12. **字体角色**：展示、阅读和比较数据各司其职吗？实际语言、断行与回退是否成立？
13. **可读性**：正文、辅助字、单位和操作能读清吗？有没有以极小、极淡换精致？
14. **颜色职责**：品牌、内容、状态、数据和表面有清楚逻辑吗？多色是否有归属？
15. **素材**：题材、机位、比例、光线与色温相容吗？有没有重复图片冒充对象或视角？
16. **图文关系**：主图真正参与构图吗？叠排与裁切是否保留识别和操作？
17. **容器**：每个底板、边界与投影都有职责吗？同一对象是否仍层层套卡？
18. **材质与图形**：玻璃、拟物、纹理和品牌图形是否有贡献，还是在补结构问题？
19. **图标**：全站同源、视觉重量协调、两态清楚，陌生命令是否可发现？

### 7.3 组件、状态与动效

20. **导航与工具**：去哪里、看什么、对对象做什么是否分清？折叠后位置关系是否保留？
21. **动作层级**：主次、行内与危险动作权重合理吗？名称能预告结果吗？
22. **表单与选择**：标签、当前值、限制、选中、禁用和错误是否清楚，展开面板是否同源？
23. **列表与数据**：可比较列、单位、时间范围与基准完整吗？图表是否回答真实问题？
24. **反馈位置**：结果能在对象、行、按钮或工作区观察吗？是否只靠 Toast 宣告？
25. **恢复路径**：空、加载、失败、离线与重试保留上下文吗？有没有伪造业务成功？
26. **视图空间**：详情、编辑、列表与设置有合适视图吗？是否全部塞进相似弹窗？
27. **运动因果**：变化是否有明确原因、对象与锚点？有没有逐块淡入和无意义循环？
28. **中断与终态**：连续操作能衔接吗？持久状态保持吗？展示复位是否被误搬进产品？
29. **输入与减少动效**：触控、键盘、焦点与减少动效下，信息和功能是否仍完整？

### 7.4 实际验证与证据

30. **两个尺度**：既看过整体缩览，也看过实际阅读尺寸，而非只看漂亮缩略图？
31. **边界内容**：长名称、大金额、零记录、缺图、字体回退和关键状态是否检查？
32. **适配**：按当前容器规则验证目标视口，是否有碰撞、无效换行、裁切与多余缝隙？
33. **内容可信**：文案、图表、评分、促销、承诺与跨题材残留是否独立核验？
34. **研究诚实**：有没有把静态图、关键帧、旧源码或展示包装当成完整功能与精确参数的证明？
35. **规范分工**：是否另行完成硬约束 17 条代码举证与两份文档回归，未把本文误用成固定皮肤？

发现「一眼 AI」时，优先修内容、主次与构图，再修字体、素材和组件，最后处理动效。交付的理由不应是「用了很多高级效果」，而应是：**这个产品的对象更清楚，关系更有秩序，操作更容易，视觉更有辨识度，而且没有多余负担。**
