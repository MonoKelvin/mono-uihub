# 高品质 UI 原型设计

## 一、核心目标

**一切为了做出好看的产品界面，同时保证好用。**

交付应像成熟设计师完成的真实产品，而不是套模板、堆卡片、换配色的普通原型。重点关注整体气质、视觉层级、字体表现、构图、色彩关系、图形语言、动效和细节完成度。

- **审美优先，但不牺牲可用性**：视觉与功能共同设计，不以删减功能换取表面简洁。
- **风格由产品决定**：允许克制、精致、活泼、先锋、华丽或富有实验性，不把“高级简约”当成唯一答案。
- **大胆自主设计**：不要等待用户提供颜色、字体、布局和动画参数。理解需求后主动探索更好的方案。
- **拒绝模板感**：不默认使用常见 SaaS 布局、固定配色、统一卡片和千篇一律的组件组合。
- **独立推导**：不要机械复用上一轮的视觉方案；相同品类也应根据内容与定位形成自己的表达。

### 设计原则参考

设计判断可参考以下成熟原则，但不要照搬其示例或转化成固定参数：

- 视觉层级、比例、平衡、对比、格式塔与视觉焦点。
- 网格、构图、节奏、留白、统一性与品牌识别。
- 一致性、可发现性、渐进披露、反馈和可访问性。
- 字体性格、字形质量、阅读场景和字体组合。
- 动效的连续性、自然加减速、空间关系和交互反馈。

参考资料：
- [Nielsen Norman Group：Visual Design Principles](https://www.nngroup.com/articles/principles-visual-design/)
- [Figma：UI Design Principles](https://www.figma.com/resource-library/ui-design-principles/)
- [IBM Design Language](https://www.ibm.com/design/language/)
- [Apple Human Interface Guidelines：Motion](https://developer.apple.com/design/human-interface-guidelines/motion)

### 不复用已有页面

- 新页面不读取、不截图、不分析 `ui/` 下已有页面，不复制其 HTML / CSS / JS 作为起点。
- 不复用上一轮的颜色、字体、布局骨架、组件组合和动效参数。
- 只允许读取本技能、`skills/ui-metadata/SKILL.md`、`tools/` 用法说明及用户当次提供的参考。
- 用户明确要求修改已有页面时，只读取对应页面。
- 设计差异不能只靠换色、换文案或换图片；应重新思考信息结构和视觉表达。

## 二、先理解产品，再决定设计

先判断产品定位、目标用户、使用场景、内容特征和品牌气质，再确定视觉方向。不要将下面的分类当作模板，它们只是设计思路：

| 产品气质 | 可探索的设计表达 |
| --- | --- |
| 国际化 / 英文品牌 | 精简文案、富有表现力的字体、大尺度排版、字距与留白、摄影和符号 |
| 潮流 / 创意 / 年轻化 | 大胆构图、强烈字体个性、图标符号、几何图形、视觉化数字和灵活的色彩关系 |
| 专业工具 / 桌面软件 | 清晰的信息组织、精致的字体、舒适的信息密度、细腻的状态反馈和克制的色彩 |
| 科技 / AI / 数据产品 | 现代字体、数据可视化、结构图形、动态反馈和有辨识度的科技视觉 |
| 文化 / 艺术 / 内容品牌 | 编辑式排版、衬线或特色字体、摄影、材质感、留白和富有情绪的色彩 |
| 高端消费 / 生活方式 | 精致字体、产品影像、材质与光影、细节质感和克制但鲜明的品牌表达 |

可以混合不同方向，也可以提出更适合当前产品的原创方向。不要机械套用某种风格名称。

### 交付容器

| 类型 | 判断依据 | 外框与滚动 |
| --- | --- | --- |
| A 软件 | 后台、工具、仪表盘 | 完整窗口展示；长列表和长文局部滚动 |
| B 网页 | 品牌、落地、内容站、作品集 | 自然文档流；整页垂直滚动 |
| C App | 移动优先、点名 App / 手机 / 小程序 | 手机比例外框；只在框内滚动 |
| D 组件 | 播放器、灯箱、上传框等单一控件 | 按内容自然尺寸展示；内部局部滚动 |

用户点明就按用户要求，没点明按功能推断。容器只决定展示方式，不限制视觉风格。

### 容器设计要点

**A 软件**
- 让窗口、背景和内容形成完整的展示关系；外框服务于产品，不要为了悬浮效果添加多余装饰。
- 优先让主要信息和常用操作自然共存；复杂内容通过合理分区和局部滚动承载。
- 先做好空间分配和响应式布局，再决定滚动区域；不靠裁切、隐藏滚动条或整体缩放掩盖布局问题。
- 窄屏优先重排、分组和调整信息呈现，不得让核心功能消失。

**B 网页**
- 根据内容选择长页叙事、模块化浏览、沉浸式首屏或其他合适结构。
- 页面应有视觉节奏和内容层次，避免每个区块都重复同一种布局。
- 可根据叙事需要加入滚动驱动动画；不为满足规则而强行添加滚动效果。

**C App**
- 采用符合移动设备习惯的导航、单列或适合场景的布局和易操作控件。
- 弹层、Toast、下拉、日期选择器等覆盖层必须限制在 App 展示容器内，不得逃逸到视口。
- 对原生控件进行必要的视觉定制，但不得损害可访问性和操作体验。
- 触控区域、底部导航和内容滚动应符合真实移动端使用习惯。

**D 组件**
- 按组件用途和内容自然成形，不套用完整软件外壳。
- 重点设计空闲、悬停、聚焦、加载、完成、出错等状态。
- 所有状态变化应清楚、连贯且可理解。

## 三、设计流程

动手前读取 `skills/ui-metadata/SKILL.md`，按其规范在页面目录写入 `metadata.json`。

### 1. 明确设计任务

确定产品定位、用户场景、核心任务、信息优先级和首屏重点。先准备真实文案与合理数据，再设计呈现方式，避免空洞占位内容。

### 2. 确定视觉方向

用简短的设计说明明确本页的气质，不必填写固定格式或参数表。至少想清楚：

- 整体视觉印象与品牌性格。
- 排版、构图和信息层级如何表达内容。
- 字体如何建立个性与品质。
- 色彩如何建立氛围、识别和重点。
- 图标、图形、摄影或数据可视化如何参与表达。
- 动画是否能增强体验，以及应该采用什么动效语言。

### 3. 建立设计系统

根据当前页面需要建立 CSS 变量和可复用样式。颜色、字体、字号、间距、圆角、边框、阴影和动效应有一致的设计逻辑，但不强制固定数量、数值或比例。

**不要把设计系统变成限制创意的参数表。** 可以灵活调整，但每个选择都应服务于整体效果。

## 四、视觉设计重点

### 4.1 排版与构图

- 让用户一眼知道应该先看哪里，再自然理解其他信息。
- 利用字号、字重、字体性格、色彩、位置、留白和对齐建立层次，不依赖卡片和边框堆砌。
- 根据内容探索网格、非对称、错位、分栏、叠排、沉浸式、编辑式或其他构图。
- 允许大胆的大小对比、特殊断行和视觉张力，但整体必须协调、易读。
- 页面应有疏密、轻重和节奏变化，避免所有区域平均用力。
- 不要默认居中、对称、等宽卡片或相同的区块排列。
- 视觉设计应帮助用户理解和完成任务，而不是只追求截图效果。

### 4.2 功能与简约的关系

**功能完整与视觉美观必须共同实现。简约不是删功能。**

- 按产品品类提供用户合理期待的完整能力，不得为了让页面更空、更简单或更好截图而擅自删除功能。
- 先优化信息架构、功能分组、入口位置、交互流程和视觉表达。
- 使用渐进披露、上下文操作、快捷入口、图标化表达、菜单和抽屉等方式降低视觉负担。
- 高频功能应容易发现和操作；低频功能可以收纳，但不能无故隐藏到难以发现。
- 图标可以减少文字，但必须容易理解；重要操作必要时保留文字标签。
- 只有用户明确要求优先极简、删减冗余功能，或某项功能确实不属于产品范围时，才考虑删除，并说明原因。
- 功能入口、状态和反馈必须完整；不能只做视觉上存在、实际没有响应的控件。

### 4.3 文案与信息表达

- 界面不是说明书。能简洁表达就不要写长段解释，但不能为了少字损失必要信息。
- 英文品牌或国际化页面可使用精简词语、短标签、大字号文字和视觉化符号。
- 潮流、创意页面可以更多使用图标、符号、图形和视觉化数字；专业工具则优先保证信息清晰。
- 中文表达自然准确，不为装饰而硬塞英文或无意义缩写。
- 文案要具体、有信息量，避免空洞营销词、重复标题和自述式引导。
- 状态、趋势、流程、分类和比例可根据理解成本选择图标、图表、结构图或文字，不强制某一种表达方式。

### 4.4 字体设计（重点）

**字体是视觉设计的重要组成部分，不要把默认系统字体当成所有页面的最终方案。**

- 当用户提出高级感、设计感、品牌感、艺术感、潮流感等要求时，应主动寻找并尝试合适的艺术字体、展示字体或高品质字体组合，优先考虑可通过 CDN 引入的字体。
- 其他页面也应根据产品气质主动选择合适字体；只有长篇正文、密集信息或阅读优先场景，才优先使用稳定易读的常规字体。
- 标题、品牌字标、关键数字、正文和辅助信息可以采用不同字体性格，但组合必须协调，避免字体数量和风格失控。
- 英文可探索几何无衬线、人文无衬线、Grotesk、衬线、窄体、宽体、Display、手写或实验字体；根据品牌性格选择，不要默认 Inter。
- 中文可探索现代黑体、宋体、衬线、圆体、书写体和特色展示字体；展示字体适合标题与短文本，长正文仍应优先阅读体验。
- 数字字体要特别谨慎：追求精致、现代和协调，同时保证数字基线、字面高度、宽度、对齐和可读性。避免过度艺术化、上下错位明显或数字形态不统一的字体。
- 可以利用字重、字宽、字距、大小写、斜体、连字和断行形成设计感，不要只靠更换字体名称。
- 使用前检查字形覆盖、数字表现、加载速度、授权和 CDN 可用性，并设置可靠回退，避免字体加载失败导致布局错乱。
- 优先从 Google Fonts、Fontsource、ZeoSeven 等可靠字体资源中寻找合适字体。按需通过 CDN 引入，不要盲目加载大量字重和字符集。
- 设置合理的字体回退栈；字体未加载时也应保持布局稳定。

参考：
- [Google Design：Choosing Web Fonts](https://design.google/library/choosing-web-fonts-beginners-guide)
- [Google Fonts](https://fonts.google.com/)
- [Fontsource](https://fontsource.org/)
- [ZeoSeven](https://fonts.zeoseven.com/)

### 4.5 配色设计

不要固定使用某套色值、配色比例或强调色。先判断产品气质，再大胆探索合适的色彩关系。

可考虑高级灰、中性色、低饱和色、自然色、冷暖对比、品牌色、明亮撞色、深色奢华、单色体系等方向。色彩可以克制，也可以鲜明；重点是协调、层次、识别度和情绪表达。

- 颜色要有明确职责，背景、内容、文字、重点和状态之间形成清楚关系。
- 强调色不必固定为某种颜色，应根据品牌和页面内容选择。
- 可以使用渐变、透明、材质和光影，但必须有设计目的，不要把渐变、发光或玻璃效果当作默认高级感。
- 颜色对比必须保证文字和重要控件可辨识；不能为了氛围牺牲可读性。
- 不要因为追求低饱和或高级灰而让页面失去重点、层次和活力。

### 4.6 图标、图形与影像

- 图标、符号、几何图形、插画、摄影和数据可视化都可以成为主要视觉语言，不局限于文字和卡片。
- 根据产品气质选择图形风格，确保线条、比例、质感和表现方式协调。
- 功能图标优先易识别；品牌或创意图形可以更有个性。
- 不要混用风格明显不同的图标库，不用 emoji 代替正式功能图标。
- 图形必须有表达目的：帮助识别、解释关系、传递状态、塑造品牌或增强视觉张力。
- 影像应有明确的构图、色彩和内容逻辑，避免随意拼图或无关素材填充页面。

### 4.7 细节与完成度

- 关注字体渲染、字距、对齐、边界、图标比例、层级、交互状态和内容细节。
- 边框、分割线、阴影、圆角、纹理和透明效果按需使用，不为装饰而装饰。
- 组件之间既要保持一致，也允许关键区域拥有合理的视觉差异。
- 页面不能只有首屏精致，滚动区域、弹层、菜单、空状态和错误状态也要完整设计。
- 不要为了“像设计稿”牺牲真实使用时的可读性、可操作性和响应速度。

## 五、动画设计与实现

动画是 UI 设计的一部分，不只是给按钮添加 hover 效果。应根据产品气质和用户需求，主动判断动画在界面中的角色。

### 5.1 先判断动画需求

- 用户明确提出优秀动画、高级动效、流畅动画、炫酷、花哨、沉浸式、电影感、动态视觉或类似要求时，应将动画作为重点设计内容，主动使用 GSAP 等专业动画库实现复杂效果，不要只用简单 CSS transition 敷衍。
- 对品牌官网、创意展示、产品发布、作品集、互动叙事等适合动态表达的页面，可以主动设计有节奏的入场、滚动叙事、视差、文字动画、图形变形、遮罩揭示、分层运动和连贯转场。
- 对专业工具、后台和高频操作界面，动画应帮助理解状态、建立空间关系和提供反馈；可以精致流畅，但不能妨碍效率。
- 用户没有明确要求复杂动画时，根据产品气质适度设计，不要为了炫技添加无意义动效。
- 不要把所有元素做成同一种淡入上移，也不要让每个组件都独立表演。

### 5.2 动画质感

- **避免机械线性运动**：空间移动、缩放和界面转场通常采用自然的加速、减速、非对称缓动或弹簧效果。Linear 仅适合匀速旋转、进度、持续滚动等确有需要的场景。
- **使用有质感的缓动**：可根据运动距离、元素质量感和场景选择 ease-out、ease-in-out、power、expo、back、spring 等曲线；克制使用夸张弹性，避免廉价的反复弹跳。
- **适当加入阻尼感**：大面积面板、浮层、拖拽、跟随、磁吸和空间转场可以有惯性、阻尼、回弹或弹簧感，让动作更自然。
- **动作要有因果**：进入、离开、展开、收起、切换、拖动和状态变化应符合用户对空间和物体的直觉。
- **编排要有节奏**：可以使用错峰、重叠、连续衔接和分层运动，但要有主次，不能所有元素同时乱动。
- **动画应响应内容和操作**：避免无意义的永久循环、持续漂浮和抢夺注意力的背景动画。
- **性能优先**：优先使用 transform、opacity 等适合合成的属性；复杂滤镜、模糊和大面积实时效果需谨慎，避免掉帧。

### 5.3 复杂动画优先考虑 GSAP

当页面需要复杂入场、滚动叙事、时间轴编排、连续转场、交互驱动、拖拽跟随或多元素协同时，优先考虑 GSAP。

- 使用 GSAP Timeline 管理一组相关动画，利用标签、重叠、嵌套和回调组织节奏，不要靠大量互不关联的 delay 拼接。
- 需要滚动驱动时使用 ScrollTrigger；需要平滑滚动、逐字逐行、路径运动或翻转过渡时，再按需选择相应插件。
- 简单状态反馈仍可使用 CSS transition / keyframes；不要为了使用库而引入库。
- 按需通过 CDN 引入，并遵循第八节的技术约定。
- 动画应模块化管理，便于播放、暂停、反向、重置和清理。

### 5.4 连续操作、打断与恢复

**交互动画必须考虑用户连续操作。不要因为新操作到来就粗暴终止所有动画，也不要让动画状态与真实 UI 状态脱节。**

- 用户在动画过程中再次点击、切换、拖动或触发其他动作时，界面应从当前视觉状态自然衔接到新的目标状态，不闪烁、不跳回初始位置。
- 同一元素不同属性的动画尽量互不干扰；只处理真正冲突的属性，不要无差别清除整个目标的所有动画。
- 对展开 / 收起、打开 / 关闭等可逆状态，优先复用同一 Timeline，通过 `reverse()`、`play()` 或进度控制实现自然反向，而不是重新从初始状态播放。
- 对用户不断改变目标值的交互，使用可更新目标的动画方式，让运动跟随最新输入。
- 多个动画序列需要衔接时，使用 Timeline、嵌套 Timeline、回调或状态机管理；不要在多个事件中创建互相争夺同一属性的独立动画。
- 明确区分“继续当前序列”“反向播放”“从当前状态转向新目标”和“并行执行其他属性动画”。根据交互语义选择，不能简单地一律追加或一律终止。
- 不要随意调用 `killTweensOf()`、`kill()` 或使用全局 `overwrite: true` 清除动画。GSAP 的 `overwrite: "auto"` 可以处理同一目标上发生冲突的属性，同时保留不冲突的动画；仍需合理规划动画归属。

### 5.5 GSAP 交互示例

以下示例说明可逆面板如何在动画尚未结束时响应下一次点击。反向播放会从当前进度自然返回，不必重新创建动画。

```html
<script src="https://cdn.jsdelivr.net/npm/gsap@3/dist/gsap.min.js"></script>
```

```js
const panel = document.querySelector(".panel");
const toggle = document.querySelector(".toggle");

// 设置面板初始视觉状态，确保首次展开时有明确的起点
gsap.set(panel, {
  autoAlpha: 0,
  y: "1em",
  scale: 0.98,
  transformOrigin: "center top"
});

const panelMotion = gsap.timeline({
  paused: true,
  defaults: { ease: "power3.out" }
});

panelMotion
  .to(panel, {
    autoAlpha: 1,
    y: 0,
    scale: 1,
    duration: 0.65
  });

let isOpen = false;

toggle.addEventListener("click", () => {
  isOpen = !isOpen;

  // 动画进行中再次操作，从当前进度自然反向或继续
  panelMotion.reversed(!isOpen).paused(false);
});
```

对连续变化的目标值，可以使用 `gsap.quickTo()`，避免每次输入都创建大量互相竞争的动画：

```js
const moveToX = gsap.quickTo(".cursor", "x", {
  duration: 0.7,
  ease: "power3.out"
});

window.addEventListener("pointermove", (event) => {
  moveToX(event.clientX);
});
```

对需要多个阶段的动画，应优先维护一个明确的 Timeline；新操作改变目标时，更新或反向现有序列。只有确实发生属性冲突时，才覆盖冲突部分。

### 5.6 无障碍与性能

- 尊重 `prefers-reduced-motion: reduce`，为用户提供减少动态效果的方案；减少动画时，信息和功能仍必须完整。
- 不用动画隐藏关键内容或延迟用户必须立即获得的信息。
- 避免高频闪烁、快速大幅缩放和可能引起不适的视差。
- 滚动动画不能影响正常滚动、键盘操作和触控操作。
- 页面离开或组件销毁时，正确清理事件监听器、ScrollTrigger 和不再需要的动画实例。
- 首屏重要内容不能依赖动画库加载完成后才显示。

## 六、素材

**统一用 `tools/resource-getter/get.py` 取素材**，不要手拼站点 URL，也不要在页面里散落一堆来源不明的外链。完整来源矩阵、许可与故障排查见 `tools/resource-getter/README.md`。

### 选型优先级

1. **透明矢量插画**：unDraw / Storyset / DiceBear / Doodle Ipsum
2. **抠图 PNG**：Pixabay（`--transparent`）/ pngimg
3. **摄影**：Pixabay / Picsum / Unsplash / Pexels
4. **手绘 SVG**（几何、装饰、图表）
5. **AI 生图**（最次，规则见下）

**默认热链，慢则落盘。** `get` 的 `auto` 模式会实测 TTFB：> 0.9s 或读取 > 2.5s 判定为慢，必须下载到 `ui/<page>/assets/`；再快也别把二十张远程大图堆进首屏。

```bash
# 透明 SVG 插画
python tools/resource-getter/get.py search undraw "developer" --limit 5
python tools/resource-getter/get.py get undraw "developer" --page <page>

# 透明插画 / 抠图 PNG
python tools/resource-getter/get.py get pixabay "fox" --type illustration --transparent --page <page>
python tools/resource-getter/get.py get pngimg "fox" --page <page>

# Storyset（免费版需署名）
python tools/resource-getter/get.py get storyset "developer" --style rafiki --page <page>

# 占位插画（会自动换成可复现的静态 URL）
python tools/resource-getter/get.py url doodleipsum --width 700 --height 1244 --style avatar --page <page>

# 头像 / 抽象图形
python tools/resource-getter/get.py url dicebear --style shapes --seed mono --page <page>

# 先看延迟再决定
python tools/resource-getter/get.py probe <url>
```

`--page` 自动建 `ui/<page>/assets/` 并打印 `<img src="./assets/...">`；`--mode hotlink` 只输出 URL，`--mode download` 强制落盘，`--force` 覆盖同名文件。

### 透明底 / 不要方框

- **unDraw** 有稳定直链 `https://cdn.undraw.co/illustration/<slug>.svg`，但每张都带一层满幅 `#f8f8f8` 背景；resource-getter 会自动移除（保守判定，覆盖不到 97% viewBox 就不动）。`--no-strip-bg` 可保留。
- **Storyset** 返回透明 SVG（`stories.freepiklabs.com`），免费使用需署名 `Illustration by Storyset`。
- **Doodle Ipsum** 用 `?bg=transparent`；裸 URL 每次刷新换图，`get` 会跟随一次 307 并缓存 `?i=` 静态地址。
- **DiceBear** 的 `backgroundColor=transparent` **必带**，否则默认给一个纯色圆/方底。
- **Pixabay** 的 `--transparent` 先按 `transparent` 标签过滤，没有标签命中时对前 8 条候选只取 64 字节做 PNG IHDR alpha 检查。
- **pngimg** 是原生抠图 PNG，但许可是 **CC BY-NC 4.0**，只用于原型演示。
- 换主色：unDraw 直接 `--recolor '#c8a24a'`（替换 `#6c63ff`）；其他 SVG 用 `--from-color '#6c63ff' --recolor '#c8a24a'`。

### 许可红线

- **可商用**：unDraw、Pixabay、Doodle / Blush、Unsplash、Pexels、Picsum。
- **需署名**：Storyset / Freepik（去署名需 Flaticon Premium）。
- **禁止商用**：pngimg（CC BY-NC 4.0，需署名）、Pixiv 作品（作者版权，仅私人参考）、Pravatar（来源授权不明确，仅原型）。
- unDraw 不得打包转售、不得用于训练模型；Pixabay / Unsplash / Pexels 不得原样转售。

**已确认拿不到稳定直链，不要再用**：`illustrations.popsy.co`（连接超时）、`popsy.co`（530）、`svgrepo.com/show/*.svg`（429 限流）、`cdn.jsdelivr.net/gh/realvjy/illustrations`（404）、`botanimals` 风格（404）。`api.iconify.design/undraw:*` 仍是 404，但 unDraw 官方 CDN 直链可用，走 resource-getter 即可。

### 图标

只用 **Tabler Icons** 一套，不混其他图标库，不用 emoji 当功能图标。图标名在 `https://tabler.io/icons` 查。每个图标都有 **线性（outline）** 与 **实心（filled）** 两种形态，按状态选用。

**1. 线性（outline，默认态）**

最省事用 webfont：

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@tabler/icons-webfont@3.49.0/dist/tabler-icons.min.css">
<i class="ti ti-flask"></i>
```

线宽（stroke）**由加载哪套样式表决定，全站统一选一种**，不要在同一页切样式表混用：

| 样式表 | 线宽 | 适用 |
| --- | --- | --- |
| `tabler-icons.min.css` | 2（默认，偏厚重） | 大号展示图标、需要存在感时 |
| `tabler-icons-300.min.css` | 1.5 | **推荐**：轻盈精致，多数 UI 通用 |
| `tabler-icons-200.min.css` | 1 | 极细，适合小图标、高密度工具栏 |

> 多数界面用 1–1.5 比死用 2 更好看。若同一页确实需要两种线宽（如大号 hero 图标 2、列表小图标 1.5），**改用内联 SVG 单独控 `stroke-width`**，不要切 webfont 样式表。

**2. 实心（filled，激活 / 选中 / "开"态）**

线性图标在激活态经常"看不出变化"——**收藏、书签、星标、tab 选中、开关打开、已读**这类必须有可见状态差异的，一律用实心，否则状态不可见（这是最常见的"激活态不显示"根因）。三种取法按场景选：

- **React / Vue / 组件项目**：导入实心组件，命名为「同名 + `Filled`」后缀，例如 `IconHeart` → `IconHeartFilled`、`IconKey` → `IconKeyFilled`；线宽用 `stroke={1.5}`（或 `strokeWidth`）单独调。
- **纯 HTML 原型**：webfont 的实心是另一套字体（`tabler-icons-filled.min.css`），与线框共用 `ti ti-<name>` 类名但字形码不同，同一页混排易冲突。**最稳的做法是直接内联 SVG**——在 tabler.io 切到 *Filled* 标签页取该图标 SVG：激活态 `<svg … fill="currentColor">`（实心），非激活态 `<svg … fill="none" stroke="currentColor" stroke-width="1.5">`（线框）。同一图标两态各留一份 SVG，按状态切 class。
- **成对设计**：凡是带"开 / 关"语义的图标（heart / star / bookmark / bell / check / eye / lock 等），都准备 outline + filled 两份，激活时切 filled；实心**只**出现在激活 / 选中态，不滥用。

**3. 统一原则**

全站图标统一字号与颜色；线性态统一一种线宽（可因图标大小在 1–1.5 间微调，不必全程锁死 2）；实心仅用于激活 / 选中态。图标必须承载信息，不做纯装饰。

### AI 生图（最次选项）

仅当素材**既无在线替代、又超出手绘 SVG 能力**时使用（复杂拟物图标、风格化立绘、需要透明底的精细图形）。能用 10 个以内 SVG 基本形状拼出七八成像的，一律手绘。

```bash
python tools/image-forge/generate.py --style lineicon \
  "a sci-fi HUD line icon, single cyan stroke, hexagonal frame" \
  ui/<page-name>/assets/icon-hud.png
```

- 必须先有本地 `.env`（`IMAGE_API_BASE_URL` / `IMAGE_MODEL` / `IMAGE_API_KEY`），且页面目录下没有 `assets/`。
- `--style` 必填：`lineicon` / `skeuomorphic` / `illustration` / `render3d` / `iso25d` / `anime` / `chibi` / `photoreal` / `product` / `cinematic` / `stylized` / `guofeng`（`--list-styles` 查全表）。
- 提示词只写主体、材质、光。**不写** `ultra detailed` / `8k` / `masterpiece`，它们是噪点与碎片感的来源。干净词由 `skills/image-purify/purify.json` 自动叠加。
- 单页不超过 5 张；要更多必须先向用户说明清单与理由。
- 生成一次就用，不回读分析、不反复重生成。`--dry-run` 可先看拼好的提示词。

## 七、交互与功能：功能做全，呈现做简

**判断标准**：功能完整度按**产品定位、目标用户和品类常识**判断，不按个人兴趣，也不为凑数堆功能。做文档编辑器，就要让用户能完成真实编辑任务；做后台，就要覆盖目标工作流中的必要操作。不能为了画面简洁而省略用户合理期待的核心能力。

**必须做到**

- 先梳理当前产品真正需要的功能，再设计布局；每项纳入范围的功能都应有入口和真实响应。
  - 软件：按品类考虑创建、导入导出、编辑、查找、视图、设置等常见能力，不适用的功能不强加。
  - 网页：按场景考虑导航、内容浏览、搜索筛选、表单校验，以及空、加载、失败等状态。
  - App：确保核心任务流程完整，并考虑导航、返回、手势、列表详情、表单和通知等场景。
  - 组件：覆盖适用的状态变化，如空闲、悬停、聚焦、加载、成功、失败和禁用，并支持必要的键盘操作。
- **核心流程要能从头走通**：原型优先用本地数据在前端完成，不依赖后端。
- **状态齐备**：空 / 加载 / 失败 / 成功 / 禁用，每个列表、表单、异步操作都要考虑。
- **每个可见控件都要有响应**：点击、悬停、切换、展开、弹层、Toast、复制、筛选、增删。

**怎么做到功能多而界面简**

- **分组**：工具栏按任务分 tab，一屏只露一组；低频功能进二级菜单。
- **渐进披露**：设置项先给默认值，细节藏进浮层 / 抽屉 / 更多菜单，用到了才展开。
- **上下文出现**：选区浮条、右键菜单、行内操作，只在相关时出现。
- **一器多用**：一个下拉承载多个值，一个按钮带菜单，一个面板切换多种视图。
- **键盘**：常用操作给快捷键（⌘S / ⌘F / ⌘B 等），界面上就可以少放按钮。

**不许做**

- 加与产品无关的功能来凑数（记账 App 里的天气、文档编辑器里的股票行情）。这是"功能多"的唯一反例。
- 不伪造业务成功：不要弹出假的"支付成功""已上传至服务器"。
- 不把业务数据写进 localStorage / sessionStorage / IndexedDB——刷新即回到初始演示状态。只有 UI 偏好（主题、动效开关）可缓存。

**复杂逻辑怎么办**

- 前端能模拟的就模拟：本地数据、假延迟、真实的状态流转。
- 模拟不了的（真实支付、真实上传、服务端协作），**入口保留、操作有响应**：一句"需要连接服务"提示，或本地降级（如导出文件代替云端保存）。
- 不许因为实现麻烦就把功能删掉，也不许留一个点了没反应的死按钮。

**与视觉冲突时**

先调整信息架构和呈现方式，例如分组、收纳到菜单、改为上下文操作，而不是删功能。只有用户明确要求删减，或功能确实不属于产品范围时，才考虑移除，并说明原因。

**分寸**

- 优先使用简洁的原生 JS 或 Alpine.js；避免无必要的抽象、框架化和过度设计。
- 交互本身也要有质感，动效遵循第五节规范。

## 八、技术约定

- HTML / CSS / JS 实现。内容多时拆为 `index.html` + `styles.css` + `app.js`。
- **第三方库只走 CDN、零构建**：GSAP 全家桶、Lenis、Alpine.js。按需引，能不引就不引；**禁 React / Vue / Tailwind / Next**，也不下载到本地。
- 颜色、字号、间距、圆角、阴影先定义成 CSS 变量，之后一律引用变量。
- 语义化标签；可见焦点态；必要的 `aria-*`；对比度达标。
- 桌面与窄屏两档响应式，窄屏重排而非横向滚动。
- 页面输出到 `ui/<page-name>/`，英文 kebab-case，不超过 4 个单词；`metadata.json` 按 `skills/ui-metadata/SKILL.md` 归档。

## 九、视觉质量检查

### 必须避免

- 不理解产品就套用常见 SaaS 模板、默认字体和默认配色。
- 为了简约擅自删除用户需要的功能、信息和操作入口。
- 所有内容都卡片化，卡片里再套卡片；用边框和阴影代替排版层级。
- 所有文字大小相近、缺少重点，或只靠颜色变化制造层级。
- 为了“高级”而过度留白，导致页面空洞、信息不足或操作不便。
- 为了“丰富”而堆叠渐变、发光、玻璃拟态、随机几何碎片和装饰图标。
- 使用不适合产品气质的默认字体；艺术字体滥用在长正文或影响数字对齐。
- 只关注静态截图，不设计滚动区域、弹层、菜单、空状态和错误状态。
- 所有动画都使用线性运动、统一淡入，或使用大量互相冲突的独立动画。
- 动画过程中重复操作导致跳帧、闪烁、回到初始位置或状态错乱。
- 为追求视觉效果牺牲可读性、可访问性、性能和真实操作体验。
- 使用假数据、空洞营销词、重复文案和无响应的装饰性控件。

### 交付前自检

1. **产品定位**：视觉语言是否符合产品气质，而不是套用通用模板？
2. **整体审美**：构图、排版、字体、配色、图形和影像是否形成统一且有辨识度的整体？
3. **字体**：是否主动选择合适字体？标题是否有设计感？正文是否易读？数字是否协调、对齐？
4. **功能**：产品应有的功能是否完整？是否通过更好的组织方式兼顾功能与美观？是否有死按钮？
5. **信息层级**：重点是否突出？内容是否易于理解和查找？
6. **动效**：运动是否自然？复杂动画是否有时间轴管理？连续操作能否平滑衔接、反向或更新目标？
7. **细节**：图标、边界、层级、对齐、状态和素材是否精致统一？
8. **适配**：不同视口、缩放和输入方式下是否仍然清晰可用？
9. **无障碍与性能**：减少动态效果时是否仍然完整？是否存在明显掉帧或操作阻塞？

最后整体审视：去掉无意义装饰和重复表达，保留必要功能与信息。若画面仍显普通，应重新推敲构图、字体和视觉语言，而不是继续堆卡片、渐变或阴影。

## 十、交付

- 交付前检查文案、字体加载、排版、状态、响应式布局和交互连续性。
- 核心流程可在本地前端完成；不能真实实现的服务端功能，应明确提示，不伪造业务成功。
- 默认不自测：不起本地服务、不截图、不跑测试，只做代码层审查，然后交付让用户双击 HTML 查看。仅当用户明确要求时才执行。
