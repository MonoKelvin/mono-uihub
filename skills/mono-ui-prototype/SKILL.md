# 高级简约 UI 原型

## 一、唯一目标

**把界面做好看。** 验收只有一条：它是否像一个有审美的设计师做的成品，而不是"功能齐全的线框刷了层颜色"。

三条不可协商：

1. **风格固定为高级简约**：克制、留白、层级清晰、细节统一。这是本技能的默认基线，不是"看情况下菜"的选项。
2. **表现层决定成败**：排版、文字、字体、配色、动画。这五项垮掉，功能再全也只是功能清单；这五项立住，界面才有产品感。
3. **每次从零推导**：见下节。

两条交付倾向：

- **功能要全，界面要简**："简约"指布局、视觉、交互的克制，**不是把功能删掉**。按品类把用户期待的能力都做出来，用分组、渐进披露、浮层收纳来控制视觉密度。只有会直接破坏画面质量、且无法重新设计的功能才可以去掉。见第七节。
- **界面不是文档**：除非用户明确要求"以文字为主"（文章页、文档站、说明页），否则默认少写字——能用一个图标、一个形状、一张示意图说清的，就不写句子。细则见 4.2。

### 严禁参考已有项目

生成任何新页面前：

- **不读取、不截图、不分析** `ui/` 下已有页面，**不复制**其 HTML / CSS / JS 作为起点。
- **不复用**上一轮的颜色、字体、布局骨架、组件写法、动效参数。品类相同也必须重新推导。
- 只允许读取：本技能、`skills/ui-metadata/SKILL.md`、`tools/` 用法说明、用户当次提供的参考。
- 唯一例外：用户明确要求修改某个已有页面，此时只读那一个。

"不一样"不能只靠换色、换文案、换图。信息层级、构图秩序、字体气质、质感手法，至少三项要重新决定。

## 二、交付形态：先定容器

| 类型    | 判断依据                    | 外框          | 滚动             |
| ----- | ----------------------- | ----------- | -------------- |
| A 软件  | 后台、工具、仪表盘               | 居中窗口 + 柔和投影 | 页面不滚，长列表/长文局部滚 |
| B 网页  | 品牌、落地、内容站、作品集           | 文档流         | 整页垂直滚动         |
| C App | 移动优先、点名"App / 手机 / 小程序" | 手机比例外框      | 只在框内滚          |
| D 组件  | 播放器、灯箱、上传框等单一控件         | 自然尺寸居中      | 内部局部滚          |

用户点明就按用户的，没点明按功能推断。**类型只决定外框与滚动模型，不决定视觉风格。**

### A 软件

- 整个界面收进**一个窗口组件**：大而柔的悬浮阴影、适度圆角，窗外一层中性背景衬托。
- 窗口控制按钮可以不做；要做只做极简三点。
- `overflow: hidden`，一屏容纳主要操作、图表与概览。
- **先调布局，再谈滚动**：先按视口分配区域高度，再调留白、间距、控件尺寸、栏宽比例；用 flex / grid 弹性空间 + `min-width: 0` / `min-height: 0`。禁止固定高度堆叠后交给滚动兜底。
- 只有长列表、长正文、确实较多的内容允许区域内 `overflow: auto`；不预设常驻滚动条，不嵌套滚动。
- 不许用隐藏滚动条、裁切内容、整体缩放来假装"一屏装下"。窄屏优先重排、分组、隐藏次要信息。

### B 网页

- 常规文档流，允许垂直滚动。
- **至少一段滚动驱动的内容**：区块出场、分层视差、pin 住一屏。用 CSS + IntersectionObserver 即合格，不必上库。
- 节奏：首屏抓人，往后一段段有呼吸、有高潮，长页不塌。

### C App

- 手机比例外框（`aspect-ratio: 390 / 844`），大圆角 40–48px，居中悬浮 + 柔和阴影，像一台立在桌面上的手机。
- 移动端规则：单列布局、大触控目标、底部 Tab、顶部导航、拇指热区。滚动只发生在框内。
- **所有覆盖层必须活在手机框内**：弹层、Toast、下拉、日期选择器一律写在手机容器里，`position: absolute; inset: 0` 相对手机框定位。
  - 禁止 `<dialog>` + `showModal()`、`position: fixed`、portal 到 body、`popover` 默认定位——它们会逃到视口。
  - 遮罩与背景模糊只覆盖手机框内部；框外背景**不得**变暗、模糊或出现遮罩。
  - 弹层宽高用 `calc(100% - 2×内边距)` 收口，内容超高在卡片内部滚动。
- 不用浏览器原生控件：`<select>`、number 的 spinbox、date / time 系统面板、原生 checkbox 全部自绘。金额用 `inputmode="decimal"` 文本输入并自行校验。
- 悬浮 Tab Bar：左右留 14–18px、距底 12–16px、`border-radius: 999px`、半透明 + `backdrop-filter`；单色线性图标、`aria-label` 兜底、容器 `overflow: hidden` + 每格 `minmax(0, 1fr)`。内容底部预留 90–100px。

### D 组件

- 单一功能控件按**内容自然尺寸**成形（给一个合理最大宽度），居中浮在中性展示台上，带柔和阴影与圆角。不套软件外壳，不铺满视口。
- 力气全压在**状态**：空闲 / 加载 / 进行中 / 完成 / 出错 / 悬停 / 聚焦，用克制过渡衔接。组件的高级感就藏在状态里。
- 窄屏自适应收窄，但始终是有边界的一块。

### 尺寸：默认夹值，不溢出、不写死

A / C / D 这类有外框的单屏容器，尺寸取"理想值 ∧ 视口值，再兜一个下限"：

- 宽 `clamp(720px, 92vw, 1360px)`；高 `clamp(560px, calc(100vh - 96px), 840px)`。
- App 用 `aspect-ratio` 锁比例，高 `min(844px, 100vh - 80px)`，宽等比缩放；矮屏不出界。
- 用户点名尺寸就按用户的，不随视口变。
- 低于下限靠重排，不靠裁切或缩字。

## 三、流程（每次走完，不许跳）

动手前读 `skills/ui-metadata/SKILL.md`，按其规范在页面目录写 `metadata.json`。字段只在那边定义，这里不复述。

### 第 1 步 · 想清楚（不写代码）

- **品类与场景**：哪类页面，用户在什么设备上看，来这一屏要看什么。
- **一件任务**：这一屏要让用户完成什么。
- **首屏主角**：最重要的一样东西（一个数字、一张图、一句话、一个操作）。只许一个。
- **真实内容**：先写出真实文案、真实数据、真实人名，再排版。内容假，设计必然假；但宁少勿多——一条具体信息胜过三段概述。

### 第 2 步 · 写方向卡（5 行，写完才能动手）

方向不是选风格流派，是在高级简约内部换气质。只有四个变化轴：

- **字体性格**：冷静几何 / 中性人文 / 编辑衬线
- **底色温度**：骨白 / 冷灰 / 暖灰 / 石墨近黑
- **构图秩序**：严整网格 / 松散编辑感 / 单栏沉浸
- **质感来源**：发丝线 / 明度分层 / 影像 / 数据可视化

```
定位：像 ___ 一样 ___          ← 一句话，具体，不许写"现代简约大气"
底色：___ + 唯一强调 ___
字体：主 ___ / 展示 ___ / 数据 ___
构图：___（主角占位 + 网格选择）
动效：CSS 还是 GSAP，一句基调
```

不要把"复古印刷 / 野性排版 / 几何构成主义 / 暗色驾驶舱"当菜单挑。这些与高级简约相斥，且最容易做廉价。

### 第 3 步 · 锁死 token

一次定完，之后所有 CSS 只引用变量：

- **色**：底 / 面 1–2 / 墨 3 档 / 强调 1 / 语义（可选）
- **字**：主字族 + 展示（可选）+ 数据（可选）；5 级字号，2 级行高
- **间距**：4 或 8 基数，6–8 档
- **圆角**：一套（0 / 12–16 / 999，三选一）；**阴影**：一套，染底色色相

页面里出现第 3 个强调色、第 4 个圆角值、第 5 种间距，就是失控。

### 第 4 步 · 构建

表现层按第四节，动效实现按第五节，交互按第七节。

### 第 5 步 · 自检

按第十节逐条过，能数的数，不凭感觉。

## 四、表现层：五个决定成败的维度

### 4.1 排版：靠间距和对齐，不靠边框

**原则**

- 一屏一个主角，其余主动退后（降字号、降饱和、减装饰）。不是所有元素平等。
- 层级用**字号跨度 + 字重 + 颜色**建立，不用卡片和分割线堆。
- 间距成体系且**不均匀**：首屏 > 章节间 > 段内。等距 margin 是最明显的"没设计"。
- 强对齐：左右边界永远落在同几条线上。

**正例**

- 首屏标题 `clamp(2.6rem, 5vw, 4.4rem)` / `line-height: 1.02` / `letter-spacing: -.03em`；正文 `16px / 1.65` / `max-width: 62ch`。
- 区块间距 120px，区块内 32px，条目间 12px，三级递减。
- 表格数字右对齐 + `tabular-nums`，列宽按内容分配。
- 不对称构图：左侧 7 栏标题，右侧 5 栏留白或副文，视线有明确入口。

**反例**

- 标题 32px、行高 1.5、字距 0，和正文只差一点。
- 正文占满 1400px 宽，一行 120 个字符。
- 所有区块 `margin: 24px 0`，从上到下一样密。
- 每个区块都套一张卡，卡里再套卡。
- 每个标题上方都挂一个 ALL-CAPS 小眉标。

### 4.2 文字：写得少，写得具体，能图形化就不写

**第一原则：界面不是文档**

- 用户没要求"以文字为主"，就不出现成段说明、解释性引导、功能介绍堆叠。
- **删字测试**：这段话删掉，用户还能完成任务吗？能删就删。删了会歧义，先想能否用图标 / 图示解决；仍不行，才留一句话。
- **每屏文字预算**：1 个标题 + 最多 1 句副文（≤ 24 字）+ 界面标签。正文段落只属于内容页（文章、详情、帮助）。
- **不重复**：副文不复述标题，卡片描述不重复卡片名，同一信息不在两处出现，标签不解释自己。
- 一句话能说完的，不拆成三行碎片；能放进控件的，不单独起一段。

**图形替代清单**

| 要表达 | 用图形 | 不要用 |
| --- | --- | --- |
| 状态 | 色点 / 图标 + 2–4 字 | "当前状态为进行中，请耐心等待处理" |
| 趋势 | sparkline、迷你柱、刻度 | "较上周增长 12.4%，环比上升" |
| 流程 / 步骤 | 节点连线、stepper、时间轴 | 一段流程说明 |
| 分类 / 能力 | 图标宫格、图例 | 三张卡、每张一段"功能特点" |
| 空状态 | 单色线稿插画 + ≤ 12 字 + 一个按钮 | 两行解释 + 若干建议 |
| 关系 / 结构 | 简单 SVG 示意、树、矩阵 | 文字罗列从属关系 |
| 比例 | 环形、条、点阵 | 单独一句"占总量的 63%" |

**图形的要求**

- 图标只用 Tabler 一套（见第六节），统一线宽与尺寸，必须承载信息，不做装饰。
- 插画用手写内联 SVG：单色线稿、1.5–2px 线宽、统一端点与圆角，尺寸 120–200px。这种简单图形不要用 AI 生图。
- 图形与文字二选一，选一眼看懂的那个。**唯一例外**：当排版本身（大字号、精确字距、讲究的断行）比图形更有表现力时，保留文字——那是设计，不是偷懒。

**要写就写具体**

- 正例：状态"3 单待发货，最迟周四 18:00 前出库"；数据"47.2%""¥1,284.50""2 小时 14 分"；名称"陈砚舟""青禾工作室"；空状态"还没有收藏。看到想留的，按 ⌘D 存进来。"；按钮"保存草稿""发送邀请"。
- 反例："一站式解决方案，赋能业务全链路增长"；"99.99% 用户满意"；"示例标题""Lorem ipsum"；"张三""Acme""智某某科技"；按钮写"提交""确定""点击这里"；"在这里你可以管理你的全部项目"这类自述式引导。

### 4.3 字体：最多三种，各有职责

- **主字族 1 种**，承担正文与全部 UI。
- **展示字族 0–1 种**，只用于 h1、字标、超大数字。
- **数据字族 0–1 种**（等宽），只用于金额、时间、ID、坐标、代码，并开 `tabular-nums`。
- 合计**不超过 3 种**。同族不同字重 / 字号不计数，系统兜底不计数。
- 中文正文优先 `"PingFang SC", "Microsoft YaHei", "Source Han Sans SC"`；中西混排时，衬线或展示体只留给拉丁字母与数字，中文走无衬线。
- 要强调标题里的某个词，用**同族斜体或加粗**，不要塞一个异族字体。
- 大标题收紧字距（`-.02em` 到 `-.03em`），小标签适度放开（`.04em`–`.16em`），正文行高 1.5–1.7。

**正例**：主字族 `Archivo`，数据 `IBM Plex Mono`；h1 用同族 600 字重 + 收紧字距。

**反例**：默认 Inter 直接上；一页 4 种字体；无衬线标题里插一个衬线词；中文正文用宋体；数字不用等宽导致列宽跳动。

字体在线引入（CDN，绝不下载）：

```css
/* 拉丁：Google Fonts */
@import url("https://fonts.googleapis.com/css2?family=Archivo:wght@400;500;600&display=swap");

/* 中文 / 特色字体：ZeoSeven，ID 与 family 必须取自字体详情页的真实值 */
@import url("https://fontsapi.zeoseven.com/628/main/result.css");
:root { --font-display: "USMCCyuanjiantecu", "PingFang SC", system-ui, sans-serif; }
```

ZeoSeven 的字体多为单一字重的展示体：用 `font-weight: normal`，只放在大标题 / 字标 / 大数字，正文另选易读字体。始终配好系统兜底栈。

### 4.4 配色：一个强调色，一个落点

**原则**

- **结构**：中性底（带微色温）+ 墨色 3 档 + 强调 1 + 语义色（少量、去饱和）。
- **比例** 60/30/10，越接近 90/7/3 越高级。强调色只落在**主操作**和**一处关键数据**上。
- **不用纯白纯黑**：骨白 / 暖灰 / 冷灰 / 象牙，或中性石墨近黑。层级用相近明度的面叠出来，不靠粗边框。
- **默认走高级中性**：黑白灰 + 莫兰迪。让照片、数据本身成为唯一彩色，是摄影、作品集、编辑、专业工具最稳的解。
- **但全页没有强调落点同样是失败**：会显得没做完。至少留一枚——一个按钮、一条线、一个数字。
- **对比度**：正文 ≥ 4.5:1，大字 ≥ 3:1。弱化文字也要能读，不要为"高级"把灰字调到看不清。

**正例**

- 浅色：底 `#F6F4EF`，面 `#FBFAF7`，墨 `#1B1A17 / #56534C / #8B877D`，强调 `#2E4A3F`（只用于主按钮 + 一个数字）。
- 暗色：底 `#141516`，面 `#1C1E1F`，墨 `#ECEBE7`，强调 `#7E93A8`（去饱和钢蓝）—— 中性石墨，不带褐。

**反例**

- `#FFF` 底 + `#000` 字 + 三处不同强调色。
- 紫蓝渐变按钮、发光边框、彩虹多强调。
- 奶油米 + 陶土橙 `#D97757`；深褐近黑 + 琥珀强调（同一个病的明暗两版）。
- 整块面板或大卡片铺渐变。
- 高饱和撞色当"大胆"。

### 4.5 动画：只做三件事

**必须有的三处**

1. **进场**：淡入 + 上移 12–16px，多条内容 stagger 60–80ms，只播一次。
2. **悬停 / 按下**：背景、边框、位移的即时反馈，120–220ms。
3. **状态切换**（tab / 展开 / 弹层）：220–360ms，位移 + 淡入，不硬跳。

**参数**

- 时长：反馈 120–220ms；进场 320–600ms；一次完整编排 ≤ 800ms。
- 缓动：`cubic-bezier(.22,1,.36,1)` 或 ease-out。禁 bounce / elastic / 多次回弹。
- 只动 `transform` / `opacity` / `filter`（必要时背景色），不动 `width` / `height` / `box-shadow` / `top` / `left`。
- 无限循环只允许极小的状态指示（8px 呼吸点这类）。
- 始终提供 `prefers-reduced-motion: reduce` 兜底：关掉位移与视差，内容保持可见。

**正例**：卡片 hover `translateY(-2px)` + 边框色加深，180ms；列表进场 stagger 60ms，`once: true`；tab 切换下划线 220ms 位移。

**反例**：每个区块从不同方向飞入；1.2s 慢动作缓动；无限漂浮光斑；视差位移超过容器高度 15%；文字还在入场用户已经开始读。

## 五、动效实现：默认 CSS，必要时才上库

**默认纯 CSS + IntersectionObserver 就够**，命中任一即不要引库：

- 容器是 A / C / D 三类——本来就没有页面级滚动；
- 页面短、叙事线性，只需要出场 + 悬停 + 切换；
- 动效只是反馈，不是内容本身。

**该上 GSAP**：仅限 B 类型，且需要连续跟随滚动（scrub）、pin 一屏、横向滚动段、分层视差、逐词逐行大标题入场。

```html
<script src="https://cdn.jsdelivr.net/npm/gsap@3.15.0/dist/gsap.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/gsap@3.15.0/dist/ScrollTrigger.min.js"></script>
<script>gsap.registerPlugin(ScrollTrigger);</script>
```

同路径按需取：`ScrollSmoother`、`SplitText`、`DrawSVGPlugin`、`MotionPathPlugin`、`Flip`、`ScrollToPlugin`。

```js
// 出场：进视口一次
gsap.utils.toArray(".reveal").forEach((el, i) => {
  gsap.from(el, {
    y: 16, autoAlpha: 0, duration: .5, ease: "power2.out", delay: (i % 3) * .07,
    scrollTrigger: { trigger: el, start: "top 85%", once: true },
  });
});

// scrub：阻尼来自秒数，true 是硬跟随
gsap.to(".hero-visual", {
  scale: 1.08, ease: "none",
  scrollTrigger: { trigger: ".hero", start: "top top", end: "bottom top", scrub: .8 },
});

// pin：段落必须自己占够滚动距离
const tl = gsap.timeline({
  scrollTrigger: { trigger: ".chapter", start: "top top", end: "+=180%", pin: true, scrub: 1 },
});
tl.to(".step-1", { autoAlpha: 0 }).from(".step-2", { autoAlpha: 0 }, "<");
```

**要点**

- `scrub: .6–1.2` 是阻尼的来源；出场一律 `once: true`。
- 字体 / 图片晚加载会让触发点漂移，加载完调 `ScrollTrigger.refresh()`。
- 列表逐项挂触发器改用 `ScrollTrigger.batch()`；上百个触发器说明设计该重做。
- **平滑滚动只用于 B**：ScrollSmoother（需 `#smooth-wrapper` / `#smooth-content` 两层）或 Lenis，`smooth` / `duration` 控制在 1 秒上下。触控端默认关闭。固定元素放包裹层外，锚点改用 `scrollTo()`。A / C / D 一律不用。
- 已用 GSAP 就用 ScrollSmoother，不叠两套滚动劫持；Lenis + ScrollTrigger 必须手动接 `lenis.on("scroll", ScrollTrigger.update)`。
- **reduced-motion 用 `gsap.matchMedia()` 写两套**：动效只写在 `no-preference` 分支；元素初始态本来就可见（用 `gsap.from`），绝不靠 JS 去"显示"内容。
- **首屏不等 JS**：首屏主角用 CSS 直接到位，滚动动效只管首屏以下。

## 六、素材

**优先级：在线热链 > 手绘 SVG > AI 生图。** 一律不下载到本地。

### 图片（热链）

- Lorem Picsum：`https://picsum.photos/seed/lab/1200/800`（带 seed 可复现同一张）
- Unsplash：`https://images.unsplash.com/photo-xxxx?w=1600&q=80&auto=format&fit=crop`
- Pexels：`https://images.pexels.com/photos/<id>/pexels-photo-<id>.jpeg?auto=compress&w=1600`
- 纯色占位：`https://placehold.co/600x400`
- 头像：`https://i.pravatar.cc/120?u=<seed>` 或 DiceBear `https://api.dicebear.com/9.x/<style>/svg?seed=xxx`

图片必须服务内容、契合方向卡，不是随手塞风景大图；带尺寸与质量参数，写好 `alt`。

### 图标

只用 **Tabler Icons** 一套，不混其他图标库，不用 emoji 当功能图标：

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@tabler/icons-webfont@3.49.0/dist/tabler-icons.min.css">
<i class="ti ti-flask"></i>
```


图标名在 `https://tabler.io/icons` 查，类名 `ti ti-<name>`；全站统一字号、线宽、颜色。

### AI 生图（最次选项）

仅当素材**既无在线替代、又超出手绘 SVG 能力**时使用（复杂拟物图标、风格化立绘、需要透明底的精细图形）。能用 10 个以内 SVG 基本形状拼出七八成像的，一律手绘。

```bash
python tools/image-forge/generate.py --style lineicon \
  "a sci-fi HUD line icon, single cyan stroke, hexagonal frame" \
  ui/<page-name>/assets/icon-hud.png
```

- 必须先有本地 `.env`（`IMAGE_API_BASE_URL` / `IMAGE_MODEL` / `IMAGE_API_KEY`），且页面目录下没有 `assets/`。
- `--style` 必填：`lineicon` / `skeuomorphic` / `illustration` / `render3d` / `iso25d` / `anime` / `chibi` / `photoreal` / `product` / `cinematic` / `stylized` / `guofeng`（`--list-styles` 查全表）。
- 提示词只写主体、材质、光。**不写** `ultra detailed` / `8k` / `masterpiece`，它们是噪点与碎片感的来源。干净词由 `skills/image-purify/purify.json` 自动叠加。
- 单页不超过 5 张；要更多必须先向用户说明清单与理由。
- 生成一次就用，不回读分析、不反复重生成。`--dry-run` 可先看拼好的提示词。

## 七、交互与功能：功能做全，呈现做简

**判断标准**：功能完整度按**品类常识**，不按个人兴趣。做一个文档编辑器，就像用户真的要在里面写完一篇文章；做一个后台，就像运营真的要靠它上完一天班。少一个标准功能，就是把用户赶走。

**必须做到**

- 先把该品类的功能清单列出来，再动手布局；每一条都要有入口、有真实响应。
  - 软件：文件操作（新建 / 导入 / 导出 / 打印）、编辑（撤销重做 / 剪切复制粘贴 / 查找替换）、格式化、视图与缩放、设置与状态。
  - 网页：导航、内容浏览、筛选搜索、表单与校验、空 / 加载 / 失败状态、页脚与次级入口。
  - App：核心任务全流程、返回与手势、底部导航、表单、列表与详情、通知与空状态。
  - 组件：完整状态机（空闲 / 悬停 / 聚焦 / 加载 / 成功 / 失败 / 禁用）、键盘操作。
- **核心流程要能从头走通**：全部用本地数据在前端完成，不依赖后端。
- **状态齐备**：空 / 加载 / 失败 / 成功 / 禁用，每个列表、表单、异步操作都要考虑。
- **每个可见控件都要有响应**：点击、悬停、切换、展开、弹层、Toast、复制、筛选、增删。

**怎么做到功能多而界面简**

- **分组**：工具栏按任务分 tab，一屏只露一组；低频功能进二级菜单。
- **渐进披露**：设置项先给默认值，细节藏进浮层 / 抽屉 / 更多菜单，用到了才展开。
- **上下文出现**：选区浮条、右键菜单、行内操作，只在相关时出现。
- **一器多用**：一个下拉承载多个值，一个按钮带菜单，一个面板切换多种视图。
- **键盘**：常用操作给快捷键（⌘S / ⌘F / ⌘B 等），界面上就可以少放按钮。

**不许做**

- 加与产品无关的功能来凑数（记账 App 里的天气、文档编辑器里的股票行情）。这是"功能多"的唯一反例。
- 不伪造业务成功：不要弹出假的"支付成功""已上传至服务器"。
- 不把业务数据写进 localStorage / sessionStorage / IndexedDB——刷新即回到初始演示状态。只有 UI 偏好（主题、动效开关）可缓存。

**复杂逻辑怎么办**

- 前端能模拟的就模拟：本地数据、假延迟、真实的状态流转。
- 模拟不了的（真实支付、真实上传、服务端协作），**入口保留、操作有响应**：一句克制的"需要连接服务"提示，或本地降级（如导出文件代替云端保存）。
- 不许因为实现麻烦就把功能删掉，也不许留一个点了没反应的死按钮。

**与视觉冲突时**

先重设计呈现方式（收进菜单、改成图标、延后出现），而不是删功能。只有"这个功能无论怎么摆都会毁掉画面"时才可以去掉，并在交付说明里写清去掉了什么、为什么。

**分寸**

- 用最简原生 JS 或 Alpine.js，不抽象、不框架化、不写"以后好扩展"的结构。
- 交互本身也要有质感，过渡参数按 4.5。

## 八、技术约定

- HTML / CSS / JS 实现。内容多时拆为 `index.html` + `styles.css` + `app.js`。
- **第三方库只走 CDN、零构建**：GSAP 全家桶、Lenis、Alpine.js。按需引，能不引就不引；**禁 React / Vue / Tailwind / Next**，也不下载到本地。
- 颜色、字号、间距、圆角、阴影先定义成 CSS 变量，之后一律引用变量。
- 语义化标签；可见焦点态；必要的 `aria-*`；对比度达标。
- 桌面与窄屏两档响应式，窄屏重排而非横向滚动。
- 页面输出到 `ui/<page-name>/`，英文 kebab-case，不超过 4 个单词；`metadata.json` 按 `skills/ui-metadata/SKILL.md` 归档。

## 九、硬禁清单（唯一权威，命中即改）

"去 AI 味"在本技能里不是抽象感觉，就是这一节的可执行禁令。除非 brief 明确要求，以下一律不出现。

**为什么显廉价**（按出现频率）：套默认审美，所有页面同一套配色字体布局；均匀用力没有主角；细节不统一（圆角、阴影、间距、字重各自为政）；用结构装饰冒充信息；文案空洞、数字假精确；收尾不到位（对比度、换行、状态、动效半成品）。

**排版**

- 标题上方 ALL-CAPS、字距拉开的小眉标。密集工具里确需分类标签时，用常规字重的短中文词。
- 标题里只给某一个词变色 / 斜体 / 加粗当"亮点"。
- 中文界面夹一排英文大写标签。
- 中点 `·` 串联一长串（每行最多 1 个）；"词 — 片段"的空格破折号。
- 链接、按钮尾部的 `→`；"Scroll ↓""向下滚动"之类滚动提示。
- 破折号 `—` 当设计元素到处用。
- `Stage 1` / `Step 1` / `01 · xxx` 用在不真是序列的内容上。
- 处处居中、处处对称，毫无节奏。
- "左边大标题 + 右上角浮一小段说明"的割裂页头。

**视觉**

- 一排三到四个等宽、带图标的"功能卡"（SaaS 卡片套件的主要特征）。
- 卡片里再套卡片；所有元素同一个圆角 + 同一片 `rgba(0,0,0,.1)` 灰阴影。
- 彩色单侧竖条；文字渐变；外发光 / 霓虹；渐变当装饰；大面积渐变底（整块面板、大卡片的默认背景）。
- 纯 `#000` / `#fff`；过饱和强调色；AI 紫 / 靛蓝发光渐变。
- 长列表、规格表每行都 `border-t` + `border-b` 发丝线。
- 带填充底轨的进度条 / 评分条当装饰。
- 用 `div` 拼假截图 / 假仪表盘 / 假终端；把手绘装饰 SVG 当默认。
- 无意义漂浮的大圆角彩色泡泡、随机几何碎片；emoji 当图标。
- 默认 Inter / 思源黑体直接上。

**配色**

- 奶油米底 + 高对比衬线 + 陶土橙 `#D97757`，及其暗色变体：深褐近黑底 + 暖橙 / 琥珀。
- 近黑底 + 单一荧光绿 / 朱红。
- 米白 + 黄铜 / 粘土 / 氧血红 + 浓咖啡近黑（高级消费品牌默认套色）。
- 报纸风：发丝线 + 零圆角 + 密集多栏（同时踩中配色与排版）。

**内容**

- 通用占位名、蛋形 / 字母头像、完美整数、创业风假品牌名、营销废词。
- 成段的解释性文案、自述式引导（"在这里你可以…"）、复述标题的副文。
- 每张卡片都配一句描述；把一句话拆成多行短碎片；同一信息在标题、副文、卡片里重复三遍。
- 地点 / 时间 / 天气氛围条；版本号标（`v0.6`、`BETA`）当装饰。
- 页面内出现"本页为原型演示""信息均为虚构"这类解释性文字。

## 十、交付前自检

**能数的数**

- ALL-CAPS 拉距眉标：**0**。
- 每行中点 `·`：≤ 1。
- 全文 `—` 与 `→`：**0**。
- 强调色：**1 个**且落点一致。圆角：**1 套**。阴影：**1 套**且染底色。字体：**≤ 3 种**。
- 每屏说明性段落：**≤ 1** 且 ≤ 2 行；副文 **≤ 24 字**；按钮文字不换行、对比达标。

**删字测试**

逐段删掉所有解释性文字，删后任务仍能完成的都不放回；再用图标、形状或图示补上被删掉的信息，而不是用另一句话替代它。

**五项审查**

1. **独立设计**：本次由当前需求独立推导，未参考任何已有原型；差异在信息结构、视觉表达、关键交互，不只是换色换图。
2. **功能面**：按第七节的品类清单逐项点名，每一项都能找到入口并真实生效；没有点了没反应的死按钮，没有"暂未接入"占位。缺了哪项，必须在交付说明里写清原因。
3. **视觉减法**：每屏只有一个主角；逐区块删一轮文字，只放回删了会影响理解的；再拿掉一件配饰。**减的是文字和装饰，不是功能。**
4. **容器**：A / C / D 无页面滚动条，UI 收在悬浮窗口或居中控件内；组件状态做齐；B 的滚动节奏成立。软件逐区检查——只有长列表 / 长正文滚，没靠隐藏滚动条或裁切过关。
5. **细节**：100% 与 200% 缩放下文字不重叠不裁切；中文多行标题换行正常；三处基本动效在；reduce 分支下内容可见可读；首屏不等 JS。

**收尾**

- 交互：每个控件有响应，主流程跑通，无伪造成功。
- 文案通读：无语病、无空洞营销词、无假精确数字。
- **默认不自测**：不起本地服务、不截图、不跑测试，只做代码层审查，然后交付让用户双击 HTML 查看。仅当用户明确要求时才执行。

## 最后

**这是方法，不是风格。** 方法恒定，画面常新：换一个功能，就重新写一张方向卡——换字体性格、换底色温度、换构图秩序、换质感来源。永远不要把本文的某个示例当成模板，也不要复用上一次的具体视觉。
