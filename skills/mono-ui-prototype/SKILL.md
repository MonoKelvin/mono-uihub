# 高级简约 UI 生成技能

## 这个技能解决什么

用户只会告诉你**要做一个什么功能的页面**（例如"一个记账 App 的首页""一个播客的落地页""一个客服工单后台"）。
UI 的一切——方向、配色、字体、布局、装饰、动效——全部由你决定，用户不需要、也不应被要求补充任何视觉提示词。

你的产出必须同时满足两件事：**高级感、没有 AI 味**。视觉上应干净整洁、布局合理、层级清晰；是否极简应由功能与内容决定，而非强制套用。克制（而不是贫衣）才是真正的简约。

产出的本质是一张**可操作的高保真 UI 原型**：核心是视觉表现与质感，不是业务逻辑的完整实现。但"原型"不等于死壳——**默认就要把能交互的元素用最简单的 JS 接上**，让它看起来是活的、能点能用能演示（细则见下方「原型交互」）。

> 核心约束：**这是一套方法，不是一种风格。** 下文所有示例都是"可能的选项"，不是要照抄的清单。
> 换一个功能、换一个品类，就必须换一套方向、配色、字体和布局骨架。严禁把某一套具体视觉写死成默认，也严禁直接复用上一个页面的样式。



## 三条第一原则

1. **先定一句设计定位（北极星）**，再让构图、字体、色彩、素材、动效全部朝它靠拢。没有定位的页面必然平庸。
2. **简约 = 克制地保留最有力的元素，删掉没有贡献的一切**；不是把所有风格磨成中庸安全的模板。留白是设计，不是没设计完。
3. **去 AI 味 = 主动避开模型的默认审美**。默认审美（见下方「去 AI 味」章）是"安全但一眼假"的根源。每做一个决定都反问一句：这是我特意为这个内容选的，还是随手套的默认？

## 页面类型：软件 / 网页 / App / 组件（第 1 步之后立即确定）

先判断要做哪一种**容器形态**——它决定整页的**滚动模型、视口与外框**，但**不决定视觉风格**（风格仍按方向卡每次重新推导）。
用户点明了就按用户的；没点明就从功能推断：管理系统 / 工具 / 仪表盘 → 软件；品牌 / 落地 / 介绍 / 内容站 → 网页；移动优先的消费应用、或点名"App / 手机 / 小程序" → App；单一功能的独立控件（播放器、图片浏览器、文件下载器等）→ 组件。

### 类型 A · 软件（桌面软件窗口）
- 这是**软件界面，不是网站**：把整个 UI 收进页面居中的**一个窗口组件**里——大而柔的悬浮阴影、适度圆角，窗口外是一层中性背景做衬托。
- 可以**不要**右上角的窗口控制按钮（红黄绿点）；要做也只做极简版。
- **不出现网页滚动条**：页面本身 `overflow: hidden`，把所有 UI 元素尽量铺进这一屏窗口。内容多时靠**窗口内部各区域局部滚动**或压缩密度来容纳，绝不让整个网页上下滚动。
- 用"固定视口"的布局思维：窗口给定宽高（例如居中的 `1360×840`，或 `min(1440px, 94vw)` 配 `min(880px, 92vh)`），内部用 flex / grid 切成侧边栏、顶栏、内容区等区域，各区域各自管理溢出。

### 类型 B · 网页（常规网站）
- 常规文档流，**允许垂直滚动**。落地页、品牌页、内容站、作品集属于此类。
- 可用 **GSAP + ScrollTrigger** 等做滚动驱动的叙事：区块随进入视口出场、视差、首屏景深、一镜到底等，至少设计一段滑动驱动的内容。
- 讲究整页滚动节奏：首屏抓人，之后一段段有呼吸、有高潮，长页不塌。

### 类型 C · App（手机应用）
- 把 UI 放进一个**手机尺寸比例的窗口**里：大圆角（约 40~48px）、居中悬浮、带柔和阴影，外面同样是中性背景——像一台立在桌面上的手机。
- 比例取手机屏，如 **390×844（iPhone）**；可选加状态栏、顶部灵动岛 / 刘海、底部 Home Indicator，增强真实感。
- 所有元素按**移动端**设计：单列布局、够大的触控目标、底部 Tab Bar、顶部导航栏、拇指热区。
- 滚动只发生在**手机窗口内部**（移动端自然滚动，建议隐藏滚动条更像原生）；手机外框本身固定居中、不随网页滚动。

### 类型 D · 组件（局部功能控件）
- 这不是一个整页，而是**一个专一功能的独立控件**：播放器、图片浏览器 / 灯箱、文件下载器、上传框、日期选择器、评论框等。
- 容器：组件按**自身内容的自然尺寸**成形（给一个合理的最大宽度），**居中悬浮**在一层安静的中性背景（展示台）上，带柔和阴影与圆角；不铺满视口、不套软件外壳（无侧边栏 / 顶栏），也不是手机框。
- **不出现网页滚动条**：组件尺寸贴合内容，背景只作衬托；内容确实多时在组件内部局部滚动。
- 把全部设计力气压到**这一个控件和它的关键交互时刻**上：认真做它的多种状态（空闲 / 加载中 / 进行中 / 完成 / 出错 / 悬停 / 聚焦），状态之间用克制过渡衔接——组件的质感就藏在状态与微交互里。
- 响应式：组件在窄屏自适应收窄，但始终是有边界的一块，而非撑满全屏。

> 四种类型共用前面全部的配色、字体、布局、装饰、动效与去 AI 味原则——**类型只换"外框与滚动模型 / 边界"，不换"审美方法"**。

## 流程（每次都完整走一遍）

### 第 1 步 · 动手前先想清楚

不写一行代码前，先回答：
- **品类**：这是什么类型的页面？（落地页 / 后台工具 / 仪表盘 / 内容站 / 表单 / 作品集……）不同品类的审美语言完全不同。
- **用户与场景**：谁在用、在什么设备上、来这一屏要看什么、要做什么。专业工具重密度与效率，消费产品重情绪与第一眼。
- **首屏主角**：这一屏最重要的一个东西是什么？（一个数据、一张图、一个操作、一句话）其余一切为它让路。
- **真实内容**：用贴近真实的文案和数据，不要"示例标题""Lorem ipsum""按钮"。内容的真实质感直接决定成品像不像真东西。

### 第 2 步 · 现场推导一个新鲜方向（防止千篇一律的关键）

方向要从 **品类 + 内容气质 + 该领域最好产品的做法** 里长出来，而不是从模型默认模板里长出来。

先在脑中过一遍"方向菜单"，挑一个与内容最契合、且刻意不同于上次的方向。菜单是启发，不是清单，可自由组合或另起炉灶：

> 编辑杂志感 · 科学仪器/控制台感 · 瑞士国际主义网格 · 极简留白画廊 · 暗色驾驶舱 · 柔和中性办公 · 几何构成主义 · 自然有机手工感 · 高对比野性排版 · 复古印刷质感 ……

然后写一张**方向卡**（简短几行即可），后面所有决策都对齐它：
- 定位一句话（例如"像一台精密科学仪器一样冷静可信"）
- 基底色 + 强调色
- 字体搭配
- 首屏主角与主视觉手法
- 动效基调

同一个品类换一次方向卡，页面就会是全新的——这正是"每次都不一样"的来源。
### 第 3 步 · 配色

- **结构化配色**：中性基底（1 个，带微色温）+ 墨色文字（1 个基色、拉出 3 档明度）+ 强调色（1 个，克制使用）+ 语义色（告警/成功等，少量、去饱和）。
- **比例**：接近 60/30/10，甚至更极端的 90/7/3。强调色只落在**主操作**和**关键数据**上，一旦到处都是就廉价了。
- **用微色温纸底替代纯白**：骨白、暖灰、冷灰、象牙……纯 `#fff`/`#000` 是 AI 味重灾区。给基底一点点色温，层级用相近明度的面叠出来，而不是靠粗边框。
- **强调色要有态度**：避开默认的"科技蓝/靛紫"。按方向选——深松针绿、砖红、芥末黄、钢蓝、墨黑都可以，关键是**低饱和、够深、够笃定**。
- **对比度达标**：正文 ≥ 4.5:1，大字 ≥ 3:1；小号弱化文字也要够深，别为了"高级"把灰字调到看不清。
- **禁用**：紫蓝渐变全家桶、彩虹多强调色、高饱和撞色、玻璃拟态默认套装。

### 第 4 步 · 字体与排版

- **搭配策略**：一个主字族承担 UI 与正文；可选加一个反差字族（衬线体或展示体）用于大标题/大数字制造个性；**数据（ID、时间、数值、坐标、金额、代码）一律用等宽字体并开启 `tabular-nums`**——这是让界面显得专业、精确、非模板的高效手段。
- **字体数量**：按每种语言分别控制，承担主要段落、正文、说明和常规 UI 文本的字体不建议超过 **3 种**；少量装饰性、凸显性的特殊字体不超过 **2 种**。特殊字体指仅用于 Logo、大标题、标记等单一场景、在页面中少量出现的字体，不作为常规正文使用。同一字族的不同字号与字重不算新增字体；系统兜底字体不计入数量。
- **中文**：优先 `"PingFang SC","Microsoft YaHei","Source Han Sans SC"` 栈；谨慎把拉丁衬线与中文混在同一标题里（容易别扭），常见做法是中文走无衬线、把衬线/展示体只留给拉丁数字与字标。
- **层级靠字号跨度 + 字重 + 颜色建立**，不要靠一堆边框和底色。大标题收紧字距（`letter-spacing: -.02em`），小标签适度放开（`.04~.16em`）；正文行高放松（1.5~1.7），标题行高收紧。
- **字号克制**：通常 2~3 个正文级别就够。够大的留白 + 清晰的层级，比满屏不同字号更高级。
- **字体来源（在线 CDN 引用，绝不下载到本地）**：当系统默认字体缺少特色时，用免费在线字体增加辨识度，但必须配好系统兜底栈，断网也不崩。
  - 拉丁字体：Google Fonts、Fontsource 等的 `<link>` / CDN 引入。
  - 中文 / 特色字体：**ZeoSeven Fonts**（`https://fonts.zeoseven.com/browse/`）。在站内挑一款契合方向卡的字体，进入它的详情页拿到**真实的 Font ID 与 font-family 名**，按官方 `@import` 方式引用（下例的 ID `628` 与名字仅为示例，务必替换成所选字体页面上给出的真实值，不要臆造 ID）：

```css
@import url("https://fontsapi.zeoseven.com/[Font ID]/[Font Style]/result.css");
/* 示例： */
@import url("https://fontsapi.zeoseven.com/628/main/result.css");

:root { --font-display: "USMCCyuanjiantecu", "PingFang SC", system-ui, sans-serif; }
h1 { font-family: var(--font-display); font-weight: normal; }
```

  - 这类字体多为**单一字重的展示体**：用 `font-weight: normal`，别指望加粗变化。主要把它用在**大标题 / 字标 / 大数字**等"主角"位置制造个性，正文仍选易读字体。
  - 中文在线字体体积偏大，ZeoSeven 已做字形切片按需加载；仍应控制使用范围、始终设好 fallback。
  - 其他免费在线字体服务同理，**前提都是：免费、在线 CDN 引用、不下载托管**。
### 第 5 步 · 布局

- **一屏一个主角**，其余安静退后。先确定主角占据的视觉重量，再安排其他。
- **真实内容驱动布局**，不是先画好格子再往里填字。让内容的真实长度、层级决定结构。
- **栅格 + 对齐 + 呼吸**：定义一套统一的间距刻度（以 4 或 8 为基数），所有间距都取自它；强对齐带来秩序感。
- **不是所有东西都要塞进卡片**：靠留白、发丝分隔线、对齐分组同样能组织信息，而且更轻、更高级。该用大图或连续排版建立气氛时，别硬塞卡片网格。
- **信息密度服务任务**：专业工具可以密，消费落地页要疏。密不等于乱——密的前提是对齐和分组清晰。

### 第 6 步 · 装饰（极致克制）

- **用发丝线、极淡阴影、相近明度的分层**，替代重边框和浓重投影。
- **功能性装饰优先**：数据可视化、状态点、坐标轴、进度条、等宽数据表本身就是最好的装饰——它们既好看又传递信息。
- **可选的质感点缀**：极淡的网格/点阵背景、一条细强调线、一个克制的几何字标，少量使用能提气质。
- **禁用**：无意义漂浮的大圆角彩色泡泡、随机几何碎片、彩色单侧竖条、表情符号当图标、过度的渐变与发光。

### 第 7 步 · 动画与过渡

- **至少三处基本动效**：①进场——内容淡入 + 轻微上移，多个元素错落 60~80ms 入场；②悬停反馈——可交互元素有即时、克制的状态变化；③状态/视图切换——切换时有平滑过渡而非硬跳。
- **手感**：时长 150~400ms，缓动用 ease-out 类曲线（如 `cubic-bezier(.22,.61,.36,1)`）。快进慢出，收尾干净。
- **数据可视化**可做一次性的 draw-in（线条描边、数字滚动、柱子生长）。
- **克制**：不无限循环晃动，不是每个元素都要动，动效要服务理解与反馈而非炫技。
- **无障碍**：始终为 `prefers-reduced-motion: reduce` 提供关闭动效的兜底。

## 去 AI 味（重点章节：怎样做出高级感、去掉廉价感）

页面"显假、廉价、不高级"，几乎都源于下面这几件事。本章要反复回读、逐条对照。

### 为什么 AI 生成的页面显得廉价
1. **套默认审美，而不是为这个内容做选择**——模型一上手就滑向同一套配色/字体/布局（见下方聚类），于是所有页面长得像同一个。
2. **到处均匀用力，没有主次**——每个区块都想抢眼，结果没有主角，整页平、吵、廉价。
3. **一致性失控**——圆角、阴影、强调色、间距各处不一样，细节对不齐；这是"廉价感"最大来源。
4. **用结构装饰代替信息**——到处眉标、编号、竖条、分隔线、彩色点，纯为"看起来像设计过"，不承载任何信息。
5. **文案塞满又空洞**——占位名、营销废词、假精确数字；文字和界面一样一眼是生成的。
6. **细节不收尾**——对比度不够、换行破裂、状态缺失、动效半成品。

### AI 默认审美聚类（出现即"显假"，brief 没要求就一律避开）
这些对某些 brief 是合法的，但它们是模型的**默认**而非**选择**，且无视主题到处出现。brief 明确指定就照做；brief 没限定的地方，**不要把自由花在这些默认上**：
1. 奶油米底 + 高对比衬线大标题 + 陶土/粘土橙强调（≈`#D97757`，这正是 Claude 自己的交互色，出现即露馅）。
2. 近黑底 + 单一荧光绿 / 朱红强调。
3. 报纸风：发丝线 + 零圆角 + 密集多栏。
4. **SaaS 卡片套件**：内容全切成一模一样的圆角卡、所有元素同一个圆角、每块下面同一片灰阴影 `rgba(0,0,0,.1)`、渐变当装饰。
5. **模板装饰层**（无论什么主题都冒出来）：每个标题上方 ALL-CAPS 字距拉开的小眉标；中点串联的元信息 `A · B · C`；"词 — 片段" 的空格破折号；用 `#0B0B0B`/`#111` 冒充黑；小数据标签一律等宽；链接/按钮尾部加 `→`。
6. AI 紫 / 靛蓝发光渐变（最常见的 tell）；默认 Inter / 思源黑体直接上；一排三个等宽带图标的卡。
7. 高级消费品牌默认套色：米白 + 黄铜/粘土/氧血红/赭石 + 浓咖啡近黑字——每个这类站都长一样，品牌直接隐形。
### 廉价 → 高级：具体怎么做
- **克制：把大胆只花在一处。** 让一个元素成为记忆点（主角），周围全部安静、克制，删掉任何不服务主题的装饰。Chanel 法则——出门前照镜子，拿掉一件配饰。
- **留白即奢侈。** 敢给大间距、大段呼吸；疏比密贵。拥挤、贴边、小字硬塞，是廉价感的直接来源。
- **一致性锁**（高级感的地基，廉价感多半是这里垮的）：
  - **一个强调色锁全页**，不要第 7 屏突然冒出另一个颜色。饱和度默认 < 80%，宁用去饱和的深色，也不要高亮荧光。
  - **一套圆角**：全锐 / 全柔（12–16px）/ 全胶囊，三选一并贯穿全页；除非有明确书面规则（如按钮胶囊、卡片 16、输入 8）并处处遵守。
  - **一套阴影**：阴影要**染上背景色相**，禁止纯黑投影压在浅底上；全页一套阴影语言，不要每块深浅不一。
  - **不用纯 `#000` / `#fff`**：用偏暖或偏冷的近黑、近白，保住层次与深度。
  - **一套图标**：同一族、同一线宽、同一字号节奏，绝不混用两套。
  - **一种文案语域**：不要把技术等宽、文艺腔、营销腔混在一个页面。
- **字体要有态度。** 别一上手就 Inter / 思源默认体，挑契合方向卡的字族。**衬线不是"创意 / 高级"的默认**——除非真的是编辑 / 出版 / 奢侈 / 传承场景，且说得出为什么是这一款衬线。要强调标题里的某个词，用**同字族的斜体或粗体**，不要往无衬线标题里塞一个衬线词（混家族强调很业余）。
- **用真实、具体、符合语境的内容。** 真实感的人名（不是"张三 / 李四 / John Doe"）、像真的品牌名（不是 Acme / Nexus / 智某某）、有机的数字（`47.2%` 而不是 `99.99%` / `50%`）；避免营销废词（赋能、一站式、极致、引领、焕新、无缝、next-gen、seamless、revolutionize）。
- **结构即信息。** 边框、编号、眉标、分隔线、状态点必须**承载信息**而非装饰。编号 `01/02/03` 只在内容**确实是序列**（分步流程、时间线）时才用；用前先确认它真是序列。
### 硬禁清单（命中即改，除非 brief 明确要求）

**排版 / 文字**
- 标题上方 ALL-CAPS、字距拉开的小眉标（每节都加 = 头号 tell）；默认**直接删掉**，标题本身足够。密集专业工具里确需分类标签时，用常规字重的短中文词，不做全大写拉距处理。
- 只给标题里的某**一个词**变色 / 斜体 / 加粗充当"亮点"。
- 中文界面里夹一堆英文大写标签。
- 中点 `·` 当万能分隔符串一长串（一行最多 1 个）；"词 — 片段" 的空格破折号。
- 链接 / 按钮尾部的 `→`；"Scroll ↓""向下滚动"之类滚动提示。
- 破折号 `—` 当设计元素到处用；能用句号 / 逗号 / 冒号 / 括号就别用。
- 编号 / 步骤标签（`Stage 1`、`Step 1`、`01 · xxx`）当内容并不是真序列。

**视觉 / 布局**
- 一排三个（或四个）等宽、带图标的"功能卡"。
- 卡片里再套卡片；所有元素同一个圆角 + 同一片灰阴影。
- 彩色单侧竖条；文字渐变；外发光 / 霓虹；渐变当装饰填充。
- 纯黑 / 纯白；过饱和强调色；AI 紫靛发光。
- 长列表 / 规格表每行都 `border-t`+`border-b` 发丝线（最懒的布局）→ 改成分组、卡片或标签。
- 带填充底轨的进度 / 评分条当对比装饰。
- 用 `div` 拼的假截图 / 假仪表盘 / 假终端；把手绘装饰 SVG 当默认。
- 处处居中、处处对称、毫无节奏；"左边大标题 + 右上角浮一小段说明"的割裂页头。

**内容**
- 通用占位名、蛋形 / 字母头像、完美整数、创业风假品牌名、营销废词。
- 地点 / 时间 / 天气氛围条、版本号标（`v0.6`、`BETA`）当装饰——除非 brief 真的需要。
### 机械式自检（交付前逐条数，能数的就别凭感觉）
- 数 ALL-CAPS / 字距小眉标出现几次 → 默认应为 **0**；真要用，整页 ≤ `ceil(区块数 / 3)`。
- 数中点 `·`：每行最多 1 个。
- 全局搜 `—` 和 `→`：默认 **0**。
- 强调色是否**只有一个**且全页一致；圆角是否**一套**；阴影是否**染色且统一**。
- 是否出现：一排三等卡、卡中卡、单侧色条、文字渐变、纯黑纯白、过饱和 / 紫靛发光。
- 每个按钮：文字对背景对比达标（正文 ≥ 4.5:1）、不换行。
- 通读每一句可见文案：有无语病、空洞营销词、假精确数字、通用假名。
- 做一次减法：每屏只有一个主角，再拿掉"一件配饰"。

### 结合同类开源设计技能
若环境里装有 `frontend-design`、`design-taste-frontend`、`redesign-existing-projects` 这类前端设计技能，设计时可一并参考它们的方向推导与反模板清单（本章与之一脉相承，可互为补充与交叉检查）。但**技术栈始终按本项目来**（原生 HTML/CSS/JS，或项目既有栈），不要因为参考它们就引入 React / Tailwind / Next 等依赖。

## 素材：图片、图标与生成资产

> **在线引用优先。** 普通照片 / 占位图 / 图标，一律**热链** — 绝不下载到本地。

需要配图、占位图或头像时，用免费图床**热链接**，绝不下载到本地；图标统一用一套在线图标库，保证全站风格一致。

### 图片 / 占位图（候选，按需挑选）
- **Lorem Picsum** — 占位照片，按尺寸直接取：`https://picsum.photos/1200/800`；要可复现同一张就加种子：`https://picsum.photos/seed/lab/1200/800`。
- **Unsplash**（真实照片热链接）— 在 unsplash.com 选好图，用它的 `images.unsplash.com` 直链并带参控制体积：`https://images.unsplash.com/photo-xxxxxxxxxxxx?w=1600&q=80&auto=format&fit=crop`。
- **Pexels** — 同样可热链接：`https://images.pexels.com/photos/<id>/pexels-photo-<id>.jpeg?auto=compress&w=1600`。
- **placehold.co** — 纯色 / 带文字的占位块，先占位、暂不想要干扰性图片时用：`https://placehold.co/600x400`。
- **头像**：`https://i.pravatar.cc/120?u=任意种子`，或 DiceBear 生成式头像 `https://api.dicebear.com/9.x/<风格>/svg?seed=xxx`。

用图原则：图片要为内容服务、契合方向卡，**不是随手塞风景大图**；务必带尺寸 / 质量参数控制加载，写好 `alt`；示例链接里的图片 ID 需换成实际可用的。

### 图标：Tabler Icons（在线 CDN，不下载）
线性图标集，风格统一、克制，适合高级简约界面。用 webfont 方式 CDN 引入：

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@tabler/icons-webfont@3.49.0/dist/tabler-icons.min.css">
<i class="ti ti-flask"></i> <i class="ti ti-snowflake"></i> <i class="ti ti-shield-check"></i>
```

- 图标名到 `https://tabler.io/icons` 查，类名格式 `ti ti-<图标名>`；版本号可按需升到当前最新。
- 全站只用这一套图标，统一字号 / 线宽 / 颜色；**绝不用 emoji 当功能图标**（见「去 AI 味」章）。
- 需要内联 SVG（便于单独做描边动画）时，也可从同一 CDN 取单个 svg，保持同源同风格。

### 生成资产（Image Forge — 按需生成透明图片）

当页面需要的图片素材 **无法从已有素库获得**（例如页面独有的科幻 HUD 线条图标、风格化物件、需要透明背景的图形），使用项目自带的生图工具 `tools/image-forge/`，在线生成 PNG 并保存到对应页面的 `assets/` 目录。

如果需要带有透明通道的、抠图后的图片，建议优先考虑该工具。比如抠图后的产品展示、立绘、彩色图标、拟物图标、插画等等。

> ⚠️ 这是「在线引用优先、不下载」原则的一个**例外**：前提是图片素材**不存在可用的在线替代**（搜索/图标库均不符），且**生成产物会被当前页面复用**，而非一次性使用的风景照。

#### 前提

1. 本地 `.env` 文件已就位（复制 `.env.example`，填入 `IMAGE_API_BASE_URL` / `IMAGE_MODEL` / `IMAGE_API_KEY`）。
   `.env` **已加入 `.gitignore`，永远不会被提交。**

2. 已确认当前生成页面目录下不存在 `assets/`（工具会自动创建）。

#### 使用方法

在生成网页时，如需透明素材图标/装饰图，调用 Python 脚本（无需安装第三方依赖）：

```bash
! python tools/image-forge/generate.py \
  "a sci-fi HUD line icon, monochrome cyan glow, transparent background" \
  ui/<page-name>/assets/icon-hud.png
```

- **提示词**：要写出清晰、可复现的关键词（参考上一条「图片 / 占位图」候选的风格与参数控制原则）。
- **路径**：输出到页面目录下的 `assets/` 子目录，文件名用英文 `-` 分隔。
- **--no-transparent**：仅当目标模型不支持透明生成时使用；大多数场景不用加。

生成后在页面里按普通图片引用即可（`<img src="assets/icon-hud.png" alt="…">`），享受确实匹配页面方向、透明可贴合的素材。

## 原型交互：默认都接上，用最简 JS

产出是 UI 原型，**重点始终是视觉与质感**；但不要交一个点哪都没反应的死壳。按下面的分寸拿捏：

- **默认把能交互的元素都接上**，哪怕用户没要求。用**最简单的原生 JS**（或 Alpine.js 这类轻量方案）实现即可，不追求工程化、不过度抽象：
  - 点击、悬停、Tab / 开关 / 折叠 / 下拉的切换、弹窗开关、轻提示（toast）、复制、主题切换；
  - 表单：基础校验与错误提示、输入联动、提交后的本地反馈；
  - 滚动与锚点跳转、轮播、筛选 / 搜索的前端过滤、列表的增删。
  - 链接：站内锚点真跳转；外链用 `#` 或占位亦可。
- **数据用本地假数据**，前端自己做增删改查即可，不接后端、不发真实网络请求。
- **太复杂的逻辑可以不做**（真实支付、真实上传、复杂算法、真正的持久化等）。两种处理都行：① 操作后弹一句克制的"功能开发中"轻提示；② 干脆无反应。但**不要伪造业务成功**——假的"支付成功""已上传至服务器"会误导。
- **交互不能拖累视觉**：接交互是为了让原型可演示，一旦与"保证 UI 展示效果"冲突，优先视觉。宁可某个按钮暂不接，也绝不为逻辑把界面做丑。
- 交互本身也要有质感：状态切换带上第 7 步定义的克制过渡，别硬跳。

## 技术约定

- 用 HTML / CSS / JS 实现；是否拆分文件自行决定（内容多时拆为 `index.html` + `styles.css` + `app.js` 更清晰）。
- **颜色、字号、间距、圆角先定义成一组 CSS 变量，之后一律引用变量**，保证整页是"一套系统"。
- 语义化标签；可访问性到位：可见的焦点态、必要的 `aria-*`、达标的对比度。
- 做好响应式：至少桌面与窄屏两档，窄屏下重排而非横向滚动。
- 字体一律用在线 CDN 引入、**不下载托管**：拉丁用 Google Fonts，中文 / 特色字体用 ZeoSeven Fonts 的 `@import`（见第 4 步）；并务必配好系统字体兜底栈，断网也不崩。
- 生成到当前工作目录下，新建一个文件夹，使用英文命名，单词之间使用‘-’分割，不建议超过4个单词。


## 交付前自检

- **减法一遍**：每一屏确认只有一个主角；逐区块删一轮文字，只放回删了会影响理解的。
- **容器类型核对**：软件 / App / 组件类型确认页面本身没有网页滚动条、UI 收在悬浮窗口或居中控件内；组件还要确认多种状态都做齐；网页类型确认滚动节奏成立。
- 在 **100% 与 200%** 缩放下看关键区域，文字不重叠、不被裁切。
- 中文多行标题、窄屏换行逐一检查。
- 三处基本动效在不在，`prefers-reduced-motion` 兜底在不在。
- **交互核对**：能交互的元素默认都接上了最简逻辑；复杂的要么轻提示"开发中"、要么无反应，没有伪造业务成功；且接交互没有拖累视觉。
- 配色对比度达标，强调色没有泛滥。
- 对照「去 AI 味」章的硬禁清单与机械式自检再过一遍。
- 不建议运行node服务环境运行脚本，生成并检查完成后直接交付即可，让用户自行双击html文件在浏览器中查看，除非用户明确指示了需要运行、截图、测试等内容。

## 最后，牢记

**这是方法，不是风格。** 下一个页面是另一个功能、另一个品类，就从头推导另一张方向卡——换基底、换强调色、换字体搭配、换布局骨架、换动效基调。永远不要把本文里某个示例当成要套用的固定模板，也不要复用上一次的具体视觉。方法恒定，画面常新。
