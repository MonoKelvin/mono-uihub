# UI 原型生成元数据

## 范围

**这是生成档案，不是生成结果的说明书。** 输出为 `ui/<page-name>/metadata.json`，结构唯一来源是本目录的 [template.json](template.json)；其他技能只引用本技能，不复制模板或字段规范。

- 保存名称、类型、标签、各轮原始提示词、模型、思考等级、使用的技能、时间、token 和耗时。
- 生图仅保留用户要求的调用统计：是否调用、成功生成数量、模型名称；不保存图片资源详情。
- 不新增 `features`、`image`、`assets`、`verification`、`implementation`、`design`、文件/依赖清单等字段；不记录生成后的功能、业务逻辑、资源 URL、图片提示词、配色字体或验收结果。
- 不添加 `source` 或 `*_source` 字段，技能使用简单字符串数组；`notes` 仅说明近似值、缺失历史等必要事项，不用于变相塞入生成结果描述。

## 工作流程

1. **开始前读取模板和已有元数据**。核实本次是新生成、实质修改还是仅整理元数据，保留本轮原始提示词、可确认的模型配置和开始时间。
2. **生成过程中记录基础信息**。保留实际读取/调用的技能、可核实的用量和生图调用统计，不等到交付时凭印象补写，不将这些单页生成记录写入全局记忆。
3. **完成后创建或更新元数据**。每次新生成页面或实质修改页面后都要归档，已有文件追加本轮历史，不覆盖旧轮次；填入已知的结束时间与耗时，更新基础信息和 `updated_at`。
4. **用标准 JSON 解析器检查**。核对键名唯一、字段类型、轮次数量、统计范围和隐私边界。此检查不需要依赖安装、本地服务、浏览器或截图。

## 创建、迁移与轮次

- **不批量补建旧项目**：未参与本轮生成或修改、且没有原始记录的历史页面，暂时不添加元数据文件。规范迁移只整理已经存在的文件。
- 以后重新生成或修改一个没有元数据的旧页面时，只从当前这轮开始记录，注明早期历史缺失；无法确认的原始创建时间、历史模型、提示词、用量和耗时不追溯猜测。
- 读取旧文件时保留用户填写的生成信息与历史，禁止用空模板整体覆盖；不要擅自删除用户自定义字段，范围不符的旧字段先确认再清理。
- `created_at` 表示页面最初创建时间，已有值不改；`updated_at` 表示最近一次页面或元数据更新的实际时间。仅整理元数据也要更新 `updated_at`，但不增加生成轮次，也不将本次整理使用的模型、技能或 token 回填到原生成轮次。
- 一个带有新需求的用户生成或修改请求记为一轮。工具调用、内部重试、自动修错及不带新需求的“继续”不单独计轮；同一轮未完成时补齐同一条记录，不重复追加。
- `generation.round_count` 必须等于 `generation.history.length`，`round` 从 `1` 连续编号。缺失早期历史时，这个数只表示已记录轮次，不冒充全部历史轮次。

## JSON 格式

使用 UTF-8 标准 JSON、2 空格缩进、英文 `snake_case` 键名和双引号；不允许注释、尾逗号、重复键、`undefined`、`NaN` 或 `...` 占位值。中文内容直接保存，布尔值用 `true` / `false`，未知值用 `null`。

[template.json](template.json) 是待填写的结构，不可原样交付。名称、目录、类型、标签和提示词须按本次任务填写，拿不到的统计信息明确设为 `null`。不要为填满模板而扫描或生成页面业务、资源及验证清单。

## 字段约定

| 字段 | 保存什么 |
| --- | --- |
| `schema_version` | 当前结构版本，使用整数 `1`。遇到无法识别的新版本先确认，不自行降级。 |
| `name` / `slug` | 页面名称和实际目录名；`slug` 与所在文件夹一致。 |
| `page_type` | `software`（软件）、`website`（网页）、`app`（App）、`component`（组件）四选一。 |
| `tags` | 从用户需求提炼的领域、主题或风格标签，使用去重字符串数组，不展开成功能清单。 |
| 各时间字段 | 使用 ISO 8601；新记录带实际时区偏移或 `Z`。旧记录未说明时区时可仅规范为本地时间并在 `notes` 中注明，不擅自补时区；缺失值用 `null`。 |
| `history[].round` / `kind` | 轮次从 `1` 连续编号；首次生成为 `initial`，实质修改或重新生成为 `revision`。旧页面从当前修改开始建档时，第一条也可以是 `revision`。 |
| `history[].prompt` | 用户该轮完整原始需求，不用摘要代替，也不拼接系统提示词。多轮逐条追加，不能只留最后一轮；原记录确实缺失时用 `null` 并说明。 |
| `model` / `reasoning_effort` | 该轮可确认的模型标识和思考等级；整理旧文件时沿用用户已有记录，不静默改写。不把工具示例、可用模型列表或猜测当成执行配置；思考等级仅记录配置值，不保存内部逐字推理。 |
| `skills` | 去重的技能名称字符串数组，例如 `["mono-ui-prototype", "frontend-design"]`。保留用户已有清单，新记录填写实际读取或调用的技能，不把仅安装或可用的技能当成已使用。 |
| `token_usage` | 本轮可核实的输入、输出及总 token 数，使用非负整数。`49.3k` 转为 `49300`，同时设 `is_estimate: true`；没有统计时保持 `null`，不能用上下文剩余额度或字数反推。 |
| `duration_seconds` | 本轮耗时，使用非负秒数，例如 `17m 54s` 为 `1074`。沿用用户记录，或在确实记录了起止时间时计算；不能拿文件修改时间或当前会话时长代替页面生成耗时。 |
| `image_generation` | 只记录本轮是否调用生图模型、成功生成图片数和去重后的模型名称数组。确定未调用时使用 `false`、`0`、`[]`；已调用但失败时仍为 `used: true`，成功数量为 `0`。 |

## 统计与历史的真实性

- 各轮模型、提示词、技能、用量、耗时和生图调用统计只归属对应的 `history` 条目。追加新轮次时不覆写旧轮，也不把当前模型或技能反填到此前的轮次。
- 若只知道多轮或整个会话的合计，不能复制到每轮；可另加 `generation.aggregate_usage` / `generation.aggregate_duration_seconds`，同时附上 `aggregate_scope` 说明已知范围。缺失部分用量时不声称得到了完整总计，也不能累计相互重叠的统计。
- `null` 表示未知；`0` / `false` 只用于已经确认的零次或未使用；空数组表示没有已记录条目，不能单凭空数组断言从未调用。记录缺失和近似值写进 `notes`。
- 不写入 `.env` 内容、API Key、授权头、私有服务地址、带凭据的 URL、个人机器路径或工具日志；原始提示词若含这些信息，先脱敏并记录已脱敏的事实。

## 交付自检

- 本次生成或修改的页面已创建/更新元数据，未触及的旧项目没有被批量补建文件。
- JSON 解析通过，核心字段与模板一致，用户原有生成记录未丢失。
- 轮次数量与历史一致，每轮原始提示词、模型、思考等级、技能、用量、耗时及生图统计已记录或明确为未知。
- 创建时间未被重置，更新时间是实际记录的时间，没有伪造或重复累计统计。
- 没有新增生成结果的功能、业务、实现、资源或验证字段，也没有隐私凭据。
